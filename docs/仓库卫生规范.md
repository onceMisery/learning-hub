# 仓库卫生规范

这个仓库要开源，所以「本地能跑」不等于「可以提交」。下面是每次提交前应该自查的清单。

## 一、不能进仓库的东西

| 类型 | 例子 | 处理 |
|---|---|---|
| 构建产物 | `dist/` `target/` `build/` `release/` | 已 gitignore |
| 依赖目录 | `node_modules/` `.pnpm-store/` | 已 gitignore |
| 编辑器配置 | `.idea/` `.vscode/*`（除推荐配置） | 已 gitignore |
| 日志与临时文件 | `*.log` `kill.txt` `*.tmp` `minidb_filelist.txt` | 已 gitignore |
| 测试报告 | `test-results/` `playwright-report/` | 已 gitignore |
| **本机绝对路径** | `D:\code\...` `/Users/xxx/...` | 改为相对仓库根的路径 |
| 密钥与令牌 | `.env` `*.pem` 各类 token | 绝不提交 |

CI 里有一道「检查绝对路径泄露」的关卡，命中会直接失败。

## 二、路径写法

正确：

```md
源码见 `tracks/rust/projects/minidb/src/engine.rs`
```

错误：

```md
源码见 `D:\code\learning-hub\tracks\rust\projects\minidb\src\engine.rs`
```

原因很简单：读者 clone 到自己的机器上后，你的盘符对他毫无意义，
而且这会暴露你的目录结构。

## 三、文件编码与换行

- UTF-8 **无 BOM**（BOM 会让一些构建工具把首行标题解析成乱码）
- LF 换行（仓库根目录有 `.editorconfig`，主流编辑器会自动遵循）
- 文件名可以有中文，但**URL slug 必须用英文**（在 `track.json` 里配）

## 四、图片

1. 放在所属轨道的 `assets` 白名单目录里，例如 `tracks/frontend/projects/lumen-kanban/screenshots/`；
2. 文档里用**相对路径**引用（`./screenshots/01-初始界面.png`）；
3. 构建时会被复制到 `site/public/content/assets/<trackId>/` 并自动改写 URL。
   不在白名单里的图片不会被复制，页面会退化成 GitHub 链接。

## 五、版本号

教程里提到的版本号（Rust 1.98、React 19.3 之类）必须：

1. 写进对应 `track.json` 的 `toolchain` 与 `verifiedAt`；
2. 在正文里注明验证时间。

站点会在每页顶部展示「基于 X，YYYY-MM-DD 验证」，
读者因此知道这条信息可能已经过期——**诚实标注时效，比假装永远正确更有价值**。

## 六、提交前自查

```bash
cd site
pnpm check      # 配置与断链
pnpm build      # 含 typecheck 与构建
pnpm smoke      # 渲染冒烟
```

三条全绿再提交。
