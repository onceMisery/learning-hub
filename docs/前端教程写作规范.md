# 前端教程写作规范

这份规范管的是 `tracks/frontend/tutorial/` 下的全部教程文档，也适用于后续新增轨道的教程。
写新内容、改旧内容之前先读一遍，别凭手感发挥——**风格一致本身就是可读性的一部分**。

> 读者画像固定为：**有 Java 开发经验，jQuery / HTML / CSS 有接触但不系统**，
> 目标是在 26~30 周内独立开发现代前端应用。所有内容都围绕这个画像取舍，
> 不要为了"全面"去补 Java 程序员已经会的通用编程概念。

## 三、核心概念小节的写法

每个概念小节统一按四步展开，不要一上来就给结论：

1. **是什么** —— 一句话定义，术语后括注英文原名（首次出现时）
2. **为什么需要** —— 它解决了什么问题；不这么做会怎样
3. **怎么用** —— 一段最小可运行代码，配关键注释
4. **坑在哪** —— 初学者 90% 会踩的那个点

模板：

```md
### 3.2 事件循环

**是什么**：事件循环（Event Loop）是 JavaScript 调度任务的执行模型……

**为什么需要**：JS 只有一个调用栈，如果所有任务排队执行，一个慢请求就会冻住整页……

**怎么用**：

```js
// 关键：微任务先于宏任务执行
console.log('1 同步');
setTimeout(() => console.log('4 宏任务'), 0);
Promise.resolve().then(() => console.log('3 微任务'));
console.log('2 同步');
// 输出顺序：1 同步 → 2 同步 → 3 微任务 → 4 宏任务
```

**坑在哪**：`await` 后面的代码相当于放进微任务队列……
```

### 长度要求

- 每个阶段文档的核心概念部分不少于 **8 个小节**
- 全文不少于 **8 个代码块**（当前多篇只有 0~2 个，是"简陋"的主要来源）
- 单篇总长度目标 **18000~26000 字符**（原为 6000 左右）

## 四、代码演示规范

1. **必须标注语言**：` ```ts ` ` ```js ` ` ```css ` ` ```html ` ` ```bash ` ` ```json `
2. **必须可运行**：不写伪代码、不写 `...` 省略关键逻辑。实在要省略，用注释 `// 其余字段略` 说明。
3. **必须有输出/结果**：异步、算法类示例在注释里写出运行结果。
4. **对比写法用正反例**：错误写法在前，正确写法在后，各配一句说明。
5. **关键行加注释**：解释"为什么这么写"，而不是复述代码在做什么。
6. **代码风格统一**：2 空格缩进、单引号、语句末尾分号、优先 `const`、优先模板字符串。
7. **不写绝对路径**：路径一律相对仓库根（见《仓库卫生规范》）。

## 五、多语言语法对照（LangTabs）

教程面向"有 Java 经验、正在学第二门语言"的读者。讲**语法点**时，必须在同一个位置给出
Java / TypeScript / Rust / Go / Python 的写法对照——读者要的不是"这门语言怎么写"，
而是"它和我已经会的语言差在哪"。

对照统一用站点提供的 `<LangTabs>` 块（用法见 `tracks/frontend/guide/01-自定义组件.md`）：
它把五份实现收进一个可切换标签的代码块，一次显示一种语言。

### 什么时候必须加对照

| 属于"语法点"，必须配 `<LangTabs>` | 属于"框架/工具概念"，不配对照 |
| --- | --- |
| 变量声明与可变性、类型标注 | React 组件与状态 |
| 函数定义、默认参数、可变参数、闭包 | Vite 配置、pnpm 工作区 |
| 类 / 结构体 / 继承 / 接口 | Tailwind 工具类体系 |
| 数组与集合的常用操作 | Motion 动画 API |
| 错误处理、异常与错误传播 | Dexie schema 与迁移 |
| 空值表示与可选值 | Electron IPC 与安全模型 |
| 字符串插值与格式化、循环、模式匹配 | 路由、测试框架 |
| 泛型、类型收窄、枚举/联合类型 | 构建产物与性能优化手段 |

判断标准很简单：**如果读者在别的语言里做过同样的事，就值得对照**；如果这个概念只在
当前生态里存在（如 Electron 的主进程），硬凑五种语言只会制造噪音。

### 写作约定

1. **顺序固定**：Java → TypeScript → Rust → Go → Python。顺序即代码围栏出现顺序，
   不要按语言名长度或心情排。
2. **每个面板 3~8 行**，只演示这一个语法点。不要贴完整程序、不要带 `main` 函数、
   不要引入与本语法点无关的 import。
3. **面板内用注释点出差异**，至少一句。例如 Rust 面板要写清"默认不可变，`mut` 才可赋值"。
   注释解释的是**与 Java 的差异**，不是复述语法。
4. **某语言确实没有对应写法**（如 Go 没有继承、Java 没有默认参数）：不要用面板凑数，
   把该语言从 `<LangTabs>` 中略去，改用 `<Callout kind="info">` 在下方一句话说明原因。
5. **版本口径**：Java 21 LTS、TypeScript 7、Rust 2024 edition、Go 1.24+、Python 3.13。
   不要用已废弃的写法（Java 的 `Date`、Python 的 `%` 格式化等）。
6. **一篇里的对照块数量**：阶段 2、阶段 3 各不少于 10 个；其余阶段只在出现语法点的
   小节里点缀 1~3 个即可。

### 配套说明文字

`<LangTabs>` 前面必须有一句话说明"这组对照在比什么"，例如：

```md
变量声明的差异集中在两处：**是否可重新赋值**，以及**类型是编译期还是运行期确定**。
```

后面可以跟一句结论性总结（放 1~2 条即可，不要复述五个面板的内容）。

## 六、章节衔接的写法

每篇开头的「本阶段在学习路径中的位置」必须回答三个问题，用一段话或三行列表说清：

```md
## 一、本阶段在学习路径中的位置

- **上承**：阶段 1 你已经能用语义化标签 + Flex/Grid 搭出静态页面，但页面是"死"的——内容写死在 HTML 里。
- **本阶段**：让页面"活"起来。建立**状态驱动**的心智模型：数据 → 渲染函数 → DOM。
- **下接**：阶段 3 用 TypeScript 给这份状态加上类型约束，让编译器替你兜住一半的 bug。
```

规则：

- 上承必须引用**上一阶段的具体产出物**，不能写"完成前面的内容"
- 下接必须给出**下一阶段文档的相对链接**
- 三段里都要出现本阶段的核心概念（加粗）

## 七、写作风格

| 规则 | 正面示例 | 反面示例 |
| --- | --- | --- |
| 用第二人称「你」 | 「你会看到控制台输出……」 | 「我们可以看到……」 |
| 先讲为什么，再讲怎么做 | 「之所以要 `min-width: 0`，是因为 flex 子项默认最小尺寸是 auto……」 | 「设置 `min-width: 0`」 |
| 不用"显然""很简单""众所周知" | 「这一步容易出错，原因是……」 | 「显然，这里只需要……」 |
| 断言要有依据 | 「官方 benchmark 显示构建提速 10~30 倍（Vite 8 发布说明）」 | 「构建快得多」 |
| 术语首次出现给英文 | 「层叠上下文（stacking context）」 | 「层叠上下文」 |
| 表格用于对比，列表用于罗列 | 语言对照用三列表格 | 三列信息硬写成段落 |
| 段落控制在 5 行以内 | — | 一整屏不分段 |

### 排版细节

- 中文与英文/数字之间加空格：`用 React 19 实现`，不是 `用React 19实现`
- 代码、文件名、命令一律用反引号包裹
- 一级标题用 `##`（H1 由页面头部渲染，正文里不要再用 `#` 之外的一级标题重复）
- 分隔线 `---` 只用于大段落之间，不要每段都加
