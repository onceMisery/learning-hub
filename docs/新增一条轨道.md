# 新增一条轨道

这是检验仓库架构是否合格的关键路径：**加一条轨道，站点代码一行都不用改。**

如果你在下面任何一步发现自己需要去改 `site/src/` 里的代码，那说明架构有问题，请开 Issue。

## 一、复制脚手架

```bash
cp -r tracks/_template tracks/golang
```

目录名就是轨道 id，只能用小写字母、数字和连字符（下划线开头的目录会被当成模板跳过）。

## 二、填 track.json

```jsonc
{
  "id": "golang",              // 实际以目录名为准，这里写一致即可
  "title": "Go · 从 Java 到 Go",
  "subtitle": "一句话说清这条轨道解决什么问题",
  "order": 30,                 // 导航排序，建议间隔 10，方便日后插入
  "status": "planned",         // planned：显示占位页；active：正常发布
  "accent": "cyan",            // blue | amber | cyan | green | teal
  "tags": ["Go", "并发", "服务端"],
  "toolchain": "go-1.24",      // 会在页面顶部显示「基于 X 验证」
  "verifiedAt": "2026-09-15",
  "outline": ["准备覆盖的主题一", "主题二"],   // status 为 planned 时展示
  "sections": [
    {
      "id": "tutorial",
      "title": "教程",
      "path": "tutorial",      // 相对 tracks/golang/ 的目录
      "order": 10,
      "pages": [
        { "file": "01-起步.md", "slug": "01-start", "title": "起步", "tags": ["入门"] }
      ]
    }
  ],
  "codeRoots": ["projects/demo"],  // <SourceRef> 能读取的目录白名单
  "assets": []                     // 允许对外发布的图片目录
}
```

### 字段说明

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | 否 | 会被目录名覆盖，写出来只是为了可读性 |
| `title` | 是 | 导航与卡片上的标题 |
| `order` | 否 | 默认 100，数值小的排前面 |
| `status` | 否 | `active`（默认）/ `wip` / `planned` |
| `accent` | 否 | 轨道主题色，默认 `teal` |
| `verifiedAt` | 否 | 内容验证日期，配合 `toolchain` 显示时效提示 |
| `sections[].path` | 是 | 相对轨道目录的路径 |
| `sections[].pages[].file` | 是 | 相对 `sections[].path` 的文件名，支持 `../` |
| `sections[].pages[].slug` | 是 | **发布后即冻结**，改它必须登记重定向 |
| `sections[].pages[].splitBy` | 否 | 超长文档按该正则拆页，例如 `"^## \\d+\\."` |
| `sections[].pages[].splitSlugs` | 否 | 拆分后各部分的 slug，数量应与拆分段数一致 |
| `codeRoots` | 否 | `<SourceRef>` 白名单，不在此列的文件一律拒绝读取 |
| `assets` | 否 | 图片资源白名单，在此列内的图片会被复制到站点 |

## 三、放文档

```
tracks/golang/
├── track.json
└── tutorial/
    ├── 01-起步.md
    └── 02-并发模型.md
```

文档用标准 Markdown（GFM）。围栏语言请写标准 id：`go` / `java` / `bash` / `toml` / `json`。

## 四、生成并验证

```bash
cd site
pnpm content     # 生成内容
pnpm check       # 校验配置与断链
pnpm dev         # 本地看效果
```

站点会自动：

- 在导航和首页生成这条轨道的入口；
- 生成路由 `/golang/tutorial/01-start`；
- 把正文纳入全文搜索；
- 在进度页为它统计完成度。

**全程不需要改任何站点代码。**

## 五、加实战项目（可选）

```
tracks/golang/
├── track.json
├── tutorial/
└── projects/
    └── demo/            # 可独立 cargo run / go run / npm start 的工程
        ├── README.md
        └── src/
```

然后在 `track.json` 里加一个 section：

```jsonc
{
  "id": "projects",
  "title": "实战项目",
  "path": "projects",
  "order": 20,
  "standalone": true,
  "projectName": "demo",
  "projectRoot": "projects/demo",
  "pages": [{ "file": "demo/README.md", "slug": "demo", "title": "demo 实战" }]
}
```

并把源码目录加进 `codeRoots`，这样正文里就能用 `<SourceRef>` 引用真实源码了。

## 六、发布

把 `status` 从 `planned` 改成 `active`，重新构建即可。

如果要下线某条轨道，把 `status` 改成 `planned` 会比删目录更友好——
读者还能看到「这条轨道曾经存在过」。
