块里的排版：每行只写和上一行不同的部分

点查一个 40 字节的键，盘上却落了 4 KB 的读；把 block_size 调大到 64 KB 想少跑几趟，点查 P99 反而从 0.9 ms 涨到 3 ms——sst_dump 给出答案：块平均 63 KB，单次点查解压的字节翻了 15 倍。差别在块的内部编码：它决定了块内二分能不能成立，也决定了每次点查要背多少额外字节。

1

表象观察：块是 I/O、缓存和压缩共同的最小单位

先不拆编码，只看它对外表现出什么。

「观察一个系统，先分清它的静态结构、动态过程和外部依赖。」

同一个块结构，三件事都压在它身上：读它就是一次 I/O（块体 + 5 字节 trailer）；缓存它就是一个条目；压缩它就是一次独立实验（压不赢就原样落盘）。所以 block_size 调大到 64 KB，「一次多读点」的顺序扫收益，会被「点查解压字节 ×15」吃回去——块的平均大小就是点查的下限成本。

键按序写入→前缀压缩：只存增量→restart：每 16 键存一次完整键→块满封口（4096/3686 线）→filter → index → data 三级定位

把 data block 想成一页只写连续账号的账页：每行只写「和上一行不同的部分」，但每隔 16 行重新誊一遍完整账号——翻页查账时，先看页边的行号目录（restart 数组）二分定位，再顺着誊清的行往下对。

动静融合：部件 × 阶段

同一部件在写块和查块两个阶段各演一个角色。

「动静融合的关键是映射：每个部件在每一步里负责什么。」
部件①–③ 写入④⑤ 路标与封口⑥ 布隆⑦ index⑧ 块内查找
entry 前缀压缩只存增量，33B→16Brestart 处强制存全键——还原靠前键接力
restart 数组—每 16 键记一个偏移——二分的路标
块尾 trailer—1B 压缩类型 + 4B 校验和——逐块自证清白
filter block——说不存在 → 0 次数据读——
index block———缩短键 → BlockHandle给出目标块
Block::Iter————二分路标 + 线性 ≤16

涌现属性：「块内二分能成立」不属于任何单个部件——它是前缀压缩（省字节）+ restart（可定位）+ 排序写入（有序）三方协同的结果。乱序写入会让三件事同时失效，这就是 SST「键必须严格升序」的报错守在这里的原因。

5

环境场景：块之外还有什么

拆掉任何一个外部依赖，前面看到的账都要重算。

「环境属性 = 外在关系 + 依赖 + 失效后果。」
块缓存filter/index 属于「一次读反复用」，可常驻或高优先级；data block 按 LRU 淘汰——一次点查最好 3 次内存查找，最坏 3 次盘读。
字典压缩4KB 块彼此独立、键只有十几字节，单块练不出字典；用前面若干块训练 16KB 字典存成 meta block，小键值压缩比从聊胜于无到 2~3 倍。
分区索引 / 分区布隆大文件把索引和布隆按 metadata_block_size=4KB 切片按需进缓存；代价是点查各多一跳顶层查询。
optimize_key_common_prefixfv ≥ 8：整块所有键的公共前缀只在块头存一次，restart 键里也剥掉——device_47xxx 这类超级前缀还能再瘦一圈。
迭代器自动预取连续块读触发预取：8KB 起步每次翻倍、上限默认 256KB——把「很多个小块读」并成少量大读，也是调大 block_size 收益递减的原因之一。
Parquet 对照两边押同一个赌注：数据排过序，「先看小抄再翻页」才划算。SST 的块服务点查（粒度细），Parquet 的页服务扫描（粒度粗）。

边界：本页画的是 data block 的编码与查找 happy path + 布隆拒绝分支；块缓存的分片与二级缓存见第 10–11 章，大值出走见 blob 篇。

复盘自测

能说清「restart 是一笔什么账」，才算真的懂块内排版。

「用自己的话能讲清楚，才算真的懂。」

一页带走

增量记账，十六行一誊；小抄三级，先筛再翻页。

· entry = shared / non_shared / value_len 三个 varint32 + 键增量 + 值；三个键 33B → 16B 省 52%，代价是每 entry 3 个长度头。

· restart point（默认每 16 键）用「每 16 键存一次完整键」换块内二分：64 键 4 路标 ≈ 2 次比较 + ≤16 线性。

· 块按字节切（block_size 4096 + deviation 10 → 3686 线），块尾是 restarts 数组 + num_restarts + 5B trailer；大值独占块是 blob 的引子。

· 一次点查 = filter → index → data 三张小抄各读一次；布隆说不存在就 0 次数据读，index 用缩短分隔键把索引项压小。

· 边界与简化：键材料 9/15/9B 与 33→16B、64 键 4 路标、device_5 缩短键均为文章算例；block_size/restart interval/误判率默认值以 RocksDB 11.13 源码为准。
