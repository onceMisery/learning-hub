表象观察：日志里的「0 字节压实」

先不拆流水线，只看它对外表现出什么。

「观察一个系统，先分清它的静态结构、动态过程和外部依赖。」

十几条 compaction 完成记录里，好几条只花几毫秒、写了 0 字节，事件是 event: "trivial_move"。这不是没干活——是 Picker 判定出「不用搬数据」：只改 MANIFEST 两行账。把一次压实想成一场搬家公司的工作流：Picker 是排单员，CompactionJob 是搬运队，CompactionIterator 是打包员，MANIFEST 是物业台账——搬家完成后一次改好，绝不改一半。

谁该搬：Picker 排单→绿色捷径：trivial move（分支）→怎么搬：切分 + 快照分带归并→谁来搬：后台线程池→原子安装：VersionEdit

策略层（上一章）决定「哪层该压」；这一章隔着三个问题把文件安全换掉：谁该搬（每轮怎么挑出互不冲突的一小撮）、谁来搬（线程池和限流怎么分蛋糕）、怎么搬（从 key range 切分到原子换账本）。

动态分析：一次任务的生命周期，8 个相位

第一遍跟琥珀点走主路；第 2 步盯绿色捷径的判定，第 4 步盯快照分带怎么丢掉 seq=4。

「动态分析看的是时间轴上的顺序、状态变化和因果链。」
相位阶段关键动作读数
0–90°① 打分选层score 最高层入选；CompactionPri（默认 kMinOverlappingRatio）取头名文件输入 1
90–180°② 扩干净切口半键重叠扩边（f5 带上 f6）；SetupOtherInputs 拉进输出层重叠文件；并发闸放行输入 3 · 切口干净
180–270°③ trivial move 判定五条件全过 → 两行账零字节；否则进主路。日志 event:"trivial_move" 不是没干活分支点
270–360°④ 切 3 段并行128 锚点按序累计，总量 1/N 下刀；边界 = user key，同键永远同段3 段并行
360–450°⑤ 快照分带合并seq=5→带8、seq=4→带8（同带只留最新→丢）、seq=2→带3（留）丢 1 版
450–540°⑥ 墓碑三道判据推干净 / bottommost / 保留（kKeepDel）；Merge 键在此结清COMPACTION_KEY_DROP_*
540–630°⑦ 输出新 SST64MB 或祖父母边界切刀；verify_output 回读校验和与键序输出 2
630–720°⑧ VersionEdit 原子安装删输入 + 加输出 → LogAndApply 一次持锁换 Version → 引用归零删旧文件新 Version 生效

动静融合：部件 × 阶段

同一部件在不同阶段扮演不同角色，这张矩阵是排障时的索引。

「动静融合的关键是映射：每个部件在每一步里负责什么。」
部件①② 排单③ 分支④ 切分⑤⑥ 归并⑦⑧ 安装
Picker（选层/扩边）打分、扩干净切口查 trivial move 条件———
并发闸 / being_compacted范围相撞 → 放弃本轮————
CompactionJob—全过 → 跳过整个 Job128 锚点切 3 段并行喂 MergingIterator—
CompactionIterator——每段一个分带去重 · 墓碑判据 · Merge 结算—
输出切口（ShouldStopBefore）———64MB / 祖父母边界切切口 = 下次输入规模
VersionEdit / MANIFEST—捷径只写两行账——删输入+加输出，一次持锁生效

涌现属性：「层内不重叠」这条不变式不属于任何单个部件——它是干净切口（同键不拆开）+ 并发闸（范围不相撞）+ 原子安装（半成品不进账）三方协同守出来的。任何一方失守，账就乱了。

5

环境场景：流水线之外还有什么

拆掉任何一个外部依赖，前面看到的流程都会变。

「环境属性 = 外在关系 + 依赖 + 失效后果。」
后台线程池max_background_jobs=2（默认）拆成 flush 1 条（HIGH）+ 压实 1 条（LOW）；压到非零最大输出层自动转 BOTTOM 池，不与前台抢带宽。
CF 级限流compaction_thread_limiter 限单个 CF 的在途任务数；领不到令牌就排队——大 CF 不许吃光所有流水线。
compaction filter每个 user key 的第一个已提交版本过一遍过滤器，返回「删」当场变墓碑或跳段；与 trivial move 互斥。
flush 孪生兄弟FlushJob 与压实共用 BuildTable 和 CompactionIterator（compaction=nullptr）；差别只有输入是 memtable、输出固定 L0、不做跨文件墓碑 GC。
Remote Compactioncompaction_service 把 subcompaction 搬到远端跑：Schedule → OpenAndCompact → Wait → 导入安装；任一环节掉链子 kUseLocal 原路回退本机。
湖上同款MANIFEST ≈ manifest 文件（不可变日志 + 原子切换，失败即全弃）；subcompaction ≈ Spark split（都按 key range 切、边界取 user key）。

边界：本页画的是一次任务的 happy path + trivial move 分支；真实收尾日志样例：「Compacted (L1 8 files + L2 23 files) => 19 files, 620MB · write-amplify(1.4) · records in: 5,800,000, records dropped: 1,230,000」。

能说清「0 字节压实为什么是好事」，才算真的懂这条流水线。

「用自己的话能讲清楚，才算真的懂。」

一页带走

排单扩边防冲突，捷径两行账；分带丢版本，一次持锁换新账。

· Picker 三步走：打分选层 → CompactionPri 取头名并扩成干净切口 → 拉输出层重叠与 grandparents；与在途任务范围相撞直接放弃本轮。

· trivial move 五条件全过 = 只改 MANIFEST 两行账：DeleteFile(L2,f9) + AddFile(L3,f9)，20MB 零字节搬运——日志 event:"trivial_move" 不是没干活。

· 线程预算三层：max_background_jobs（2）总闸 → max_subcompactions（1）单任务并行 → limiter 按 CF 限在途；128 锚点按 key range 切段，边界永远落在 user key 上。

· CompactionIterator 按「最早可见快照」分带，同带只留最新；墓碑要「早于最早快照 + 更深层无此键」或「bottommost 且无更老带引用」才能真删。

· 安装 = 一个 VersionEdit（删输入+加输出）+ 一次 LogAndApply：读侧要么旧账要么新账，不存在「看见一半」；旧文件引用归零后由后台删除。

· 边界与简化：演示任务的输入 3 / 输出 2 / 丢 1 版为小算例；subcompaction 切 3 段为示意（默认 max_subcompactions=1）；日志样例数字引自正文第五节。
