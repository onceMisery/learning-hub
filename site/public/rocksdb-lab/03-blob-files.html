大值单独安家：SST 里只留一张提货单

2 MB 的文档切片跟着键走完 7 层 LSM，要被原样重写 7 遍、实际写盘 14 MB——写放大 7 倍，钱花在一堆几乎永远不会改的字节上。这页看 Integrated BlobDB 怎么在 flush/压实顺手把大值切进 blob file：账本只留提货单，回收靠压实时给 blob 文件称重。

1

表象观察：磁盘三倍占用，压实窗口打满盘

先不拆机制，只看大值在 LSM 里对外表现出什么。

「观察一个系统，先分清它的静态结构、动态过程和外部依赖。」

文档检索服务把 2 MB 切片直接塞进 RocksDB：磁盘占用是估算量的三倍，凌晨压实把盘打满，COMPACT_WRITE_BYTES 高得离谱——而这批文档大多是写进去就不改的冷数据。差别不在值多大，而在这些值被迫跟着键走完了 LSM 的每一层。

2MB 值→flush/压实分流→SST 只留 8B BlobIndex→blob file 存原值→压实搬提货单

一句话本质：大值在落盘时就地分流，SST 里只留一张提货单。不开 blob 付三笔账：SST 膨胀（索引/布隆被稀释）、压实 O(层数) 搬运（写放大 ≈ 层数）、缓存挤占（2MB 冷块顶掉几百个热小块）。100GB 业务数据、值平均 2MB：开 blob 后 SST 总量 ≈ 100GB × (9B 键 + 8B 指针)/2MB ≈ 1MB 级，blob 文件常态接近 100GB 静置。

5

环境场景：分流之外还有什么

拆掉任何一个外部依赖，前面看到的行为都会变。

「环境属性 = 外在关系 + 依赖 + 失效后果。」
blob cache 配置默认 nullptr：未配则每次热读都多一次盘读——点查 P99 长尾变差先查它。
压实节奏GC 主体是常规压实：压得不勤的库，blob 垃圾照样堆积——开关只是给了回收一条路。
MANIFESTBlobFileAddition/BlobFileGarbage 随 VersionEdit 原子生效；offset 报错先查这里是否与 SST 同步。
min_blob_size 选型值普遍几百字节时划不出有意义的线，间接寻址开销压过写放大收益。
blob_file_starting_level短命大值场景调高：浅层保持完整 LSM 语义，活过几轮压实的才分流。
温度分层blob 文件支持温度标记，与 Temperature 配合把冷数据大值成批送到低温盘，账本留在热盘。

边界：本页主线是成熟的 flush/压实分流；11.x 实验性的写路径直写（enable_blob_direct_write）与旧的独立 BlobDB 包装层不展开。

6

复盘自测

能说清「提货单在什么时候开、GC 靠谁推动」，才算真的懂 blob 分流。

「用自己的话能讲清楚，才算真的懂。」

一页带走

大值落盘就地分流，账本只留提货单；回收跟着压实走。

· 大值在 LSM 里付三笔账：SST 膨胀、压实 O(层数) 搬运、缓存挤占；enable_blob_files 让 flush/压实顺手把 ≥ min_blob_size 的值切出去。

· SST 里留 BlobIndex：type+文件号+偏移+大小+压缩，2MB 换 8B；offset 指向 value 本身，读整条记录回退 key+32 字节。

· blob file 是 append-only 日志：30B header、32B 记录头（双 CRC：定位与内容各一层）、关闭时写 32B footer。

· 读路径多一层间接：SST 块 → BlobIndex → blob cache / blob file；BlobFileCache 缓存 reader，blob cache 缓存内容。

· GC 三机制：BlobGarbageMeter 称重进 MANIFEST，age_cutoff 圈最老 25% 搬迁，force_threshold（默认 1.0=永不触发）强排引用 SST。

· 边界与简化：min_blob_size=1KB、700/300 组合、文件 10 的 100MB/20MB 均为文章演示值；写路径直写与旧包装层本页不展开。
