1

表象观察：删了 8000 万行，P99 为什么反而涨

先不拆路径，只看它对外表现出什么。

「观察一个系统，先分清它的静态结构、动态过程和外部依赖。」

数据明明变少了，点查却变慢。差别不在缓存冷热，而在 LSM 读路径的形状：写入永远落在 memtable，读取却要从新到旧、一层一层问过去。那 8000 万行删除只留下满地墓碑，旧层的文件还在原地，每次点查照样要问到最后一层。

Get(key)→SuperVersion 快照→memtable→immutable→L0 逐个→L1+ 每层一个→第一次命中即返回

一句话本质：问一群按资历排座的师傅，规矩只有一条——先被问到的答案就是最终答案，因为座次就是新旧次序。命中层越深，这次读越贵：GET_HIT_L0 → L1 → L2_AND_UP 三个计数器直接反映数据「冷」到了哪一层。

动态分析：一次 Get 的 8 个相位

第一遍只看橙点一层层往下问；第二遍同时看读数条「布隆判定」和「返回值」什么时候落定。

「动态分析看的是时间轴上的顺序、状态变化和因果链。」
相位阶段关键动作读数
0–90°取快照 seq先引用 SuperVersion，再取快照 seq（顺序约束）视图已钉住
90–180°问 memtable内置布隆先行，再查跳表MEMTABLE_MISS
180–270°问 immutable队列新→旧逐个问未命中
270–360°问 L0f7 布隆「肯定没有」；f8 键范围外2 个全裁掉
360–450°层内裁剪二分 + FileIndexer 收窄，键范围过滤L1 候选 1 个
450–540°布隆过滤F3「可能存在」→ 放行进漏斗可能存在
540–630°块内定位index → BlockHandle → 读块（块缓存）→ SeekForGet块已定位
630–720°SaveValue 裁决撞上 seq=10 墓碑 → kDeleted 终止NotFound（墓碑）

相位零点：0° = Get 钉住 SuperVersion；720° = 裁决完成返回。值得分步细看的两处：第 ④ 步两个 L0 文件被两种不同手段裁掉（布隆 vs 键范围）；第 ⑧ 步 kDeleted 终止后 L2 的旧版本永远不被看到。

涌现属性：「读不阻塞写」不属于任何单个部件——SuperVersion 引用计数让后台随便换视图，读者拿着钉死的旧视图跑完。而「先问的一定对」由两个不变式涌现：seq 全局单调 + 层间新旧不变，缺一个整条读路径就塌。

5

环境场景：读路径之外还有什么

拆掉任何一个外部依赖，前面看到的行为都会变。

「环境属性 = 外在关系 + 依赖 + 失效后果。」
块缓存（默认 32MB）读回来的 4KB 块安家在内存；没有它，每个候选文件都要真读一次盘。
row cache第 0 关：缓存「这个键的最终答案」；数据一 flush 就作废，只适合反复点查的负载。
快照列表（压实侧）快照对读只是一个 seq 数字；重的那半（不许压实丢可见版本）记在压实侧的账上。
上游写负载flush 频率决定 L0 厚度、压实进度决定旧层深浅——读放大的形状是写路径给的。
布隆过滤器每文件一份全量过滤器：占内存与元数据，换来「肯定没有」时的零块读取。
MultiGet 批量同一条漏斗，块收集后集中读：键的空间局部性决定省多少往返。

边界：本页画的是点查 Get；范围删除墓碑在本页只登记不判死（max_covering_tombstone_seq），展开留到压实篇。

一页带走

座次即新旧，第一答案算数；墓碑也是答案。

· 一次 Get = 钉 SuperVersion → 定快照 seq → 拼 LookupKey → memtable → immutable → Version 逐层；第一次命中即终止。

· 正确性靠两个不变式：seq 全局单调 + 同 key 上游永远比下游新；命中层越深读越贵（GET_HIT_L0/L1/L2_AND_UP）。

· 磁盘侧四段漏斗：布隆挡点查（零块读取）→ index 定位块 → 读块（4KB/块缓存 32MB）→ SaveValue 按 type 裁决。

· kDeleted 与 kNotFound 都返回 NotFound：语义等价、代价不同——删除只是一次写，回收要靠一次压实。

· 边界与简化：演示时刻的文件布局为教学设定（墓碑在 L1）；迭代器方向切换税、Merge 键归并与范围删除本页不展开。
