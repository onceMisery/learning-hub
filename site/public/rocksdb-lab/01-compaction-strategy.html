1

表象观察：L0 打摆与 500 ms——形状选错，一本账爆掉

先不拆策略，只看它对外表现出什么。

「观察一个系统，先分清它的静态结构、动态过程和外部依赖。」

压测前 30 分钟写入 P99 稳定 2 ms，之后开始抖，40 分钟后掉到 500 ms——磁盘只用了不到 20%。STATS 里 L0 文件数在 20 和 36 之间来回打摆，soft_pending_compaction_bytes_limit（默认 64GB）的减速逻辑已经触发：写入线程在等后台收拾账本。写入永远是把账「先记下来」，压实负责「把账理清」；策略决定后台按什么形状理账。

写入：一切先记下→压实形状：金字塔 / 叠放 / 队列→读放大：一次点查问几个→写放大：重写几遍→空间放大：新旧共存多久

不收拾会发生三件坏事：读放大失控（重复版本越多问的人越多）、墓碑永生（Delete 只是一条写入）、空间账没法收。压实的三件事——去重、消墓碑、控读放大——怎么排优先级，就是三种策略的分岔口。策略在 CompactionStyle 里定型：Level（0，默认）、Universal（1）、FIFO（2）、None（3，只走手动 CompactFiles）。

动态分析：同一条数据流的 8 个相位

第一遍看 Leveled 怎么把 L0 收进层里；第 6/7 步切到 Universal，第 8 步切到 FIFO——同一条数据流，三种走向。

「动态分析看的是时间轴上的顺序、状态变化和因果链。」
相位阶段关键动作读数

动静融合：策略 × 三本账

同一份数据交给不同形状，三本账的付法完全不同——这张矩阵就是选型表。

「动静融合的关键是映射：每个部件在每一步里负责什么。」
账本Leveled（dynamic，7 层）Universal（默认参数）FIFO（默认参数）
写放大最高：下推一层 ≈ 10× 重写，全链路常到两位数中低：只合尺寸接近的 run，size-amp 大归并偶发≈0：从不重写
读放大最低：L0 ≤4 + 每层 1 个，约 5~10 个候选高：run 间全重叠，候选 = run 数（可用 max_read_amp 压）最高：N 个文件逐个问
空间放大低：层形状约束在 multiplier 倍内可配：默认最多 200%（100B → 300B）由 max_table_files_size（1GB）硬封顶
去重 / 消墓碑每次压实都做每次压实都做不做（靠整体删除）

涌现属性：「哪本账贵」不属于任何单个参数——它是触发线（score / size_ratio / 容量线）× 形状（层 / run / 队列）协同涌现的结果。两笔账之间有一条硬约束：压得越勤，写放大越高、读放大越低；压得越懒，反之。

5

环境场景：账本之外还有什么

拆掉任何一个外部依赖，前面看到的形状都会变。

「环境属性 = 外在关系 + 依赖 + 失效后果。」
写停顿闸门soft/hard_pending_compaction_bytes_limit（64GB/256GB）+ L0 减速 20/停写 36：压实欠账直接顶住前台写入——开头压测的 500 ms 就是这一闸。
监控三落点压实日志 write-amplify 字段看写放大；GET_HIT_L0/L1/L2_AND_UP 看命中层深度；EstimateCompactionBytesNeeded 高企就是压实欠账。
负载类型点查密集选 Leveled；大批量写/扫描选 Universal；TTL 流水（监控、轨迹、暂存）选 FIFO——大值为主配 Leveled+BlobDB 或 FIFO。
压缩过滤器compaction filter 在归并时逐键执行（服务端 TTL、数据修补），与 trivial move 互斥——过滤器要真的执行。
手动模式kCompactionStyleNone 关掉后台压实，只走 CompactFiles——离线批处理专用，欠账没人替你还。
湖上同款Iceberg rewrite_data_files / Delta OPTIMIZE 与 LSM 压实同构：不可变文件 + 后台重写 + 原子换清单；FIFO ≈ 按保留期整分区删除。

边界：本页画的是三种策略各自的 happy path 与文章算例；压实任务内部（Picker 扩边、快照分带、原子安装）见第 6 章。

复盘自测

能说清「为什么没有同时全低的形状」，才算真的懂选型。

「用自己的话能讲清楚，才算真的懂。」

一页带走

层收读、叠省写、队列零重写——三本账先挑贵的。

· Leveled：L0 按 level0_file_num_compaction_trigger（4）计分、L1+ 按层尺寸/层目标，score ≥ 1 触发；dynamic_level_bytes 默认开，基座浮动、目标按 10 反推，小库不养空层。

· Universal：一摞按时间叠放的 sorted run；size_ratio 挑尺寸接近的相邻 run，max_size_amplification_percent（200）兜底空间放大，allow_trivial_move 让不重叠 run 白捡换层。

· FIFO：全在 L0，超 max_table_files_size（1GB）删最旧、ttl 到期整文件删；写放大 ≈0，代价是不清旧版本、点查逐个问。

· 同层先压谁由 CompactionPri（默认 kMinOverlappingRatio）决定：重叠越少越先，零重叠可能白捡一次 trivial move。

· 边界与简化：三本账条长为演示值；run 尺寸 24/20/17/14/10 与 30/28/27/10、FIFO 的 300/300/400MB 均为文章算例，参数默认值以 RocksDB 11.13 源码为准。
