磁盘上的有序账本：命门长在尾巴上的 53 字节

备份脚本把一个 SST 截短了几百字节，RocksDB 直接拒绝打开：Corruption: Input is too short to be an SST file。坏的不是数据块，而是尾部——SST 把全部目录信息放在文件最后固定的 53 字节里，尾巴一缺，前面的数据块纵然完好也一张地图都没有。这页把 writer 的正向写和 reader 的反向找放在同一条时间轴上。

1

表象观察：拒绝打开，而不是少几条数据

先不拆布局，只看它对外表现出什么。

「观察一个系统，先分清它的静态结构、动态过程和外部依赖。」

同一个 SST，中间挖掉 4KB 可能要等第一次读到那个块才报 block checksum mismatch；尾巴缺 100 字节却在开库那一刻就拒绝——因为这个格式的命门恰好长在尾巴上。SST（Sorted String Table）只有两条硬约束：按键有序（乱序输入直接报 Keys must be added in strict ascending order.）和不可变（footer 落盘后再也不改，删除是追加墓碑，旧文件等压实退役）。

单遍写：边写边追加→写最后一块时才有块清单→目录只能放尾部→尾部 53 字节 = 唯一可靠入口→reader 反向找

不可变是全系统的地基：读不用加锁、块缓存键永不过期、压实只增不改（半成品不在 MANIFEST 里就不存在）、cp 就是备份。文件名也简单到只有编号：000005.sst，六位数字加后缀。

动态分析：写一遍，读一遍，8 个相位

第一遍跟橙点正向写（0–450°）；第二遍跟绿点反向找（540–720°）——写是正向的，读是反向的。

「动态分析看的是时间轴上的顺序、状态变化和因果链。」
相位阶段关键动作读数
0–90°① 写 data blocks键值对流式追加，每块记下 BlockHandle（offset/size）0 → 630,000
90–180°② 写 filter布隆过滤器整块落盘，挡点查的第一道闸631,000 → 751,000
180–270°③ 写 index分隔键 → 数据块 BlockHandle；fv≥6 起句柄进 metaindex751,000 → 791,000
270–360°④ 写 propertiesrocksdb.properties：统计 + 身份三件套791,000 → 791,500
360–450°⑤ 写 metaindex块名 → 句柄的小字典（140B）791,500 → 791,640
450–540°⑥ 写 footer53 字节封尾，文件从此不可变791,640 → 791,693
540–630°⑦ 解 footer文件大小−53 → 末 8 字节验魔数 → 解出 metaindex 位置791,693 − 53 = 791,640
630–720°⑧ 三层接力metaindex → index → data：每层的钥匙都在上一层手里跳回 data block

相位零点：0° = 第一个数据块落盘；720° = reader 沿 index 跳回数据块。footer 的解析顺序是从后往前：先魔数、再 version、再校验、最后 metaindex 位置——扩展魔数挡住 format_version 字节级损坏。

4

动静融合：块 × 读写阶段

同一个块在写侧和读侧各演一个角色——这张矩阵把两条时间轴叠在一起。

「动静融合的关键是映射：每个部件在每一步里负责什么。」
块writer 落盘时reader 找路时拿到的便宜 / 付出的代价
data blocks流式追加，写完即封index 指到哪读哪（4KB + trailer）顺序写最省；随机读靠 index 裁剪
filter键集合编码成位图说不存在 → 整文件免读点查 0 次数据读的概率换空间
index分隔键 → BlockHandle二分定位目标块25 万块 → 数 MB 索引（fv≥4 句柄 delta）
properties统计 + 身份三件套seq 范围快速短路、缓存键对账restart interval 设成 int32 上限（免前缀压缩）
metaindex最后写的小字典footer 的第一把钥匙几十字节换「块名→句柄」全表
footer53 字节封尾文件大小−53 固定入口尾部一缺，全文件作废——命门即入口

涌现属性：「反向找路」不是 reader 的偏好，而是单遍写的必然——写最后一块时才有完整的块清单，目录只能后置。Parquet 的 footer 在尾部是同一条因果律：两个格式在骨架上是同一个思路的两次实现。

5

环境场景：文件之外还有什么

拆掉任何一个外部依赖，前面看到的便宜都会变。

「环境属性 = 外在关系 + 依赖 + 失效后果。」
块缓存（默认 32MB）读回的 4KB 块安家在内存；唯一 ID（db_id + db_session_id + 文件号）保证缓存键跨库、跨重启都不撞。
报错对着布局找too short → 尾部；Bad magic → Part 3 魔数；unsupported format_version → 版本号；checksum mismatch @offset → 那块的 5B trailer。
备份 / 迁移cp 就是备份、硬链接就是快照——文件不改，拷贝时刻即一致点；截短尾部则开库即拒。
压缩 / 字典块级独立压缩；跨块字典（rocksdb.compression_dict）让小键值也有 2~3 倍压缩比——读侧多一张要读的小抄。
自定义收集器TablePropertiesCollector 在构建时逐键回调，把「过期数据占比」这类业务统计写进 properties，给压实当输入。
Parquet 对照目录后置 + 尾部入口 + 反向解析两边同款；SST 的目录服务「找一个键」，Parquet 的 footer 服务「裁剪一批列」。

一页带走

正文在前，目录在后；命门 53 字节，钥匙层层递。

· SST = 按键有序的不可变块集合；不可变是缓存安全、无锁读、压实「只增不改」的地基。

· 布局：data blocks → meta blocks（filter/properties/字典/范围删除）→ metaindex → index → footer，写入顺序即落盘顺序。

· footer 固定 53 字节（1 + 2×20 + 4 + 8），从文件尾反向解析；扩展魔数挡住 format_version 损坏；BlockHandle = varint64 的 offset+size，上限 20 字节。

· 每块带 5 字节 trailer（1B 压缩类型 + 4B 校验和），fv ≥ 6 起 footer 也有校验、偏移也参与校验。

· TableProperties 是体检报告，db_id + db_session_id + 文件号派生唯一 ID 撑起块缓存键。

· 边界与简化：文件偏移 630,000/631,000/751,000/791,000/791,500/791,640 为正文标尺算例（数字示意、结构为真）；块大小 4KB、缓存 32MB、format_version 8、校验默认 XXH3 均为 RocksDB 11.13 实际值。
