一条 KV 的进来与出去：一切都是追加

device_47 只「写过一次」，目录里却有它的多份影子；删掉的键一小时后还占着盘。不是 bug——RocksDB 从不原地修改数据：写是追加记录，更新是追加更大 seq 的新版本，删除是追加墓碑。这页跟着 4 条记录走完全程。

1

表象观察：三个「怪现象」其实是三个特性

先不拆引擎，只看它对外表现出什么。

「观察一个系统，先分清它的静态结构、动态过程和外部依赖。」

一个键「写过一次」，好几个 SST 里都有它的影子；删掉的键过了一小时还占着盘；du 看到的空间是业务估算的两倍。差别不在代码写错，而在 RocksDB 的根本工作方式：它从不原地修改数据，一切都是追加。写入是追加一条记录，更新是追加一条更大 seq 的新版本，删除是追加一条墓碑。

写 · 更新 · 删除→LSM 引擎：一切追加→memtable 多版本并存→flush / 压实逐层收敛→Get 挑出对的那份

一句话本质：它是一个库，不是一台数据库——一个持久的、带版本的、有序的键值映射。seq 是全库递增的序号，每写一条领一个号，是「谁更新」的唯一裁判。写永远不等旧数据，删除永远不挡新写入，空间永远有人负责收拾。

动态分析：一条 KV 的一生，8 个相位

第一遍只看橙色点（记录本体）怎么从写流水线走到 L6；第二遍同时看读数条里的「现存版本」怎么 4 → 1 → 0。

「动态分析看的是时间轴上的顺序、状态变化和因果链。」
相位阶段关键动作读数
0–90°① 组包Put 装进 WriteBatch，领 seq=7SST 0 本
90–180°② 追加 WAL整车记录顺序写进 000005.log崩溃可回放
180–270°③ 写 memtable跳表插入；seq=8/9/10 陆续入账，谁也不覆盖谁4 条并存
270–360°④ flush 出 L064MB 满 → immutable → BuildTable 顺序写成一个 SSTL0 1/4
360–450°⑤ L0 攒够 4 个四个 memtable 各出一文件，键范围互相重叠L0 4/4 触发压实
450–540°⑥ L0→L1 压实归并排序：seq7/8/9 作废丢弃，墓碑必须留下版本 4→1
540–630°⑦ 读层层问SuperVersion 快照 → memtable → immutable → L0 从新到旧第一次命中即返回
630–720°⑧ 收敛完成墓碑沉到 L6：底下无版本、无快照 → 全部丢弃版本 0

相位零点：0° = 一次 Put 领到 seq=7 开始组包；720° = device_47 在盘上 0 份痕迹。读相位（540–630°）发生在写完与压实之后，是同一时刻轴上的第二幕。

动静融合：部件 × 阶段

同一部件在不同阶段扮演不同角色，这张矩阵是排障时的索引。

「动静融合的关键是映射：每个部件在每一步里负责什么。」
部件①②③ 写入④ flush⑤⑥ 压实⑦ 读取
WriteBatch / 组提交组包、合车、领 seq———
WAL先记账，崩溃凭据memtable 落盘后可回收——
MemTable跳表追加新版本满 64MB 转 immutable—从新到旧被问
L0 SST—BuildTable 顺序写键范围重叠，逐个被问从新到旧逐个问
CompactionJob——归并去旧版本、消墓碑—
Version / SuperVersion—原子替换账本原子替换账本钉住快照，逐层找文件

涌现属性：「删除最终完成」不属于任何单个部件——它是「墓碑也是一条记录」+「压实发现底下再无版本、无快照」协同涌现的结果。写路径把账搞乱，压实负责把账理清，这是 LSM 用读的复杂度换写的顺序性之后，自己给自己还债的方式。

5

环境场景：引擎之外还有什么

拆掉任何一个外部依赖，前面看到的行为都会变。

「环境属性 = 外在关系 + 依赖 + 失效后果。」
嵌入方进程它是库不是服务：Flink StateBackend、TiKV、MyRocks 把它嵌进自己进程；宿主一退，引擎就没了。
文件系统与 LOCK顺序追加、原子 rename 的能力直接支撑「不可变文件 + 原子换账本」；LOCK 保证同目录一个读写实例。
MANIFEST 与 CURRENTVersionSet 的持久化账本；丢了它，SST 文件还在盘上却不被认识。
块缓存（默认 32MB）读回来的 4KB 块安家在内存里，下次同块直接命中——没有它，热点读要反复碰盘。
WriteOptionssync 与 disableWAL 由调用方声明：改变「崩溃丢多少」的承诺，不改流水线形状。
监控计数器GET_HIT_L0/L1/L2_AND_UP、STALL_MICROS 等：三条流水线的健康度都从计数器读出来。

边界：本页画的是 Leveled 分层的默认形状与 happy path；压实怎么挑文件、写停顿怎么踩刹车，见第 5–6 章与第 3 章。

一页带走

写是追加，读是问答，压实还债。

· 一切皆追加：写追加记录、更新追加更大 seq 的新版本、删除追加墓碑；旧值从不被原地改。

· 三条流水线：写（组包→WAL→memtable）、flush+压实（64MB→L0→归并收敛）、读（SuperVersion→从新到旧，第一次命中即返回）。

· 压实的双重身份：空间回收（4 份痕迹收成 0 份）+ 读优化（该键每层最多一份）。

· 出厂默认值藏着形状：64MB 写缓冲 ×2、L0 攒 4 个触发、7 层、4KB 块、32MB 块缓存。

· 边界与简化：动画中的文件名、占用曲线与并发写为演示值；默认值以 RocksDB 11.13 源码为准，压实选型与写停顿见后续章节。
