数据类型与列：内存里的列长什么样

String、Nullable(String)、LowCardinality(String) 在 SQL 里都能存 region，但在内存里是三种完全不同的结构：offset+chars、null map、字典+下标。类型决定布局，布局决定速度和空间。

表象观察：三种 region 写法，差 10 倍空间

SQL 语义相同，内存布局完全不同。

「类型不是声明，是布局。」
String→offsets+chars→12 GB

Nullable 多 null map；LowCardinality 用字典 + 下标。12 亿行、100 个区域值，LowCardinality 可能只有 String 的十分之一。

复盘自测

一页带走

IDataType 是逻辑类型，IColumn 是物理列；createColumn() 把两者对上。

· IDataType 是逻辑类型，IColumn 是物理列；createColumn() 把两者对上。

· Vector 连续内存；String 是 offsets+chars；Nullable 多 null map。

· LowCardinality 是字典+下标，适合低基数；高基数会反噬。

· Array 是 offset+nested；JSON 是动态路径+typed paths；AggregateFunction 存状态。

· 金额用 Decimal，低基数字符串用 LowCardinality，能不用 Nullable 就不用。
