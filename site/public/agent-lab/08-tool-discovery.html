工具发现与披露漏斗：一条能力怎么走到模型眼前

系统里有 127 项工具，和模型这一轮看见 5 项，是两件事。这页课讲这条能力走过的漏斗：目录 → 检索 → 闸口 → 只追加的轨迹 → 模型工位，以及没命中时的三条退路。动画支持自动运转与分步点击两种模式，部件可以直接点亮，读数和副图始终同相位。

1

表象观察：先把它当黑盒

第一步不拆机器，只看它对外表现出什么行为。

「对事物的观察包括了静态结构 + 动态生命周期 + 环境场景三个方面的内容。」

从外部看，这台机器做的事只有一件：把「系统里有的能力」翻译成「模型这一轮能看见的能力」。请求进来时它并不回答，而是先决定哪些工具定义出现在窗口里；回答得对不对，取决于这一步放进来的是什么。

一次带能力缺口的请求→ 披露漏斗（黑盒）→ 本轮在场 5 个 schema（主产物） 「未找到」回执 + token 账单（副产物）

黑盒观察还能看出两件事：其一，在场数量与目录数量不成比例——127 对 5，压缩比来自宿主策略而不是协议；最省事的写法（把 tools/list 的结果全量注入 system prompt 顶部）会让 5 个 MCP server 的 schema 就吃掉数万 token，200K 窗口里对话还没开始就先占掉近三成。其二，没命中时它会明确说没命中，而不是挑一个看起来像的先用上。第二件事比第一件事更能说明这套机制是否可信。

口诀：先问本轮在场几个，再问系统里一共几个。

2

静态分解：它由什么组成

打开黑盒，沿空间维度拆解。点部件卡片，动画中对应部分会亮成琥珀色。

「它由什么构成？核心方法是分解、分类、结构化——分解需符合 MECE 法则，同层必须粒度一致。」

披露漏斗按功能分成四组九件。先看静态标注图（编号与动画、部件卡三处一致），再点卡片。

读法：① → ⑤ 是主线（能力怎么走到模型眼前），⑥ 是出手，⑦ 是没走到时的出口，⑧ ⑨ 是这本账的两条结论。编号与顶部动画、下方部件卡一一对应。口径：图上所有数字与动画同一份，未展开的多轮并发见「边界与简化」。

供给组 —— 负责「哪些能力被摊开」
在场组 —— 负责「模型这一轮看见什么」
出手组 —— 负责「看见之后能不能安全做」
分支与对账组 —— 负责「没命中怎么办、这趟值不值」

静态分解只回答了「有什么」。一条能力怎么在 4.6 秒里走完漏斗、没命中时又怎么走岔？必须切换到时间维度——下一节。

口诀：目录、尺子、闸口、轨迹、工位——五件把能力送进门，剩下四件管没送成的那一半。

3

动态分析：它如何运转

盯住那块琥珀色的 schema 卡。用动画下方 9 个步骤点逐帧走完一次披露漏斗。

「它如何演变与运作？关注时间轴上的发展规律、行为模式和内部流程。核心方法是流程分析、行为追溯。」

操作：点步骤条圆点（或「下一步」）画面会定格在对应相位；也可以直接点目录里的任意小格，看那一项 schema 单独披露会不会改变本轮结论。建议完整走两遍：第一遍只跟踪那块卡（目录 → 两把尺子 → 闸口 → 轨迹末尾），第二遍同时读右侧模型工位、执行框与副图的三段带。

读法：色带是阶段长度（不是等分时间），刻度单位是相位°；红虚线是缓存失效点，它落在「准入审批之后」而不是「追加 schema 之后」——这个区别就是本页最贵的一句话。口径：本轴与动画 STEPS 同一份数据，阶段区间逐条对应下方表格。

4

动静融合：三段带如何协同出「该在场的在场」

把第 2 节的「结构」和第 3 节的「流程」叠在一起——这才是理解的完成态。

「动静融合的关键是建立映射：将组成部件与操作步骤一一对应，理解各部件如何协同产生外在行为。系统 = 元素 + 连接 + 目标。」

映射表：每个部件在每个阶段里承担什么角色。竖着看是一个阶段的全体协同，横着看是一个部件的完整职责。

部件 ＼ 阶段① 缺口② 检索③④ 出闸入轨迹⑤ 选择⑥⑦ 准入执行⑧⑨ 分支对账
① 127 项目录全量在册被扫描只出 5 项不参与不参与50,597 是账本不是在场
② 检索层读缺口语义 + 分词交候选——无命中即触发 ⑦
③ 闸口—等结果放行 5 条定义候选集—不出闸 = 不假装看见
④ 前缀 + 轨迹前缀钉住不变末尾追加被读取写调用与结果工具集变动 → 缓存全废
⑤ 模型工位声明缺口—第一次看见5 选 1提交调用选不出就退回缺口
⑥ 执行框————审批 · 回写拒绝理由进轨迹
⑨ 准确率牌—————打平是实测结论

读法：先看六次交接各交出什么东西，再看那条虚线回环——执行结果回写进轨迹，才让「下一轮少查一次目录」成为可能。口径：交接顺序即动画相位顺序，未展开多轮并发。

点题一句：「127 项能力、每轮只花 9,675 token，而且缓存还在」这个外在行为，不是任何一个部件的属性，而是「披露策略 × 追加顺序 × 准入边界」整体协同涌现的。三件事少一件就换一种失守：只改披露不改追加顺序（把 schema 回填进前缀），token 省了、缓存废了；只保缓存不管工具集变动，前缀看似稳定、其实每轮都在重排；把「看见」和「能调」混成一件事，检索就成了越权通道——搜索是补说明书，不是开权限。对称设计在另一侧：没命中也要留痕，显式的「未找到」和静默塞一个相近工具，是两种完全不同的可审计性。

口诀：token 是买出来的，判断力不是；前缀钉住，账才算得清。

5

环境场景：它依赖什么才能工作

主体之外，还有一圈支撑系统。

「对事物的认识 = 空间属性 + 时间属性 + 环境属性（外在关系和依赖）。」

读法：先看六个外部系统各供给什么，再看底部三条失效后果——每条都能在第 3 节的某个阶段上找到对应现象。口径：49% → 74%、约 98% 为论文报告，与本页本地实测不同等级。

索引与嵌入服务本地 all-MiniLM-L6-v2 把 127 项压成可检索的向量。拆掉它，检索层只剩名称分词，闸口宽度就得靠人写规则。
宿主披露策略协议不管披露，宿主管：全量注入、只留名称索引、转延迟项 + 检索三条路，只有第三条把「看见」和「能调」分开。
定价与缓存机制稳定前缀的读取成本按公开定价量级约 1/10——但缓存键必须含用户身份与授权范围，否则会把 A 的权限结果喂给 B。
权限与准入系统拦截是工具名粒度的。没有准入，检索出来的 schema 就同时是权限申请单，审批门形同虚设。
发布流程（worktree + PR）运行内生成的插件重启即消失，不能被自动提升为正式能力；造新工具这条退路全靠它兜底。
评估集与轨迹日志「准确率打平」这个负结论能被复现，靠的是同一批任务 + 可比价指标 + 完整轨迹。拆掉它，只能讲省了多少 token 的故事。

动画里的漏斗能转起来，前提是这六个系统在「环境」里就位。拆掉任何一个，外在行为立即消失——尤其是宿主披露策略与发布流程：拆掉前者，「按需披露」退化成一堆检索代码；拆掉后者，Agent 自造的工具会悄悄长成正式能力，把整条审计链断在最贵的那一环。

口诀：漏斗能转，靠的是索引、准入、定价、发布四件事都在场。

6

复盘自测：学习-实践-复盘的闭环

用自己的话能讲清楚，才算真的懂。先答题，再对照解析。

「复盘是把『我当时怎么想的』和『实际怎么走完的』对齐：结论要能复现，数字要能定级——实测、论文报告、A/B 实测是三种不同的分量。」

口诀：讲得清口径，才敢引用数字；分得清实测与报告，才敢写进方案。

一页带走

目录里一百二十七，本轮只放五个；买到的是 token 与延迟，不是判断力。

· 方法：表象（能力翻译机）→ 结构（四组九件）→ 流程（九阶段一轮漏斗）→ 融合（「该在场的在场」是三段带协同涌现的）。

· 结构：127 项目录 + 两把尺子的检索层 + top-5 闸口 + 钉住的前缀与只追加轨迹 + 模型工位与执行框 + 未命中分支与两块对账牌。

· 行为：检索花宿主的算力不花模型的 token；schema 追加到末尾并保持首次位置；工具集一变动，缓存自首个变动处起全废；没命中就显式说没命中。

· 协同：披露策略 × 追加顺序 × 准入边界三件齐了，「127 项能力、每轮只花 9,675 token」才成立；缺任一件，账就变成一笔糊涂账。

· 边界与简化：漏斗按单轮演示，多轮并发检索与批量披露未展开；检索与全量注入的延迟差异未按比例绘制；缓存读取成本 1/10 是公开定价量级示意；未命中分支只演了「三条退路里选一条」的过程，真实系统还要按外部契约是否变化来判该不该自愈。
