TAO 循环：以大模型为变迁引擎的状态机

ReAct 循环转了 847 圈、日志全绿、账单爆了——问题不在 Prompt 怎么写漂亮，在这个循环的状态怎么维护得住。TAO 的本质是一个状态机，只是把代码写的迁移规则换成了模型现场决定。这页课按认知链展开，动画支持自动运转和分步点击两种模式。

① 表象观察→ ② 静态分解→ ③ 动态分析→ ④ 动静融合→ ⑤ 环境场景→ ⑥ 复盘自测

1

表象观察：先把它当黑盒

第一步不拆机器，只看它对外表现出什么行为。

「对事物的观察包括了静态结构 + 动态生命周期 + 环境场景三个方面的内容。」

从外部看，一个执行中的 Agent 做的事只有一件：一句目标进来，一个结果出去；中间是一圈一圈的「想一步、做一步、看一步」。每一圈都可能调用工具、改写状态。至于圈内怎么想、什么时候该停，暂时不用管——先把输入和输出看清楚：

目标 + 上下文（输入）→ TAO 循环（黑盒）→ 任务结果（主产物） 追问 / 中断 / 账单（副产物）

黑盒观察的结论：这是一台把概率性思考编译成可恢复流程的装置——「智能」以 token 计价，工程以状态、事件、闸门计价。带着这个结论，现在打开黑盒。

2

静态分解：它由什么组成

打开黑盒，沿空间维度拆解。点部件卡片，动画中对应部分会亮成琥珀色。

「它由什么构成？核心方法是分解、分类、结构化——分解需符合 MECE 法则，同层必须粒度一致。」

一个最小可用的 TAO Runtime 可按功能分成五组：

循环本体组 —— 负责「一圈怎么走」
状态组 —— 负责「世界被结构化」
出口组 —— 负责「循环怎么停」
治理组 —— 负责「别烧穿、别闯祸」
留痕组 —— 负责「出事能重建」

静态分解只回答了「有什么」。这些部件怎样在时间里配合出一圈循环、又怎样停下来？必须切换到时间维度——下一节。

3

动态分析：它如何运转

盯住那个琥珀色令牌。用动画下方的 9 个步骤点逐帧走完一次任务。

「它如何演变与运作？关注时间轴上的发展规律、行为模式和内部流程。核心方法是流程分析、行为追溯。」

操作：点击动画下方步骤条上的圆点（或「下一步」按钮），画面会定格在对应时刻。建议完整走两遍：第一遍只看令牌绕圈，第二遍同时看右侧六个出口哪个在亮、预算条怎么掉。

两个容易错过、但值得在分步模式里细看的点：① 第二轮的超时是「黄灯」，不是「没执行」——网络超时不代表远端没执行，UNKNOWN 状态要先拿幂等键查外部真实结果，而不是立刻重试；② 预算条每一步都在掉，ControlState 是唯一不能省的状态——没有它，循环停不停全看模型自觉。

4

动静融合：部件如何协同出「可恢复的执行」

把第 2 节的「结构」和第 3 节的「流程」叠在一起——这才是理解的完成态。

「动静融合的关键是建立映射：将组成部件与操作步骤一一对应，理解各部件如何协同产生外在行为。系统 = 元素 + 连接 + 目标。」

映射表：每个部件在每个阶段里承担什么角色。竖着看是一个阶段的全体协同，横着看是一个部件的完整职责。

点题一句：「崩了能接着跑」这个外在行为，不是任何单个部件的属性，而是「状态外置 + 事件追加 + 双账本」整体协同涌现的。朴素 ReAct 把执行权整个交给概率模型，日志全绿也能把钱出两次；把循环翻译成状态、事件、闸门与账本之后，同样一个模型才能安全地跑长任务。对称设计的代价也要说清：事件流只进不出，日志会膨胀——所以压缩必须带 replacement_history 式的完整快照，而不是打一个截断标记。

5

环境场景：它依赖什么才能工作

主体之外，还有一圈支撑系统。

「对事物的认识 = 空间属性 + 时间属性 + 环境属性（外在关系和依赖）。」
模型服务变迁引擎本身。它的概率性、延迟、限流策略，全部透过预算与熔断层被计价管理。
工具与外部系统Action 的真正落点。每个工具自带副作用等级、幂等要求、超时上限的强类型声明。
事件溯源存储追加写的日志与定期快照。恢复 = 加载最近检查点 + 重放增量事件，跟数据库 WAL + Checkpoint 一个道理。
幂等账本记录「外部动作发生过几次」。和流程账本分开记——最凶险的窗口是外部已入账、本地还没来得及写 DONE。
沙箱与审批高风险动作的笼子。沙箱拒绝要不要自动升权重试，是一次明确的策略取舍而非默认补救。
监控与 TraceGeneration / Score 两类传统监控没有的对象。没有它，「为什么这么决定」这个问题无人回答。

动画里的循环能转起来，前提是这六个系统在「环境」里就位。拆掉任何一个，外在行为立即消失——尤其是事件存储和幂等账本：拆掉它们，「崩溃后接着跑」立刻退化成「崩溃后钱出两次」。

6

复盘自测：学习-实践-复盘的闭环

用自己的话能讲清楚，才算真的懂。先答题，再对照解析。

一页带走

模型是引擎，循环才是整车；想、做、看、账，一圈一账。

· 方法：表象（概率思考 → 可恢复流程）→ 结构（五组部件）→ 流程（九阶段）→ 融合（可恢复是涌现属性）。

· 结构：T/A/O + 状态更新、状态库五态、六个出口、预算四件套、事件流。

· 行为：每轮「读状态 → 想 → 做 → 看 → 记账」；超时走黄灯重试；成功标准满足才 Finish。

· 协同：终止权外置 + 事件追加 + 双账本，才让同一个概率模型敢跑长任务。

· 边界与简化：预算按轮次离散步进演示；真实 token / 金额按调用累计，超时与重试的实际耗时未按比例绘制。
