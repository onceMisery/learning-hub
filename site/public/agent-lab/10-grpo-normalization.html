组内归一化与零方差死区：一次 RL 更新到底改变了什么

GRPO 的一步只做四件事：一组采样 → 一个均值 → 一次归一化 → 一次更新。这页课把这条链摊开成一张会动的账本，并钉住那个最反直觉的死角——组内方差为 0 时优势消失、这一步不产生梯度。动画支持自动运转与分步点击两种模式，部件可以直接点亮，读数与副图始终同相位。

1

表象观察：先把它当黑盒

第一步不拆训练框架，只看它对外表现出什么行为——尤其是「不动」的行为。

「当你怀疑『训练没效果』时，先看去是不是所有 rollout 都同分。」——同分说明这一步压根没产生梯度，继续加 step 只会烧采样预算。

从外部看，这台机器做的事只有一件：把「同一个 prompt 下采出来的一组轨迹」翻译成「策略分布的一次位移」。几个现场症状都不是「调参不够」，而是这一步在数学上就没有信号：训了 200 个 step，loss 在降、指标却不动；奖励维度加了五个，效果反而更差；把 batch 开大一点想快，训练当场变味。它们的共同形状是——组内没有差异，就没有优势；没有优势，就没有梯度。

同一 prompt→ G=16 条 rollout（黑盒）→ 组内归一化 · 优势→ 一次策略位移（主产物） 一个 step 的墙钟账（副产物）

黑盒观察还能看出两件事：其一，梯度不是「有奖励」就有——只给终点 0/1 时，一组全 0 或全 1，优势直接消失；其二，「不动」有两种相反的病因——全 0 是任务不可达，全 1 是验证器没区分度，处置完全相反。这两件事就是本页的全部机制线索。

读法：从左到右是一条更新链；琥珀色三段（组均值 / 归一化 / 下一轮）是「组内」发生的事，绿色一段是分离出的正负优势。口径：管线次序与「一组采样、一个均值、一次归一化、一次更新」取自正文第三节；数字 4/16、+4/−12 是该节算例。顺带接上第 05 篇：全 1 那个死角本质是评估缺陷，不是训练缺陷——判据链在参数层同样成立。

口诀：loss 降而指标不动，先去看组内有没有差异，别急着加 step。

2

静态分解：它由什么组成

打开黑盒，沿空间维度拆解。点部件卡片，动画中对应部分会亮成琥珀色。

「它由什么构成？核心方法是分解、分类、结构化——分解需符合 MECE 法则，同层必须粒度一致。」

这台机器按功能分成三组七件：采样组管「喂进去什么、打分打出什么」，归一化组管「一组分数怎么变成优势」，更新与死机组管「优势怎么改分布、什么时候改不动」。

采样组 —— 负责「同一 prompt 下采出可比较的一组」
归一化组 —— 负责「一组分数 → 一条相对好坏」
更新与死机组 —— 负责「优势怎么改分布、何时改不动」

静态分解只回答了「有什么」。同一条均值线，4 通过 12 失败时能分裂出正负优势，16 条全 0 时却什么都分不出来——必须切换到时间维度看它怎么坍缩——下一节。

口诀：一组、一均、一归一、一更新；方差是命门，零方差即死区。

动态分析：它如何运转

盯住 16 条 rollout 与那条均值线。用动画下方 9 个步骤点逐帧走完一次「组内归一化 → 更新 → 死区演示 → 时间账」。

「它如何演变与运作？关注时间轴上的发展规律、行为模式和内部流程。核心方法是流程分析、行为追溯。」

操作：点步骤条圆点（或「下一步」）画面会定格在对应相位。建议走两遍：第一遍跟主链（采样 → 打分 → 归一化 → 正负分离 → 策略位移）；第二遍专看两块分支板如何点亮——470° 全 0 分支、540° 全 1 分支，其余时刻它们灰化。

读法：色带是阶段长度（对数节拍被等距压缩，见「边界与简化」），刻度单位是相位°；注意 470°/540° 两块红色死区段的现象相同（无梯度）、处置相反。口径：本轴与动画 STEPS 同一份数据，阶段区间逐条对应下方表格。

动静融合：七件部件如何协同出「这一步到底改不改得动」

把第 2 节的「结构」和第 3 节的「流程」叠在一起——这才是理解的完成态。

「动静融合的关键是建立映射：将组成部件与操作步骤一一对应，理解各部件如何协同产生外在行为。系统 = 元素 + 连接 + 目标。」

映射表：每个部件在每个阶段里承担什么角色。竖着看是一个阶段的全体协同，横着看是一个部件的完整职责。

部件 ＼ 阶段① 采样② 打分③④ 归一与分离⑤ 位移⑥⑦ 死区⑧⑨ 账与回填
① 一组 rollout并行铺开各交一条提供组内样本被加权全 0 / 全 1 的载体耗时=墙钟来源
② 验证器—给 0/1分数进均值—全 1 = 无区分度CPU 瓶颈位
③ 组均值——零点参照 0.25决定抬/压全同分→均值即分数—
④ 组内方差——归一化的除数 σ缩放优势=0 → 优势消失命门指标
⑤ 优势——+4 / −12加权更新恒为 0 → 无梯度—
⑥ 策略位移被采样——抬升/压低不动→ 下一轮
⑦ 死区板————全 0 补底座 / 全 1 修评估先诊断再加预算

三条 PPO 对照与数值细节必须一起看（正文 3.1 / 第三节）：PPO 多一个 critic——优势 = 折扣回报 − V(s)，重要性比率 ratio = exp(logπ − log μ_old)，再对 min(ratio·A, clip(ratio,1±ε)·A) 取保守值；on-policy 要求采样策略 π 与更新时的 μ 一致，比率 ρ 才等于 1。一旦数值失配就会伪装成「训练不稳」：logprob 微差 → 概率比指数化 → 长前缀累积——4,000 token 各带 1e-3 偏差可累积到 e⁴ ≈ 54.6；而改 batch size 会改变计算归约、破坏 batch invariance，把本该 on-policy 的 RL 变成隐式 off-policy。症状是比率尖峰、大量 token 被裁剪、响应长度突变，随后奖励与熵一起坍塌——处置是「更新之前先比 sampler 与 trainer 的 logprob」，这一步几乎免费。

点题一句：「这一步改不改得动」不是任何一个部件的属性，而是「组内有差异 × 方差不为零 × 优势被加权」三者协同涌现的。三者少一件就换一种失守：只打分不归一，正负不可比；方差为 0 还硬更新，烧预算空转；把全 1 当全 0 去补底座，方向彻底反了。加奖励维度同理——每一维都要先能在少量 rollout 里产生组内差异，否则它只是噪声，或更糟：一个恒为 0 的维度把优势整体拽偏。

口诀：能算出差异才谈更新；先组内差异、再方差、最后预算——顺序反了就是烧 GPU。

5

环境场景：它依赖什么才能工作

主体之外，还有一圈支撑系统与前置判据。

「对事物的认识 = 空间属性 + 时间属性 + 环境属性（外在关系和依赖）。」
判据先于方法（pass@k）pass@k = 1−(1−p)^k、pass^k = p^k。p=0.6、k=5 时一个升到 99.0%、一个掉到 7.8%：近零说明正确策略不在分布里，硬上 RL 无事可放大，该补底座（Mid-training / RAG）。顺序：先排除不改权重 → 测 pass@k → 立协议 → 才上 RL。
验证器 / 评估质量全 1 是评估缺陷不是训练缺陷。隐藏测试必须模型改不了、写不了；每加一维奖励，先确认它能在少量 rollout 里产生组内差异，否则只是噪声或被钻空子的口子。
采样并发与验证 worker复杂 Agent rollout 几十轮工具调用，16 条并行的墙钟由最慢那条决定。当验证器是 CPU 程序（跑测试 / 解析 / schema）时，瓶颈常在验证 worker 数量，不在 GPU——扩 worker 有时比调学习率管用。
PPO 的 critic 与 on-policyPPO 用价值网络 V(s) 估优势，多一套 critic 训练负担；GRPO 用组内归一化替代它。on-policy 要求 μ=π 才有 ρ=1，任何「采样与训练不同步」都会退化成 off-policy。
数值内核一致性vLLM/SGLang 与 FSDP/Megatron 即使权重相同，也会因精度、归约顺序、并行布局、batch size、KV cache、fused kernel 给出不同 logprob。四件可执行事：先比 logprob、同步模板与 revision、存下 behavior logprob、对齐精度或显式 off-policy 修正并限 staleness。
课程与部分奖励全 0 的可执行出口：改课程（把任务拆到 p>0 的粒度）或给部分奖励（R = O + βΦ，Φ 由确定性规则逐动作计算，两路各自归一化再合并）。但 R=O+βΦ 那组报告数字（违规 3.71→0.66、迭代 7.0→4.4）是论文 / 外部实现口径（书中实验 8-16 本地未跑），先测信号可达性再决定是否加维。

样本效率环境：RL 贵，贵在「每次昂贵环境交互换来多少有效参数更新」。一条长度 T 的 on-policy RL 轨迹只有终点一个 0/1；换成 on-policy 蒸馏可把「1 个标量」变成「约 T 组逐 token 监督」，数学任务上所需步数约为纯 RL 的 1/10——但它同样吃 3.1 的数值失配前提。口径提醒：ReTool 的 RL 训练时间是 SFT 的 200 倍以上（9 天 vs 1 小时）、SimpleVLA-RL 报告 17.3%→91.7%——这些是论文 / 他人报告（书中实验 8-13 / 8-14 / 8-16 本地未跑），只能作量级参照，不能当本页或你的实测结论。

口诀：先测 pass@k 再谈方法；先比 logprob 再更新；先扩 worker 再调 lr。

6

复盘自测：学习-实践-复盘的闭环

用自己的话能讲清楚，才算真的懂。先答题，再对照解析。

「复盘是把『我当时怎么想的』和『实际怎么走完的』对齐：哪条机制对应哪种失败，答不出对应关系的，下次预算就烧在那条上。」

口诀：讲得清「全 0 与全 1 为何处置相反」，才敢怀疑评估；讲得清「为何先看方差」，才敢按下加 step 的按钮。

一页带走

一组采样一个均值，一次归一一次更新；方差为零优势即灭，全零补底座全一修评估。

· 方法：表象（改不改得动的黑盒）→ 结构（三组七件：rollout/验证器/均值/方差/优势/位移/死区）→ 流程（九相位一次更新）→ 融合（「改得动」是「组内差异 × 方差非零 × 优势加权」协同涌现的）。

· 结构：GRPO 一步四件事——同一 prompt 采 G=16 → 验证器给 0/1 → 组内归一化（减均值 0.25、除 σ≈0.433）得优势 → 加权更新 π。PPO 多一个 critic：优势 = 折扣回报 − V(s)，on-policy 要求 μ=π、ρ=1。

· 行为：混合结果 4 通过 → 正优势 +1.73（4 条）/ 负优势 −0.58（12 条）→ 有梯度；全 0 → 方差 0、优势消失、无梯度 → 补 Mid-training 或改课程 / 部分奖励；全 1 → 同样方差 0、无梯度，但病因是验证器没区分度 → 先修评估。判据链先测 pass@k=1−(1−p)^k、pass^k=p^k（p=0.6、k=5 → 99.0% / 7.8%）。

· 协同与账：诊断顺序「先看组内有没有差异 → 再看方差 → 最后才加预算」；一个 step 时间账 = 墙钟（最慢 rollout ≈2,000s）+ 梯度（≈600s）≈2,600s≈43 分钟、100 step≈72 小时；数值失配链 logprob 微差→概率比指数化→长前缀累积（4,000×1e-3→e⁴≈54.6），改 batch size 破坏 batch invariance 会退化为隐式 off-policy。

· 边界与简化：本页是单步演示，真实训练是多个 step 的累积；rollout 长度与耗时是示意分布，真实取决于任务轮数与并发度；策略分布曲线的位移是教学示意，不代表真实参数变化；相位时间轴把阶段等距压缩进 0–720°，未按真实秒数比例。数字口径：R=O+βΦ 那组（3.71→0.66、7.0→4.4）、17.3%→91.7%、200 倍 / 9 天 vs 1 小时 属论文 / 他人报告（书中实验 8-11 / 8-13 / 8-14 / 8-16 本地未跑），只能作量级参照，不写成实测；4/16、+1.73/−0.58、2,000s/600s/43 分钟/72 小时、54.6 是正文第三、四节给的量级与算例，pass@k/pass^k 为公式逐帧计算。
