事件消费的三种策略与安全点：世界推过来时，在哪儿切进去

模型一次生成是一段流式、不可分割的推理，而事件随时会到。这页课讲事件进来之后的处置规则：安全点在哪、紧急与常规各走哪条策略、被打断的工具怎么在轨迹里收口。动画支持自动运转与分步点击两种模式，部件可以直接点亮，读数和副图始终同相位。

1

表象观察：先把它当黑盒

第一步不拆机器，只看它对外表现出什么行为。

「回合制是接口约定，不是环境的性质。」——你和 Agent「轮流说话」是模型与接口之间的约定，环境本身从不等待。

从外部看，这台机器做的事只有一件：把「世界任意时刻推过来的事件」翻译成「轨迹里合法的、按安全点消费的一条条消息」。四种现场症状都指向「时间不对」而不是「模型不够聪明」：用户中途改口时 Agent 正卡在第三次工具调用上；任务执行到一半来了要求停止的邮件；语音助手在手机号报到一半时抢答；屏幕上第 13 步弹了窗，Agent 还按旧截图算坐标。

任意时刻到达的事件→ 安全点闸口（黑盒）→ 轨迹新增合法条目（主产物） 队列积压计数 + 取消回执（副产物）

黑盒观察还能看出两件事：其一，不是所有事件都能立即被处理——常规事件会被「晾」在队列里等到某个确定的点；其二，被打断的工具不会凭空消失——轨迹里会出现一条写明「结果尚未取得」的占位条目。这两件事就是本页的全部机制线索。

读法：横轴是对数时间轴；本页动画只演最上面那条「秒—天」带（事件驱动与打断），语音与 Computer Use 的时序不在本页展开。口径：四条带子的时间范围与「谁在催」取自正文第一节的四类任务对照表；顺带接上第 8 章的「事件触发工具」——那章讲这类工具长什么样，本页讲事件进来之后的处置规则。

口诀：先问这件事的真实节奏是多少毫秒，再问事件该在哪一步被消费。

2

静态分解：它由什么组成

打开黑盒，沿空间维度拆解。点部件卡片，动画中对应部分会亮成琥珀色。

「它由什么构成？核心方法是分解、分类、结构化——分解需符合 MECE 法则，同层必须粒度一致。」

这台机器按功能分成三组七件：供给组管「事件长什么样、能不能切进去」，策略组管「切进去之后走哪条路」，记账组管「一切必须在轨迹里留痕」。

供给组 —— 负责「事件能不能被合法地送进门」
策略组 —— 负责「紧急度不同，处置完全不同」
记账组 —— 负责「一切必须在轨迹里留痕」

静态分解只回答了「有什么」。两条事件同时落到一条正在执行工具调用的推理流上，260° 与 500° 处发生了什么不同的事？必须切换到时间维度——下一节。

口诀：信封、路由、闸口三件管进得去；取消、队列、并行三件管怎么走；轨迹一件管留痕。

3

动态分析：它如何运转

盯住两张下落的卡片。用动画下方 8 个步骤点逐帧走完一次「改口 + 紧急中断」的事件处置。

「它如何演变与运作？关注时间轴上的发展规律、行为模式和内部流程。核心方法是流程分析、行为追溯。」

操作：点步骤条圆点（或「下一步」）画面会定格在对应相位。建议完整走两遍：第一遍只跟踪紧急卡片 E2 的下落路线（到达 → 触发取消 → 落进取消分支）；第二遍同时读三个分支面板的点亮次序与底部轨迹条的增行——120° 到 260° 之间它一条都不该多。

读法：色带是阶段长度（对数节拍被等距压缩，见「边界与简化」），刻度单位是相位°；注意 260° 的取消不等安全点——它是唯一允许掀掉推理段的口子。口径：本轴与动画 STEPS 同一份数据，阶段区间逐条对应下方表格。

阶段相位谁在场定格读数这一步在干什么
① 推理段流式中0°–120°主推理流 · 工具 A积压 0/4 · 轨迹 1 条模型一次生成是一段流式的不可分割推理；事件可达不可切，不能在任意字节处切进去

④ 取消式四步280°–400°取消分支 · 轨迹轨迹 +队列原文停生成与同步工具 → 清队列 → 清出的队列与紧急事件一起追加轨迹 → 重新调用；清队 ≠ 丢弃

⑥ 安全点批量注入500°队列分支 · 安全点积压 0/4任一 tool.result 返回 = 天然安全点：队列一次性批量追加，E1 不单独占一轮
⑦ 占位符补写560°轨迹条+1 占位条目「发起过、结果未取得」写进轨迹；已落账的 tool result 绝不重发——复制会让模型以为查了两遍且一致，从此不再复查
⑧ 重新调用 · 闭环640°–720°模型工位轨迹全合法重规划（先取消，取消成功后才改地址）；自检三种非法形态：缺配对结果 / 回灌半截思考 / 清掉的队列没落轨迹

走查例的四个细节，每个都对应一种故障（正文 3.5 节）：

细节正确做法做错时的故障
多条事件同时到达紧急与常规一起批量注入，不是一人一轮逐条注入 = 每处理一条就重新规划一次，成本与漂移翻倍
未完成工具的占位符明写「尚未取得结果」+ 下一步该等还是该做写成「已发起」，模型下一步就开始念取消成功的回执——编造就是这么来的
已落账的 tool result不重发复制一份 → 模型认为查了两遍且一致，从此不再复查
优先级的表达位置写在 context.priority 字段里，由策略消费靠「放消息末尾最后一条」表达优先级——下一轮顺序一变，优先级就变了

两个值得在分步模式里细看的点：① 第 ③ 步取消不等安全点——「取消点必须是工具或推理能安全收尾的地方」约束的是「在哪取消副作用」，不是「在哪消费事件」，紧急通道是掀掉推理段而不是插进推理段；② 第 ⑥ 步批量注入发生在 tool.result 返回处而不是紧急事件到达处——常规事件从 120° 起就在队列里，470° 之前轨迹一条都不能多。

口诀：0° 切不进，120° 入队，260° 掀桌，500° 批量，560° 补占位，640° 重新想。

4

动静融合：七个部件如何协同出「打断之后轨迹仍然合法」

把第 2 节的「结构」和第 3 节的「流程」叠在一起——这才是理解的完成态。

「动静融合的关键是建立映射：将组成部件与操作步骤一一对应，理解各部件如何协同产生外在行为。系统 = 元素 + 连接 + 目标。」

映射表：每个部件在每个阶段里承担什么角色。竖着看是一个阶段的全体协同，横着看是一个部件的完整职责。

部件 ＼ 阶段① 推理段中② 常规进场③④ 紧急与取消⑤ 旁路⑥⑦ 安全点与占位⑧ 重调用
① 结构化事件在途四字段可路由priority 定生死载荷自带上下文原文进轨迹被消费过的字段不再出现
② 事件路由器分类不切流判为常规判为紧急判为旁路查询—只分类不决策
③ 安全点闸口关：不可切入放行到队列紧急绕行不等主轨迹开：结果返回处消费推理段结束
④ 取消式——四步执行—触发占位符重新调用
⑤ 队列式—入队不打断队列被清出—批量注入清空待新事件
⑥ 并行式——不受牵连另起会话回写带 lane归因可读
⑦ 轨迹条[1] 已发起未落账不变队列原文落账旁路结论落账占位符落账全合法才发

兼容五规则（第四节的「没有原生异步时」）是⑦的施工图：及时记录已完成的 assistant 消息与工具调用项；工具完成才记 result（半截不记）；执行中被打断补占位符 + 追加打断事件 + 重新调用；无原生 steering 时不能假定半截输出或隐藏推理可以任意回灌；非打断事件入队、批量注入。三条会被当场拒掉的非法轨迹：有 tool_calls 缺配对 tool 结果（删 assistant 等于没发起过，而外部副作用已发生——只能补占位）；回灌被截断的思考（思考签名绑的是产生它时的前缀，轻则静默丢弃重则 400）；清掉的队列没落轨迹（模型看到「什么都没发生」，实际 cancel 已发出——它要么重发取消，要么以为取消过）。

点题一句：「打断之后轨迹仍然合法」这个外在行为，不是任何一个部件的属性，而是「安全点定义 × 清队落轨迹 × 占位符明写」三者协同涌现的。三件事少一件就换一种失守：只停生成不清轨迹，模型的世界和你的世界分叉；只清轨迹不写占位，模型编造工具结果；只有并行不标身份，归因错到检索层头上。取消改变的是执行，不改变事实记录。

口诀：token 会骗人，轨迹不会——轨迹缺一条，世界就分叉。

5

环境场景：它依赖什么才能工作

主体之外，还有一圈支撑系统。

「对事物的认识 = 空间属性 + 时间属性 + 环境属性（外在关系和依赖）。」
实时通道（推 vs 轮询）内置渠道是推送（Gateway 直接收到）；外部事件源（新邮件、第三方回调）只能等下一个周期。先把「这件事能不能被推」问清楚，再设计 Agent 的作息表——顺序反了就是一堆轮询加「感觉像主动」的话术。
事件路由器用规则（来源 + 关键词 + 优先级字段）或一次轻量 LLM 分类判紧急。注意是路由器不是决策者：判错顶多早打断一次，不会改变任务本身。
厂商续接协议reasoning 状态按厂商协议保留，不要自己拼接不可见思考；思考签名绑的是产生它时的前缀，前缀一换就失效。
状态栏与队列计数只把最后一条事件回给模型，前几条它不知道存在。状态栏常驻 [未处理事件 2/4] 并在消息末尾汇总——看不见的状态等于没有状态。
工具层发起/完成解耦initiate_phone_call 立即返回任务 ID 与初始状态，进展通过 phone_call_connected / phone_call_ended 事件通知。工具自己异步，事件循环才有东西可分派。
取消令牌与执行边界拿到取消令牌，别硬等返回；但已发出外部请求、结果未落账处不能取消——调用报错 ≠ 外部操作失败，那会留下悬挂副作用。

原生异步（新一代模型 API 已提供）把这一页的规则变成两个能力：异步工具调用（发起与取结果分离，先去做不依赖结果的工作）与回合中途引导（同一任务内改约束）。三条验收随之而来：结果归属与未完成状态是否清楚；「修改计划」不等于「停止执行」，更不等于「撤销已发生的动作」；多条更新能否同时遵守（预算改了、人数也改了，两个都要用）。这条线要划清：用了 asyncio 不等于模型具备原生异步能力——一半的「异步 Agent」项目，异步只在 IO 层，推理仍按轮次串行。

口诀：先问能不能被推，再谈 Agent 的作息表；异步写在外层还是模型里，决定你要背几页兼容规则。

6

复盘自测：学习-实践-复盘的闭环

用自己的话能讲清楚，才算真的懂。先答题，再对照解析。

「复盘是把『我当时怎么想的』和『实际怎么走完的』对齐：哪条规则对应哪种故障，答不出对应关系的，下次故障就出在那条规则上。」

口诀：讲得清「清队为什么不是丢弃」，才敢上打断；讲得清「旁路为什么必须带身份」，才敢开并行。

一页带走

推理段切不进，紧急有旁路门；清队不是丢弃，旁路要带身份。

· 方法：表象（事件翻译机）→ 结构（三组七件）→ 流程（八相位一次处置）→ 融合（「打断后轨迹仍合法」是三者协同涌现的）。

· 结构：结构化事件四字段（source/channel/content/context）+ 两档事件名 + 安全点闸口（推理段结束 / 工具返回 / 消息边界）+ 三种消费策略 + 只追加的轨迹条。

· 行为：取消式四步（停生成 → 清队列 → 队列与紧急事件一起入轨迹 → 重新调用）；队列式在任一 tool.result 返回处批量注入；并行式另起会话并显式标 lane:"parallel"；未完成工具补占位符「结果尚未取得」。

· 协同：兼容五规则维持轨迹合法性；三种非法轨迹（缺配对结果 / 回灌半截思考 / 清掉的队列没落轨迹）各对应一次真实失败；原生异步两条能力 + 三条验收（改计划 ≠ 停止执行 ≠ 撤销已发生动作）。

· 边界与简化：事件时序被等距压缩进 0–720° 相位，未按真实延迟比例绘制；只演 4 条事件中的 2 条与三种策略的组合，多轮抢占与恢复未展开；占位符文案「工具正在后台执行，请优先处理新事件」是兼容规则里的示意写法，落点要求只有一条——明写「结果尚未取得」；本页不演示语音（10毫秒—1秒）与 Computer Use（亚秒—秒）的时序，它们的时间尺度只出现在第 1 节刻度带。
