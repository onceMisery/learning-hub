评估闭环：把「好不好」变成可验证的工程问题

日志四行全是 Success(200)，用户却在投诉未经授权取消了订单——Agent 的故障大多是认知故障，不是运行故障。测试是刹车，管死活；评估是仪表盘，管好坏。这页课把最小闭环搬上动画：一次点踩怎样沿六个站点走回线上，动画支持自动运转和分步点击两种模式。

① 表象观察→ ② 静态分解→ ③ 动态分析→ ④ 动静融合→ ⑤ 环境场景→ ⑥ 复盘自测
速度1× 演示速度 ≈ 1 个闭环 / 6.4 秒
自动运转模式 点下方步骤点可切换到分步演示，随你点击定格。
1

表象观察：先把它当黑盒

第一步不拆机器，只看它对外表现出什么行为。

「对事物的观察包括了静态结构 + 动态生命周期 + 环境场景三个方面的内容。」—— 人月聊IT · 思维系列

从外部看，评估系统做的事只有一件：把一次线上的不满意，变成一条再也跑不掉的测试。它不直接让 Agent 变聪明，它保证每一次「优化」都是可验证的改进而不是改动。输入是线上信号与 trace，输出是版本、阈值与回归报告。

线上信号（点踩 / 纠正 / 异常）→ 评估闭环（黑盒）→ 回归测试集（主产物） 指标三组 / 灰度报告（副产物）

黑盒观察的结论：这是一台把「软体验」变成「硬证据」的装置——满意度是软的，测试集和指标是硬的；软的只能定性，硬的才能进门禁。带着这个结论，现在打开黑盒。

2

静态分解：它由什么组成

打开黑盒，沿空间维度拆解。点部件卡片，动画中对应部分会亮成琥珀色。

「它由什么构成？核心方法是分解、分类、结构化——分解需符合 MECE 法则，同层必须粒度一致。」—— 人月聊IT · 思维系列

评估闭环可按功能分成五组：

指标组 —— 负责「什么叫好」
判分组 —— 负责「这次算好还是坏」
裁判组 —— 负责「语义化评估」
闭环组 —— 负责「一个坑只踩一次」
回流组 —— 负责「活水进测试集」

静态分解只回答了「有什么」。一次点踩怎样沿闭环走回线上、在哪一步被拦下？必须切换到时间维度——下一节。

3

动态分析：它如何运转

盯住那个琥珀色令牌。用动画下方的 8 个步骤点逐帧走完一次完整闭环。

「它如何演变与运作？关注时间轴上的发展规律、行为模式和内部流程。核心方法是流程分析、行为追溯。」—— 人月聊IT · 思维系列

操作：点击动画下方步骤条上的圆点（或「下一步」按钮），画面会定格在对应时刻。建议完整走两遍：第一遍只看令牌走哪个站点，第二遍同时看中央六问链和右侧双平面判分台。

阶段时刻站点关键面板这一步在干什么
① 线上运行0°–70°运行中埋点亮Trace 落盘：Generation 带 model / prompt 版本，Score 挂质量信号
② 采集反馈70°–200°信号入队九信号用户点踩——最便宜的标注信号，赶在输入到达后立刻打标
③ 定位归因200°–340°归因六问链 + 双平面六问定位断点；终态对但轨迹违规 → 判失败，不写「标准答案」写「禁止集合」
④ 修复340°–460°打补丁patch 纪律滚动 patch：扫描矛盾、补全新陷阱、升版本号；原样重跑不算重试
⑤ 用例入库460°–580°进测试集快照三件输入快照 + 参考轨迹 + 禁止集合 + Prompt 版本；任一条改一个字段，数据集版本号就变
⑥ 回归测试580°–660°跑回归历史成功集曾成功的用例变差即打回；门禁三态：先判方向再判显著
⑦ 灰度与再评估660°–700°影子转正三组指标约百次不劣于线上才转正；汇报要「目标 +8%、护栏持平、纠正率 −12%」三个数一起说
⑧ 回到线上700°–720°闭环计数器 +1同一个坑只踩一次——回流最重要的价值

两个容易错过、但值得在分步模式里细看的点：① 第 ③ 阶段六问链走到第二问就断了——槽位没抽出 budget_max，后面四环只是在一个空约束下跑，「系统全绿」与「决策正确」是两个世界；② 第 ⑥ 阶段回归用的不是「新用例集」而是历史成功集 + 新用例——只有曾成功的变差被打回，才发现「修一个坑挖一个新坑」。

4

动静融合：部件如何协同出「可信的改进」

把第 2 节的「结构」和第 3 节的「流程」叠在一起——这才是理解的完成态。

「动静融合的关键是建立映射：将组成部件与操作步骤一一对应，理解各部件如何协同产生外在行为。系统 = 元素 + 连接 + 目标。」—— 人月聊IT · 思维系列

映射表：每个部件在每个阶段里承担什么角色。竖着看是一个阶段的全体协同，横着看是一个部件的完整职责。

部件 ＼ 阶段① 运行② 采集③ 归因④ 修复⑤ 入库⑥ 回归⑦ 灰度
三层指标被采集负向信号定校准点—写进口径三组并看放行依据
双平面判分轨迹留痕—终态×轨迹修什么有据定义 expected判定依据—
Judge 裁判异步打分异常聚类语义归因校验补丁生成参考轨迹批量评估影子比对
六站点闭环起点信号入队断点定位滚动 patch快照入库门禁三态转正
回流九信号—强信号优先聚类输入—活水来源回归权重—
护栏 + 人审红线布防—违规判定两保险之一禁止集合阻断维度不许自主改的清单

点题一句：「同一个坑只踩一次」这个外在行为，不是任何一个部件的属性，而是「信号 + 归因 + 快照 + 门禁」整体协同涌现的。其中有两个对称设计值得点名：双平面打分让「蒙对」无处遁形（终态与轨迹互相制衡）；护栏指标与人工审批让「刷分」无处下手（核心涨的同时关键指标不得明显恶化）。代价同样清晰：回流会带来噪声，所以只有强负反馈与异常样本优先入库；自动化的步子越大，越需要先回答「怎么算好」。

5

环境场景：它依赖什么才能工作

主体之外，还有一圈支撑系统。

「对事物的认识 = 空间属性 + 时间属性 + 环境属性（外在关系和依赖）。」—— 人月聊IT · 思维系列
埋点与 TraceGeneration（model / promptName / promptVersion / usage / cost）与 Score 两个传统监控没有的对象。没有它，「这决策是谁在哪版指令下做的」无人回答。
录放与 CI事故卡带逐轮落盘，CI 零网络零随机回放。卡带耗尽必须抛错提示重录，绝不给虚假绿灯。
分流实验平台按用户或会话分桶（多轮 Agent 按请求分流根本测不出来）；影子模式让新版本旁观运行不产生副作用。
模型服务裁判与被测异源；temperature=0 也不等于完全确定，所以要做统计检验，不拿两个平均分比大小。
业务规则库评审规则进 Git，策略即代码。安全要的是清晰、可控、可审计，不是连自己都解释不清的模型风险分。
人审通道System Prompt、工具权限、安全策略、资金操作的变更，不许 Agent 自主改——两道保险之一。

动画里的闭环能转起来，前提是这六个系统在「环境」里就位。拆掉任何一个，外在行为立即消失——尤其是埋点与录放：拆掉它们，「线上到底发生了什么」立刻退化成叙事态的一面之词。

6

复盘自测：学习-实践-复盘的闭环

用自己的话能讲清楚，才算真的懂。先答题，再对照解析。

一页带走

测试是刹车，评估是仪表盘；绿灯只证明系统活着，不证明 Agent 做对了。

· 方法：表象（体验翻译 brittleness）→ 结构（五组部件）→ 流程（八阶段）→ 融合（可信改进是涌现属性）。

· 结构：三层指标 + 双平面判分 + Judge + 六站点闭环 + 回流九信号。

· 行为：点踩入队 → 六问定位 → 滚动 patch → 快照入库 → 历史成功集回归 → 影子灰度 → 三组指标并看。

· 协同：双平面让「蒙对」无处遁形，护栏 + 人审让「刷分」无处下手；同一个坑只踩一次。
