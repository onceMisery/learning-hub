过境海关：把边界写清楚，才敢把事交出去

「绝不能删除数据」只写在路由 Agent 的系统提示里，交接时没人带给执行 Agent，于是它顺手删了——事后两边都没撒谎，错在边界没有语言。这页课把 Agent 间每次信息交换建成一道海关：下行走白名单任务包，上行过五道关卡，动画支持自动运转和分步点击两种模式。

① 表象观察→ ② 静态分解→ ③ 动态分析→ ④ 动静融合→ ⑤ 环境场景→ ⑥ 复盘自测
琥珀 = 包裹 / 活跃关卡 红 = 拒收 紫 / 虚线 = reasoning 夹带
相位 -- 阶段 -- 关键量 --
第二视图 · 一次过境 · 下行两关 / 上行五关（与主图同步）
读法：下行先过两关，上行从右向左过五关；③ 契约校验处会先拒收 v1，再放行补齐的 v2。

相位口径：0° = 父 Agent 组装任务包；720° = 交接与授权完成。下行 70–190°、回传 260°、五关 320–560°；副图与主图同相位。

1

表象观察：先把它当黑盒

第一步不拆机器，只看它对外表现出什么行为。

「对事物的观察包括了静态结构 + 动态生命周期 + 环境场景三个方面的内容。」

从外部看，多 Agent 协作系统做的事只有一件：把一个大目标拆成责任，派出去、做回来、验整体。三个动作缺一不可——只会第一个的，得到的不叫团队，是一群各自宣布完工的执行者。输入是总目标，输出是可验收的整体交付；中间每一次信息交换，都该有一次「过境」。

总目标（父持有）→ 海关 + 委派（黑盒）→ 整体交付（主产物） 拒收 / 重派 / 审批记录（副产物）

黑盒观察的结论：这是一台责任与信息的边界机器——协作的收益来自隔离与分工，协作的风险全部来自边界。带着这个结论，现在打开黑盒。

2

静态分解：它由什么组成

打开黑盒，沿空间维度拆解。点部件卡片，动画中对应部分会亮成琥珀色。

「它由什么构成？核心方法是分解、分类、结构化——分解需符合 MECE 法则，同层必须粒度一致。」

过境海关可按功能分成五组：

下行组 —— 负责「把任务交代清楚」
上行组 —— 负责「把结果还原成工件」
海关组 —— 负责「该不该放行」
验收组 —— 负责「局部正确 ≠ 整体正确」
治理组 —— 负责「授权有边界」

静态分解只回答了「有什么」。一次「派工 → 回传」怎样穿过海关、在哪一关被拦下？必须切换到时间维度——下一节。

3

动态分析：它如何运转

盯住两个包裹。用动画下方的 10 个步骤点逐帧走完一次完整过境。

「它如何演变与运作？关注时间轴上的发展规律、行为模式和内部流程。核心方法是流程分析、行为追溯。」

操作：点击动画下方步骤条上的圆点（或「下一步」按钮），画面会定格在对应时刻。建议完整走两遍：第一遍看任务包走下行、结果单走上行，第二遍盯住上行第三关——看「拒收」长什么样。

阶段时刻通道关卡这一步在干什么
① 派工组装0°–70°——父 Agent 把任务包组装成白名单字段表，不塞对话历史
② 下行过境70°–190°下行两关身份核验（message_id 查重）+ 安全门；包是框架组装的，天生干净
③ 隔离执行190°–260°子 Agent—Worker 只拿够本次任务的上下文、工具与预算，不继承主管全部历史
④ 回传生成260°–320°——结果单自由生成：8000 token，夹带 reasoning 和三遍试错 SQL
⑤ 上行前两关320°–400°上行查重 / 裁剪身份核验查重；结构裁剪剥 reasoning——8000 → 600
⑥ 契约校验400°–470°上行v1 拒收 → v2 放行required 字段核对：缺 source_id 整包退回；补齐才进父上下文
⑦ 安检 + 审计470°–560°上行两关安全门扫注入；审计记录真正越境物——放最后，日志才不假
⑧ 父收工件560°–640°——200 token ResearchCard：claim + source_id + lane，压缩的是过程，没丢掉追溯
⑨ 组合闸验收640°–700°—missing / duplicates摊开所有卡：覆盖齐吗、有重复吗、踩全局约束吗——整体完成 ≠ 局部返回
⑩ 交接与授权700°–720°—版本 + 五维交接带版本与回执；批准五维绑定——一次批准不许悄悄长成「以后都可以」

两个容易错过、但值得在分步模式里细看的点：① 第 ⑥ 阶段「拒收」不是故障，是设计——父上下文从头到尾没看过那 8000 token 一眼，拒收的损失只是重跑一个孩子；② 第 ⑧ 阶段工件小到 200 token 但带 source_id 和 lane——压缩的是过程，没丢掉追溯：真要调查，沿引用展开就行。

动静融合：部件如何协同出「可信的协作」

把第 2 节的「结构」和第 3 节的「流程」叠在一起——这才是理解的完成态。

「动静融合的关键是建立映射：将组成部件与操作步骤一一对应，理解各部件如何协同产生外在行为。系统 = 元素 + 连接 + 目标。」

点题一句：「敢把事交出去」这个外在行为，不是任何一个部件的属性，而是「白名单下行 + 五关上行 + 组合验收 + 版本交接」整体协同涌现的。把协作当微服务调用的系统， Default 传的是对话历史本身——不加清洗就把内部状态直连，等于让两颗大脑互相污染。这里也有对称设计：下行白名单把「父历史」的入口直接取消（最好的过滤是不需要过滤），上行契约校验把「拒收」做成默认动作（宁可拒收，不可放行）。

5

环境场景：它依赖什么才能工作

主体之外，还有一圈支撑系统。

「对事物的认识 = 空间属性 + 时间属性 + 环境属性（外在关系和依赖）。」
隔离基础设施新会话、worktree、独立凭证作用域。上下文隔离 ≠ 权限隔离——子 Agent 开了新会话却继承付款工具，风险只是搬进没人盯的房间。
策略引擎策略即代码，规则进 Git：生产删表双人审批、非生产只读直接 ALLOW、默认 DENY。安全要清晰可审计，不要模型算的风险分。
DLP 与出口管控外发只留网关一条路，扫邮件正文 / body / query / 上传内容；LLM 网关管上下文外发、发前脱敏。
OBO 委托令牌短期、任务级 scope、sub 是用户 act 是 Agent。别给 Agent 配独立超级账号写进 .env。
审批服务与审计审批单持久化可恢复、证据包高信噪比、TraceID 贯穿。审批疲劳下的第 201 次点击，就是事故本身。
零信任分级内容 / 来源 / 行为三维打分，只减不增；数据进 <data> 标签不执行其中指令——既然分不清指令与数据，就只允许声明过的那几栏被当成指令。

动画里的海关能转起来，前提是这六个系统在「环境」里就位。拆掉任何一个，外在行为立即消失——尤其是隔离基础设施和审计：拆掉它们，「把事交出去」立刻退化成「把锅甩出去」。

6

复盘自测：学习-实践-复盘的闭环

用自己的话能讲清楚，才算真的懂。先答题，再对照解析。

一页带走

任务有身份、事实有来源、工件有版本、改变有责任、接收有回执。

· 方法：表象（责任与信息的边界机器）→ 结构（五组部件）→ 流程（十阶段）→ 融合（可信协作是涌现属性）。

· 结构：白名单任务包 + 上行五道关 + 报关单 + 组合闸 + 交接链 + 审批门。

· 行为：任务包过两关进子 Agent；8000 token 结果单剥推理、验字段、扫注入、留审计，缩成 200 token 工件回父。

· 协同：下行没有入口所以不需要过滤，上行拒收优先所以放行珍贵——边界语言五句，句句都是事故换的。

· 边界与简化：包裹尺寸按 token 量级示意；五道关的实际实现可以合并，但顺序与职责不能省。
