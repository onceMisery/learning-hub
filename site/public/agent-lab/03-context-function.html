上下文管理：把「模型看见什么」做成一个函数

模型的全部世界观，就是这一次喂给它的那块上下文。Context 是仓库，Window 是工作台——仓库里堆多少不算数，台面上摆着哪几样才算。这页课把装配过程做成五段流水线，并让「注意力曲线」直接可见，动画支持自动运转和分步点击两种模式。

① 表象观察→ ② 静态分解→ ③ 动态分析→ ④ 动静融合→ ⑤ 环境场景→ ⑥ 复盘自测
速度1× 演示速度 ≈ 1 轮装配 / 6.4 秒
自动运转模式 点下方步骤点可切换到分步演示，随你点击定格。
1

表象观察：先把它当黑盒

第一步不拆机器，只看它对外表现出什么行为。

「对事物的观察包括了静态结构 + 动态生命周期 + 环境场景三个方面的内容。」—— 人月聊IT · 思维系列

从外部看，上下文管理做的事只有一件：每一次模型调用前，把「这块窗口该装什么」重新决定一遍。它不产生智能，它决定智能的边界——窗口里没有的事实，对模型而言不是「暂时想不起来」，是压根不存在。

Context 仓库（全部信息空间）→ f 装配（黑盒）→ Window 可见工作集（主产物） 压缩痕迹 / 索引句柄（副产物）

黑盒观察的结论：这是一台注意力预算分配装置——仓库无限、窗口有限、注意力不均，工程就是在「有限窗口 × 有损压缩 × 无限信息」这对矛盾里，维持模型工作集的真实性与相关性。带着这个结论，现在打开黑盒。

2

静态分解：它由什么组成

打开黑盒，沿空间维度拆解。点部件卡片，动画中对应部分会亮成琥珀色。

「它由什么构成？核心方法是分解、分类、结构化——分解需符合 MECE 法则，同层必须粒度一致。」—— 人月聊IT · 思维系列

上下文装配台可按功能分成五组：

来源组 —— 负责「仓库里有什么」
f 组 —— 负责「五段流水线」
窗口组 —— 负责「台面摆什么」
压缩组 —— 负责「有损但不失真」

静态分解只回答了「有什么」。一次调用前，这些工位怎样在时间上配合、窗口怎样被填满又压回？必须切换到时间维度——下一节。

3

动态分析：它如何运转

盯住那个琥珀色令牌。用动画下方的 9 个步骤点逐帧走完一次完整装配。

「它如何演变与运作？关注时间轴上的发展规律、行为模式和内部流程。核心方法是流程分析、行为追溯。」—— 人月聊IT · 思维系列

操作：点击动画下方步骤条上的圆点（或「下一步」按钮），画面会定格在对应时刻。建议完整走两遍：第一遍只看令牌走哪个工位、条目怎么落位，第二遍同时看窗口上方的注意力曲线和右侧预算条。

阶段时刻活跃工位预算占用这一步在干什么
① Retrieve0°–80°检索—从仓库初筛「可能相关」；P3 只挂 handle，不展开
② Select80°–160°分诊—P0 贴眼前 / P1 进窗口 / P2 压缩进 / P3 挂入口
③ 装填160°–260°窗口20% → 55%候选条目陆续进窗——但不放满，要留容错与召回余地
④ Compress260°–320°压缩55% → 35%触到 60% 线先压再跑：旧轮次转摘要，错误堆栈强制保护
⑤ Order320°–400°排序35%条目从「堆叠」滑到「有序」：System → Goal → 硬约束 → 状态 → 事实 → 证据 → Observation → Action → 摘要
⑥ Inject400°–480°注入35%最终装配：首尾三明治，约束钉头 + 尾部追加 reminder
⑦ 注意力480°–560°曲线扫描35%扫描线扫过窗口：首尾亮、中间暗——「在」≠「被看见」
⑧ 交托560°–640°→ 模型48%一个中等模型读干净的三万 token，胜过最强模型淹在十八万噪声里
⑨ 回收640°–720°下一轮48% → 20%新信息进来，窗口重新装填；压缩后的历史成为下一轮的 Context

两个容易错过、但值得在分步模式里细看的点：① 第 ③ 阶段预算只爬到 55% 就停——「模型支持 128K 就直接放满」的代价是没有容错、没有召回余地、注意力被稀释；② 第 ⑦ 阶段把扫描线停在窗口正中：最关键的约束如果被海量工具返回推到中间，位置本身就等于失效，模型不是忘了，是看不见。

4

动静融合：部件如何协同出「干净的工作集」

把第 2 节的「结构」和第 3 节的「流程」叠在一起——这才是理解的完成态。

「动静融合的关键是建立映射：将组成部件与操作步骤一一对应，理解各部件如何协同产生外在行为。系统 = 元素 + 连接 + 目标。」—— 人月聊IT · 思维系列

映射表：每个部件在每个阶段里承担什么角色。竖着看是一个阶段的全体协同，横着看是一个部件的完整职责。

部件 ＼ 阶段① Retrieve② Select③ 装填④ Compress⑤ Order⑥ Inject⑦ 注意力
Context 仓库被初筛候选池条目流出原文可召回———
Select 分诊—定 P0-P3决定谁进窗决定谁被压———
预算线——爬升到 55%触发压缩约束余量核算—
Compress———旧轮次→摘要摘要参与排序——
Order 排序——条目堆叠—滑到有序位—位置决定明暗
首尾三明治———约束不参与压缩钉最前缀尾部追加 reminder两端高亮
注意力曲线————排序服务它注入完成扫描验证

点题一句：「模型这次答得好」这个外在行为，不是任何单一工位的属性，而是「分诊 + 压缩 + 排序 + 三明治」整体协同涌现的——尤其顺序：同样的九条内容，无序堆叠时中间的关键约束亮度只有 0.4，有序装配后头部与尾部都站到了注意力高地上。另一个涌现属性是可自述：截断过的工具返回带着「原文 N token 已省略」的标记，模型知道自己看到的不是全文——裁剪成为可推理的前提，而不是暗厢操作。

5

环境场景：它依赖什么才能工作

主体之外，还有一圈支撑系统。

「对事物的认识 = 空间属性 + 时间属性 + 环境属性（外在关系和依赖）。」—— 人月聊IT · 思维系列
写入侧供应链入库解析、分片、补元数据、索引清单——写入侧被当软件资产管理（可发布、可灰度、可回滚），检索才有的可查。
检索基础设施向量库 / ES / 关键词索引 / 图谱。Select 与 Retrieve 的地基，也是 Refine 细节召回的慢路。
压缩用的轻量模型摘要是抽取不是推理。模型可读压缩：删礼貌与转场，只求极致信息密度，但禁改原意。
多副本存储DB + Redis、原文 / 摘要 / 索引三种精度共存。要管的是版本与失效：Item 带 version，事实走 upsert，软记忆带 superseded。
分诊埋点trace_id / item / priority / decision / reason / tokens_used——没有 trace 的分诊就是黑盒，调参只能调运气。
画像与记忆系统长期 / 候选 / 当前三层画像，四 C 稳定性评分。画像属于「老而重要」：新鲜度规则对它不适用。

动画里的装配台能转起来，前提是这六个系统在「环境」里就位。拆掉任何一个，外在行为立即消失——尤其是写入侧供应链和分诊埋点：拆掉它们，「哪条内容该进窗口」立刻退化成模型临场自判。

6

复盘自测：学习-实践-复盘的闭环

用自己的话能讲清楚，才算真的懂。先答题，再对照解析。

一页带走

仓库不是工作台；先分诊、再装配；约束钉两头，摘要不吞错。

· 方法：表象（注意力预算分配）→ 结构（五组部件）→ 流程（九阶段）→ 融合（干净工作集是涌现属性）。

· 结构：Context 仓库 + f 五段流水线 + P0-P3 分诊 + 预算线 + 注意力曲线 + 首尾三明治。

· 行为：检索 → 分诊 → 装填到 55% → 60% 触发压缩 → 排序装配 → 注入 → 扫描验证 → 交托模型。

· 协同：顺序与三明治让同九条内容亮度重排；干净的中等窗口胜过淹没在噪声里的最强模型。
