分路召回：让该在场的必须到场

「评审会上定死的禁止 ORM，特意写进了向量库，六周后 Agent 照样导入」——它没删你的规则，它只是没看见。相似度这把尺子，量不了「该不该在场」。这页课把检索做成四路并发的管线，并用一次完整的事故-修复对照演示分路架构，动画支持自动运转和分步点击两种模式。

① 表象观察→ ② 静态分解→ ③ 动态分析→ ④ 动静融合→ ⑤ 环境场景→ ⑥ 复盘自测
红框 / 红段 = 约束强制在场 琥珀 = 概率域返回 灰虚线 = 未发生的查询
相位 -- 阶段 -- 关键量 --
第二视图 · 四路返回时序 · 谁先到、谁强制（与主图同步）
读法：先看哪一路先返回、哪一路强制置顶，再看合并带的 40% 约束帽如何被填满。
速度1× 演示速度 ≈ 1 次检索 / 6.4 秒
自动运转模式 点下方步骤点可切换到分步演示，随你点击定格。

相位口径：0° = Query Planning 开始；720° = 生成与闭环结束。四路并发 80°、合并 300°、入窗 360°；副图与主图同相位。

1

表象观察：先把它当黑盒

第一步不拆机器，只看它对外表现出什么行为。

「对事物的观察包括了静态结构 + 动态生命周期 + 环境场景三个方面的内容。」

从外部看，检索系统做的事只有一件：一个问题进来，一组排好序、带着来源的证据出去。它不生成答案，它决定模型「凭什么下判断」。好的检索和坏的检索，在调用方看来都是一次普通查询——差别只在答案的因果链能不能追到「哪一版索引里的哪个 chunk」。

Query（含缺口）→ 分路召回（黑盒）→ 证据卡（主产物） 空结果 / 迭代轮次（副产物）

黑盒观察的结论：这是一台知识供应链的读取段——写入侧管「候选从哪来、是什么版本」，读取侧管「谁先进窗口」。带着这个结论，现在打开黑盒。

2

静态分解：它由什么组成

打开黑盒，沿空间维度拆解。点部件卡片，动画中对应部分会亮成琥珀色。

「它由什么构成？核心方法是分解、分类、结构化——分解需符合 MECE 法则，同层必须粒度一致。」

分路召回管线可按功能分成五组：

Query 组 —— 负责「先知道缺什么」
四路组 —— 负责「不同域用不同尺子」
融合组 —— 负责「谁先进窗口」
出口组 —— 负责「证据变成决策素材」
经济组 —— 负责「花多少钱办多少事」

静态分解只回答了「有什么」。一次「写数据库访问层」的检索，四路怎么并发、红线怎么进窗、什么时候停？必须切换到时间维度——下一节。

3

动态分析：它如何运转

盯住那些移动的卡片。用动画下方的 9 个步骤点逐帧走完一次完整检索。

「它如何演变与运作？关注时间轴上的发展规律、行为模式和内部流程。核心方法是流程分析、行为追溯。」

操作：点击动画下方步骤条上的圆点（或「下一步」按钮），画面会定格在对应时刻。建议完整走两遍：第一遍只看红框卡片走哪条路，第二遍同时看合并带的预算段怎么按优先级填。

4

动静融合：部件如何协同出「该在场的在场」

把第 2 节的「结构」和第 3 节的「流程」叠在一起——这才是理解的完成态。

「动静融合的关键是建立映射：将组成部件与操作步骤一一对应，理解各部件如何协同产生外在行为。系统 = 元素 + 连接 + 目标。」

点题一句：「保命红线六周后仍在场」这个外在行为，不是任何一个检索器的属性，而是「写入分类 + 读取分路 + 优先级合并」整体协同涌现的。把同一条规则倒进向量池，它的生死由余弦相似度决定——那是把确定域扔进了概率筛子，像拿尺子量温度。反过来，分路架构也有它的价格：规则路依赖 domain 抽取，抽错了全线跳过——所以兜底要按「抽错也不至于全废」来设计：多值宽口径注入、按动作类型触发、约束漏注入计入审计。

5

环境场景：它依赖什么才能工作

主体之外，还有一圈支撑系统。

「对事物的认识 = 空间属性 + 时间属性 + 环境属性（外在关系和依赖）。」
写入侧供应链采集、解析、分片、补元数据、入库校验。没有 IndexManifest 和 golden_set 回归，索引连「能不能切线上」都答不了。
检索基础设施规则引擎 / 倒排索引 / 向量库 / 图谱。先一百万缩到一万，再谈向量查询——高频过滤条件提前建索引。
Embedding 与 Rerank概率域的两件重型装备。但 Codex 全仓零向量也活得很好——语料短而可控时才敢零向量，可抄的是决策顺序。
知识源治理owner、生效期、权限域、下线预案。废止规则还躺在索引里答题，是「新文档没生效」类事故的经典根子。
评估黄金集Recall@K、证据覆盖率、重复率、检索结果编辑距离。Recall 涨而答案降，最常见是重复率上升——进来的更多，但更脏。
缓存三层结果缓存 → 答案缓存 → 入库期派生复用。优先缓存检索结果，谨慎缓存最终答案——依赖实时数据时它就是过期答案发射器。

动画里的管线能转起来，前提是这六个系统在「环境」里就位。拆掉任何一个，外在行为立即消失——尤其是写入侧供应链：拆掉它，「候选从哪来、是什么版本」立刻变成一笔糊涂账。

6

复盘自测：学习-实践-复盘的闭环

用自己的话能讲清楚，才算真的懂。先答题，再对照解析。

一页带走

确定域走规则，概率域走向量；名次是硬通货，最快的查询是没发生的查询。

· 方法：表象（知识供应链读取段）→ 结构（五组部件）→ 流程（九阶段）→ 融合（红线在场是涌现属性）。

· 结构：Query Planning + 四路召回 + RRF 融合 + 优先级预算 + 证据卡 + 最小充分。

· 行为：约束走触发条件强制进，偏好细节走向量按名次填；充分性够就停，缺什么才查什么。

· 协同：写入分类 × 读取分路 × 优先级合并，三件事齐了，「该在场的必须到场」才成立。

· 边界与简化：四路返回时序被压缩到同一时间轴；真实检索延迟差异很大，演示只保留因果关系。
