# 附录：依赖安全与供应链

Java 项目会关心 Maven 依赖漏洞、许可证、传递依赖、私服和构建可重复性。Rust 项目也一样，只是工具换成了 Cargo 生态。这篇附录讲 `cargo audit`、`cargo deny`、crate 选择标准、许可证检查和版本升级策略。

## 一、Rust 依赖风险来自哪里

Rust 依赖通常来自 crates.io。风险包括：

- 已知安全漏洞。
- 恶意 crate 或 typo-squatting。
- 维护者停止维护。
- 许可证不兼容。
- 传递依赖过多。
- feature flags 拉入不需要的依赖。
- `build.rs` 在构建时执行代码。

**Java 程序员注意**：`build.rs` 有点像 Maven plugin 或 Gradle task，它会在构建阶段执行。不要随便信任来源不明的 crate。

## 二、查看依赖树

```bash
cargo tree
```

只看某个依赖为什么被引入：

```bash
cargo tree -i openssl
```

查看 feature：

```bash
cargo tree -e features
```

常见用途：

- 查重复版本。
- 查 OpenSSL、native 依赖来源。
- 查某个大依赖是谁引入的。
- 查 default features 是否拉入不必要能力。

## 三、cargo audit：漏洞扫描

安装：

```bash
cargo install cargo-audit
```

运行：

```bash
cargo audit
```

它会检查 `Cargo.lock` 里的依赖是否命中 RustSec Advisory Database。

CI 里：

```yaml
- name: Audit dependencies
  run: |
    cargo install cargo-audit
    cargo audit
```

对应 Java：

| Java | Rust |
|------|------|
| OWASP Dependency-Check | cargo audit |
| Snyk | cargo audit / cargo deny / 平台扫描 |
| Maven lock/依赖解析 | Cargo.lock |

**Java 程序员注意**：`cargo audit` 依赖 `Cargo.lock`。应用项目一定要提交 lockfile，否则扫描结果不可重复。

## 四、cargo deny：许可证和策略

`cargo deny` 能检查：

- 漏洞。
- 许可证。
- banned crate。
- 重复版本。
- unknown registry 或 git source。

安装：

```bash
cargo install cargo-deny
```

初始化：

```bash
cargo deny init
```

运行：

```bash
cargo deny check
```

示例 `deny.toml` 片段：

```toml
[licenses]
allow = [
    "MIT",
    "Apache-2.0",
    "BSD-2-Clause",
    "BSD-3-Clause",
    "ISC",
]
confidence-threshold = 0.8

[bans]
multiple-versions = "warn"
wildcards = "deny"

[sources]
unknown-registry = "deny"
unknown-git = "deny"
```

CI：

```yaml
- name: Check dependency policy
  run: |
    cargo install cargo-deny
    cargo deny check
```

## 五、如何选择 crate

选择 crate 时不要只看下载量。建议检查：

| 检查项 | 为什么 |
|--------|--------|
| 最近更新时间 | 判断维护活跃度 |
| GitHub issue/PR 状态 | 判断维护质量 |
| 文档质量 | Rust 生态很重视 docs.rs |
| 依赖数量 | 依赖越多供应链面越大 |
| unsafe 使用 | 高风险 crate 要看维护者和测试 |
| 许可证 | 是否适合公司项目 |
| MSRV | 是否符合你的 Rust 版本 |
| feature flags | 是否可以关闭不需要功能 |
| 社区采用度 | 是否是事实标准 |

常见事实标准：

| 场景 | 常用 crate |
|------|------------|
| JSON/序列化 | serde |
| 异步运行时 | tokio |
| HTTP 客户端 | reqwest |
| Web 框架 | axum / actix-web |
| 错误处理 | thiserror / anyhow |
| 日志追踪 | tracing |
| 命令行 | clap |
| 数据库 | sqlx / diesel |

## 六、版本升级策略

日常升级：

```bash
cargo update
cargo test
cargo clippy --all-targets --all-features -- -D warnings
```

只升级一个依赖：

```bash
cargo update -p tokio
```

查看过时依赖可以用：

```bash
cargo install cargo-outdated
cargo outdated
```

升级建议：

- 应用项目：定期 `cargo update`，依赖测试和 CI 兜底。
- 库项目：谨慎提高最低版本，注意下游兼容。
- 安全漏洞：优先升级受影响依赖，必要时临时替换 crate。
- 大版本升级：单独 PR，避免和业务修改混在一起。

## 七、Feature Flags 安全

很多 crate 的 default features 会带入额外依赖：

```toml
reqwest = { version = "0.12", default-features = false, features = ["json", "rustls-tls"] }
```

好处：

- 减少 OpenSSL 等 native 依赖。
- 减少不必要代码和攻击面。
- 构建更可控。

检查 feature：

```bash
cargo tree -e features
```

**Java 程序员注意**：这类似排除 Maven 传递依赖，但 Rust feature 是编译期能力开关，会影响最终二进制内容。

## 八、Git 依赖和 path 依赖

生产项目尽量少用 Git 依赖：

```toml
my_crate = { git = "https://github.com/example/my_crate", rev = "abc123" }
```

如果必须用：

- 锁定 `rev`，不要只写 branch。
- 确认仓库可信。
- CI 中保留 lockfile。
- 后续尽量迁移到 crates.io 或内部 registry。

本地 path 依赖适合 workspace：

```toml
common = { path = "../common" }
```

不要把临时本地路径依赖提交到公共库里。

## 九、最小 CI 安全门禁

推荐组合：

```bash
cargo fmt --all --check
cargo clippy --all-targets --all-features -- -D warnings
cargo test --all-features
cargo audit
cargo deny check
```

GitHub Actions 示例：

```yaml
name: Security

on:
  push:
    branches: [main]
  pull_request:

jobs:
  dependency-check:
    runs-on: ubuntu-latest

    steps:
      - uses: actions/checkout@v4

      - uses: dtolnay/rust-toolchain@stable

      - uses: Swatinem/rust-cache@v2

      - name: Install tools
        run: cargo install cargo-audit cargo-deny

      - name: Audit
        run: cargo audit

      - name: Deny
        run: cargo deny check
```

## 十、团队规范建议

可以写进项目 README 或 CONTRIBUTING：

- 应用项目必须提交 `Cargo.lock`。
- 新增依赖要说明原因。
- 新增依赖前先检查许可证和维护状态。
- 不允许 wildcard 版本，例如 `serde = "*"`。
- 尽量不用未锁定 rev 的 Git 依赖。
- CI 必须运行 `cargo audit` 或等价扫描。
- 对包含大量 `unsafe` 的 crate 做额外 review。

## 小结

Rust 依赖治理的核心是：

- 用 `Cargo.lock` 固定实际依赖。
- 用 `cargo tree` 看清传递依赖和 feature。
- 用 `cargo audit` 扫已知漏洞。
- 用 `cargo deny` 管许可证、来源和策略。
- 选 crate 时看维护、文档、依赖、许可证和社区采用度。

Java 项目里你不会随便加一个陌生 Maven 依赖；Rust 也一样。Cargo 让加依赖很容易，但工程团队仍然要有边界。
