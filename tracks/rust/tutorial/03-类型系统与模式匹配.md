# 写给 Java 程序员的 Rust 入门（三）：类型系统与模式匹配

> 这是系列第三篇。Rust 的 `struct`、`enum`、泛型和 trait 能对应上 Java 里的 class、enum、generic、interface，但不要一一硬套。Rust 更愿意用类型把状态和错误表达清楚，而不是把问题留到运行时。

## 一、Struct（结构体）

### 基本定义

Java 用 class 来组织数据和行为，Rust 把数据和方法**分开**定义：

```java
// Java
public class User {
    private String name;
    private int age;

    public User(String name, int age) {
        this.name = name;
        this.age = age;
    }

    public String getName() { return name; }
    public int getAge() { return age; }

    public boolean isAdult() { return age >= 18; }
}
```

```rust
// Rust：数据定义和方法分开
struct User {
    name: String,
    age: u32,
}

// 方法定义在 impl 块里
impl User {
    // 构造函数（关联函数，不接收 self）
    fn new(name: String, age: u32) -> User {
        User { name, age }
    }

    // 实例方法（接收 &self，类似 Java 的 this）
    fn name(&self) -> &str {
        &self.name
    }

    fn age(&self) -> u32 {
        self.age
    }

    fn is_adult(&self) -> bool {
        self.age >= 18
    }

    // 可变方法
    fn set_name(&mut self, name: String) {
        self.name = name;
    }
}

fn main() {
    let user = User::new(String::from("Alice"), 25);
    println!("{} is {} years old", user.name(), user.age());
    println!("Adult? {}", user.is_adult());
}
```

关键区别：

1. **数据和方法分离**：`struct` 只管数据，`impl` 块定义方法。Java 把它们放在一起。
2. **没有构造函数语法**：`new` 只是一个普通的关联函数（类似 Java 的静态工厂方法）。
3. **`self` 参数有三种形式**：
   - `&self`：不可变借用（最常用，类似 Java 的 `this` 但只读）
   - `&mut self`：可变借用（可以修改字段）
   - `self`：转移所有权（方法调用后原变量失效）

```java
// Java 里 this 就是 this，不需要区分读写
class User {
    void setName(String name) { this.name = name; }  // this 天然可变
}
```

```rust
// Rust 必须明确：只读还是可写
impl User {
    fn read_name(&self) -> &str { &self.name }           // 只读
    fn change_name(&mut self, name: String) { self.name = name; }  // 可写
}
```

### 结构体创建语法糖

```rust
// 字段初始化简写（参数名和字段名相同时）
fn new(name: String, age: u32) -> User {
    User { name, age }     // 等价于 User { name: name, age: age }
}

// 结构体更新语法
let user2 = User {
    name: String::from("Bob"),
    ..user1    // 其余字段从 user1 复制（注意：如果 User 不是 Copy，user1 的 name 会被 move）
};
```

### 元组结构体

```rust
// 没有字段名，只有类型
struct Point(f64, f64);
struct Color(u8, u8, u8);

let p = Point(1.0, 2.0);
println!("x = {}, y = {}", p.0, p.1);   // 用 .0 .1 访问
```

```java
// Java 的等价做法
record Point(double x, double y) {}
// 或者
class Point {
    final double x, y;
    Point(double x, double y) { this.x = x; this.y = y; }
}
```

### 单元结构体

```rust
// 没有任何字段
struct Marker;

let m = Marker;   // 不需要括号
```

Java 里没有直接对应。可以理解为只有一个实例的 enum（类似 Java 的单例）。

### 派生宏（Derive）

```rust
// 自动实现常用 trait
#[derive(Debug, Clone, PartialEq)]
struct User {
    name: String,
    age: u32,
}

fn main() {
    let u1 = User { name: String::from("Alice"), age: 25 };
    println!("{:?}", u1);           // Debug 打印

    let u2 = u1.clone();            // 深拷贝
    assert_eq!(u1, u2);             // 相等性比较
}
```

```java
// Java 的等价做法
// Lombok 注解
@Data
class User {
    String name;
    int age;
}

// 或者 Java 14+ record
record User(String name, int age) {}  // 自动有 toString, equals, hashCode
```

常用 derive 宏：

| 宏 | 作用 | Java 对应 |
|----|------|-----------|
| `Debug` | 可用 `{:?}` 打印 | `toString()` |
| `Clone` | 可深拷贝 | `clone()` 方法 |
| `Copy` | 按位拷贝（仅适用于全是 Copy 字段的 struct） | 基本类型赋值 |
| `PartialEq` | 可用 `==` 比较 | `equals()` |
| `Eq` | 完全相等（需要 PartialEq + 全字段可比较） | — |
| `Hash` | 可计算哈希 | `hashCode()` |
| `Default` | 有默认值 | 无直接对应 |
| `Serialize/Deserialize` | 序列化（serde crate） | Jackson 注解 |

## 二、Enum（枚举）

Rust 的枚举和 Java 的枚举**完全不是一个东西**。Java 的 enum 本质是一组固定的单例实例，Rust 的 enum 是**代数数据类型（ADT）**——每个变体可以携带不同类型和数量的数据。

### 基本定义

```rust
// Rust：每个变体可以携带不同的数据
enum Shape {
    Circle(f64),                      // 圆形，携带半径
    Rectangle(f64, f64),              // 矩形，携带宽高
    Triangle { a: f64, b: f64, c: f64 },  // 三角形，携带三边长
}

fn area(shape: &Shape) -> f64 {
    match shape {
        Shape::Circle(r) => std::f64::consts::PI * r * r,
        Shape::Rectangle(w, h) => w * h,
        Shape::Triangle { a, b, c } => {
            let s = (a + b + c) / 2.0;
            (s * (s - a) * (s - b) * (s - c)).sqrt()
        }
    }
}
```

```java
// Java：enum 是一组固定实例
enum Shape {
    CIRCLE, RECTANGLE, TRIANGLE;
}

// Java 想实现类似效果，通常用 sealed class（Java 17+）
sealed interface Shape permits Circle, Rectangle, Triangle {
    double area();
}
record Circle(double radius) implements Shape {
    public double area() { return Math.PI * radius * radius; }
}
record Rectangle(double width, double height) implements Shape {
    public double area() { return width * height; }
}
record Triangle(double a, double b, double c) implements Shape {
    public double area() {
        double s = (a + b + c) / 2;
        return Math.sqrt(s * (s - a) * (s - b) * (s - c));
    }
}
```

可以看到 Java 需要 sealed interface + record 才能模拟 Rust 的 enum。Rust 原生就支持，而且更简洁。

### 枚举可以给方法

```rust
enum Message {
    Quit,
    Move { x: i32, y: i32 },
    Write(String),
    ChangeColor(i32, i32, i32),
}

impl Message {
    fn process(&self) {
        match self {
            Message::Quit => println!("Quit"),
            Message::Move { x, y } => println!("Move to ({x}, {y})"),
            Message::Write(text) => println!("Write: {text}"),
            Message::ChangeColor(r, g, b) => println!("Color: ({r}, {g}, {b})"),
        }
    }
}
```

```java
// Java 的 enum 也可以有方法和字段，但不能携带不同数据
enum Message {
    QUIT,
    MOVE,
    WRITE,
    CHANGE_COLOR;

    void process() {
        switch (this) {
            case QUIT -> System.out.println("Quit");
            case MOVE -> System.out.println("Move");
            // ...
        }
    }
}
// 问题：MOVE 没法携带 x, y 数据，WRITE 没法携带文本
```

### 枚举在内存中的大小

Rust 的 enum 大小 = **最大变体的大小 +  discriminant（标签，用于区分变体）**：

```rust
enum Example {
    A,                    // 0 字节数据
    B(i32),               // 4 字节数据
    C(String),            // 24 字节数据（ptr + len + capacity）
}
// Example 的大小 ≈ 24 + 1（discriminant）+ padding ≈ 32 字节
```

Java 的 enum 实例是对象引用（8 字节），实际数据在堆上。Rust 的 enum 是值类型，数据直接内联。

## 三、Option 类型

### 为什么需要 Option？

Java 的 `null` 是"十亿美元的错误"——它表示"没有值"，但任何引用类型都可以是 null，编译器不强制你检查。结果就是到处都有 `NullPointerException`。

Rust 没有 null。它用 `Option<T>` 来表示"可能有值，也可能没有"：

```rust
// Option 的定义（标准库里已经定义好了，这里只是展示）
enum Option<T> {
    Some(T),    // 有值
    None,       // 没有值
}
```

```java
// Java
String name = findName();   // 可能返回 null
if (name != null) {
    System.out.println(name.length());   // 忘了判空就 NPE
}

// Java 8+ 的 Optional
Optional<String> name = findName();
name.ifPresent(n -> System.out.println(n.length()));
```

```rust
// Rust
let name: Option<String> = find_name();
match name {
    Some(n) => println!("{}", n.len()),   // 编译器强制你处理 None 的情况
    None => println!("Not found"),
}
```

**核心区别**：Java 的 `null` 是类型系统的一个漏洞（任何引用都可以是 null），Rust 的 `Option<T>` 是类型系统的一部分（`Option<String>` 和 `String` 是不同类型，不能混用）。

### Option 的常用方法

```rust
let some_value: Option<i32> = Some(42);
let none_value: Option<i32> = None;

// unwrap：有值返回值，None 则 panic（类似 Java 的 Optional.get()）
let v = some_value.unwrap();   // 42
// let v = none_value.unwrap();   // panic！

// expect：和 unwrap 类似，但可以自定义 panic 信息
let v = some_value.expect("value should not be None");

// unwrap_or：None 时返回默认值（最安全）
let v = none_value.unwrap_or(0);   // 0

// unwrap_or_else：None 时用闭包计算默认值（惰性求值）
let v = none_value.unwrap_or_else(|| compute_default());

// map：有值时转换，None 保持不变
let doubled = some_value.map(|x| x * 2);   // Some(84)

// and_then（flatMap）：有值时执行返回 Option 的操作
let result = some_value.and_then(|x| {
    if x > 0 { Some(x.to_string()) } else { None }
});   // Some("42")

// is_some / is_none
if some_value.is_some() {
    println!("has value");
}

// if let 简化写法（后面会详细讲）
if let Some(v) = some_value {
    println!("value is {v}");
}
```

```java
// Java Optional 的对应方法
Optional<Integer> opt = Optional.of(42);

opt.orElse(0);                    // 对应 unwrap_or
opt.orElseGet(() -> 0);           // 对应 unwrap_or_else
opt.map(x -> x * 2);             // 对应 map
opt.flatMap(x -> ...);            // 对应 and_then
opt.isPresent();                  // 对应 is_some
```

**Java 程序员注意**：Java 的 `Optional` 是后来加上去的，很多旧 API 还是返回 null。Rust 的 `Option` 是一开始就设计好的，所有标准库 API 都用它来表示"可能没有值"。

还有一个很常见的坑：`map` 会消费 `Option<T>` 本身。如果你只有一个引用，或者后面还要继续使用原来的 `Option<String>`，先用 `as_ref()` 把它变成 `Option<&String>`。

```rust
let name: Option<String> = Some("Alice".to_string());

let len = name.as_ref().map(|s| s.len()); // Some(5)，不拿走 String
println!("{name:?}");                     // name 还能继续用

// 如果写 name.map(|s| s.len())，String 会被 move 出 Option
```

## 四、match 表达式

`match` 是 Rust 里最常用也最有分量的控制流工具之一。Java 的 `switch` 主要是"选择执行哪个分支"，Rust 的 `match` 是**模式匹配**——可以同时检查值、解构数据、绑定变量。

### 基本语法

```rust
let number = 13;

match number {
    1 => println!("one"),
    2..=12 => println!("two to twelve"),    // 范围匹配
    13 | 19 => println!("thirteen or nineteen"),  // 多值匹配
    _ => println!("something else"),         // 通配符，匹配所有剩余情况
}
```

### 穷尽性检查

**match 必须覆盖所有可能的情况**，否则编译不过：

```rust
let x: u8 = 200;
match x {
    0 => println!("zero"),
    1 => println!("one"),
    // 编译错误！没有覆盖 2-255 的情况
    // 需要加 _ => ... 或者其他分支
}
```

```java
// Java 的 switch 语句不要求穷尽
switch (x) {
    case 0: System.out.println("zero"); break;
    case 1: System.out.println("one"); break;
    // 不写 default 也不会编译错误
}

// Java 14+ 的 switch 表达式必须能产生值，所以要穷尽
String text = switch (x) {
    case 0 -> "zero";
    case 1 -> "one";
    default -> "other";
};
```

更准确地说：Rust 的 `match` 天生要求穷尽；Java 要分情况看，传统 switch 语句不强制，switch 表达式和 sealed class/pattern matching 场景会逐步接近这种约束。

### 模式匹配的强大之处

```rust
// 匹配枚举并解构数据
enum Coin {
    Penny,
    Nickel,
    Dime,
    Quarter { state: String },
}

fn value_in_cents(coin: &Coin) -> u32 {
    match coin {
        Coin::Penny => 1,
        Coin::Nickel => 5,
        Coin::Dime => 10,
        Coin::Quarter { state } => {
            println!("Quarter from {state}");
            25
        }
    }
}
```

```rust
// 匹配 struct
struct Point { x: f64, y: f64 }

fn describe(point: &Point) -> String {
    match point {
        Point { x: 0.0, y: 0.0 } => String::from("origin"),
        Point { x, y: 0.0 } => format!("on x-axis at {x}"),
        Point { x: 0.0, y } => format!("on y-axis at {y}"),
        Point { x, y } => format!("at ({x}, {y})"),
    }
}
```

```rust
// 匹配元组
fn describe_pair(pair: (i32, i32)) -> String {
    match pair {
        (0, 0) => String::from("origin"),
        (x, 0) => format!("({x}, 0)"),
        (0, y) => format!("(0, {y})"),
        (x, y) => format!("({x}, {y})"),
    }
}
```

这里还有一个 2018 edition 之后的“自动挡”规则，叫 match ergonomics。比如 `value_in_cents(coin: &Coin)` 里匹配的是 `&Coin`，但代码可以直接写 `Coin::Quarter { state }`，不用写 `&Coin::Quarter { ref state }`。编译器会根据被匹配的值自动选择借用绑定。

```rust
fn value_in_cents(coin: &Coin) -> u32 {
    match coin {
        Coin::Penny => 1,
        Coin::Quarter { state } => {
            // state 的类型是 &String，不是 String
            println!("{state}");
            25
        }
        _ => 0,
    }
}
```

这能让代码短很多，但也解释了为什么有时你以为拿到的是 `T`，实际类型却是 `&T`。看不清时，让 IDE 显示变量类型，或者临时写一个类型标注让编译器告诉你。

### 守卫（Guard）

```rust
let num = 4;
match num {
    x if x < 0 => println!("negative"),
    x if x % 2 == 0 => println!("even"),
    _ => println!("odd"),
}
```

### 绑定 `@`

```rust
let msg = Message::Hello { id: 42 };

match msg {
    Message::Hello { id: id_var @ 42..=100 } => {
        println!("Got id in range: {id_var}");
    }
    Message::Hello { id } => println!("Got id: {id}"),
    _ => {}
}
```

### match 是表达式

```rust
let description = match number {
    1 => "one",
    2 => "two",
    _ => "many",
};
```

```java
// Java 14+ 的 switch 表达式也可以返回值
String description = switch (number) {
    case 1 -> "one";
    case 2 -> "two";
    default -> "many";
};
// 功能类似，但 Java 的 switch 不能解构数据
```

## 五、if let 与 while let

`match` 很强大，但有时候你只关心一种情况，其他情况忽略。写一个完整的 match 太啰嗦：

```rust
// 太啰嗦
let value = Some(42);
match value {
    Some(v) => println!("value is {v}"),
    None => {},   // 不想处理 None，但必须写
}

// 用 if let 简化
if let Some(v) = value {
    println!("value is {v}");
}
```

```java
// Java 的等价做法
if (value != null) {
    System.out.println(value);
}
// 或者 Java 的 pattern matching（Java 21+）
if (value instanceof String s) {
    System.out.println(s);
}
```

### while let

```rust
// 当条件满足时一直循环
let mut stack = vec![1, 2, 3];
while let Some(top) = stack.pop() {
    println!("popped: {top}");
}
// 输出 3, 2, 1（栈顶到栈底）
```

```java
// Java 的等价做法
while (!stack.isEmpty()) {
    Integer top = stack.pop();
    System.out.println("popped: " + top);
}
```

### let-else（Rust 1.65+）

```rust
// 如果不匹配，必须执行 diverging 语句（return, break, panic 等）
let Some(value) = get_value() else {
    return;   // 必须 diverge
};
println!("Got: {value}");

// 等价于：
let value = match get_value() {
    Some(v) => v,
    None => return,
};
```

### 模式不只在 match 里

刚学时很容易以为"模式匹配 = match"。其实 Rust 很多地方都能写模式，`match` 只是最完整的一种。

```rust
// let 解构
let point = (10, 20);
let (x, y) = point;

// for 循环解构
let users = vec![("alice", 30), ("bob", 25)];
for (name, age) in users {
    println!("{name}: {age}");
}

// 函数参数也能解构
fn print_point((x, y): (i32, i32)) {
    println!("x={x}, y={y}");
}
```

Java 里 record pattern 正在往这个方向走，但 Rust 很早就把它放进了日常语法里。读代码时看到 `let Some(x) = ... else { ... }`、`for (k, v) in map`，都可以按"左边是模式，右边是要匹配的数据"来理解。

## 六、Result 类型

Java 用异常处理错误，Rust 用 `Result<T, E>`：

```rust
// Result 的定义
enum Result<T, E> {
    Ok(T),     // 成功，携带返回值
    Err(E),    // 失败，携带错误信息
}
```

```java
// Java：用异常
public String readFile(String path) throws IOException {
    return Files.readString(Path.of(path));
}

try {
    String content = readFile("/tmp/test.txt");
} catch (IOException e) {
    System.err.println("Error: " + e.getMessage());
}
```

```rust
// Rust：用 Result
use std::fs;
use std::io;

fn read_file(path: &str) -> Result<String, io::Error> {
    fs::read_to_string(path)
}

match read_file("/tmp/test.txt") {
    Ok(content) => println!("Content: {content}"),
    Err(e) => eprintln!("Error: {e}"),
}
```

**核心区别**：

| 对比项 | Java 异常 | Rust Result |
|--------|-----------|-------------|
| 是否强制处理 | 受检异常强制，运行时异常不强制 | 编译器强制（至少要用 `_` 忽略） |
| 错误类型 | 运行时才知道 | 编译期确定（`Result<T, E>` 里的 E） |
| 控制流 | try/catch 跳转 | 普通的枚举值，用 match 处理 |
| 性能 | 创建异常对象有开销 | 零成本（就是枚举值） |

`?` 运算符是 `Result` 的好搭档，用于简化错误传播：

```rust
// 不用 ?
fn read_and_parse(path: &str) -> Result<i32, io::Error> {
    let content = match fs::read_to_string(path) {
        Ok(c) => c,
        Err(e) => return Err(e),   // 错误向上传播
    };
    match content.trim().parse::<i32>() {
        Ok(n) => Ok(n),
        Err(e) => Err(io::Error::new(io::ErrorKind::InvalidData, e)),
    }
}

// 用 ? 简化
fn read_and_parse(path: &str) -> Result<i32, Box<dyn std::error::Error>> {
    let content = fs::read_to_string(path)?;   // 如果 Err，直接 return Err
    let number = content.trim().parse::<i32>()?;
    Ok(number)
}
```

`?` 运算符的含义：如果结果是 `Ok(v)`，取出 `v` 继续执行；如果是 `Err(e)`，立即 `return Err(e.into())`。

这里的 `.into()` 很关键：`?` 不是魔法，它要求当前错误类型能从下层错误转换过来，也就是实现了 `From<LowerError>`。如果你把返回类型写成自己的 `AppError`，却没有实现 `From<io::Error>`，会看到类似 `the trait From<std::io::Error> is not implemented for AppError` 的报错。

```rust
#[derive(Debug)]
enum AppError {
    Io(std::io::Error),
    Parse(std::num::ParseIntError),
}

impl From<std::io::Error> for AppError {
    fn from(e: std::io::Error) -> Self {
        AppError::Io(e)
    }
}

impl From<std::num::ParseIntError> for AppError {
    fn from(e: std::num::ParseIntError) -> Self {
        AppError::Parse(e)
    }
}

fn read_number(path: &str) -> Result<i32, AppError> {
    let content = std::fs::read_to_string(path)?;
    let number = content.trim().parse::<i32>()?;
    Ok(number)
}
```

真实项目里通常不用手写这么多样板：库代码用 `thiserror` 的 `#[from]`，应用入口用 `anyhow::Result` 加 `.context()`。第 5 章会展开讲。

## 七、泛型（Generics）

### 泛型函数

```java
// Java
public static <T> T first(List<T> list) {
    return list.get(0);
}
```

```rust
// Rust
fn first<T>(list: &[T]) -> &T {
    &list[0]
}
```

语法几乎一样。但底层实现完全不同。

### 泛型 struct 和 enum

```rust
struct Point<T> {
    x: T,
    y: T,
}

enum Result<T, E> {
    Ok(T),
    Err(E),
}

enum Option<T> {
    Some(T),
    None,
}
```

```java
// Java
class Point<T> {
    T x, y;
}
```

### 关键区别：单态化 vs 类型擦除

这是 Rust 和 Java 泛型最本质的区别：

**Java：类型擦除（Type Erasure）**
```java
// 编译后，List<String> 和 List<Integer> 都变成 List<Object>
// 运行时无法区分
List<String> strings = new ArrayList<>();
List<Integer> ints = new ArrayList<>();
System.out.println(strings.getClass() == ints.getClass());  // true！
```

**Rust：单态化（Monomorphization）**
```rust
// 编译时，编译器为每个具体类型生成一份代码
// Point<i32> 和 Point<f64> 是完全不同的类型，在运行时各自独立
let pi = Point { x: 5, y: 10 };       // Point<i32>
let pf = Point { x: 1.0, y: 4.0 };    // Point<f64>
```

| 对比项 | Java 泛型 | Rust 泛型 |
|--------|-----------|-----------|
| 实现方式 | 类型擦除 | 单态化 |
| 运行时类型信息 | 丢失 | 保留 |
| 性能 | 有装箱拆箱开销 | 零成本（和手写具体类型一样快） |
| 代码大小 | 一份字节码 | 每个类型一份机器码 |
| `List<String>` == `List<Integer>` | true（运行时） | 不可能（不同类型） |

**Java 程序员注意**：Rust 泛型是零成本抽象——编译器为每个具体类型生成独立的代码，没有运行时开销。代价是编译产物更大、编译时间更长。

### 方法中的泛型

```rust
impl<T> Point<T> {
    fn new(x: T, y: T) -> Point<T> {
        Point { x, y }
    }

    fn x(&self) -> &T {
        &self.x
    }
}

// 可以只对特定类型实现方法
impl Point<f64> {
    fn distance_from_origin(&self) -> f64 {
        (self.x * self.x + self.y * self.y).sqrt()
    }
}
```

## 八、Trait（特征）

Trait 是 Rust 里最接近 Java interface 的概念，但比 interface 灵活得多。

### 定义和实现

```java
// Java
public interface Summary {
    String summarize();

    // 默认方法
    default String summarizeUsage() {
        return "Used a lot";
    }
}

public class Article implements Summary {
    @Override
    public String summarize() {
        return "Article summary";
    }
}
```

```rust
// Rust
trait Summary {
    fn summarize(&self) -> String;

    // 默认实现
    fn summarize_usage(&self) -> String {
        String::from("Used a lot")
    }
}

struct Article {
    title: String,
    content: String,
}

impl Summary for Article {
    fn summarize(&self) -> String {
        format!("Article: {}", self.title)
    }
}

fn main() {
    let article = Article {
        title: String::from("Rust is great"),
        content: String::from("..."),
    };
    println!("{}", article.summarize());
    println!("{}", article.summarize_usage());   // 使用默认实现
}
```

### Orphan Rule：不能随便给外部类型补实现

Java 里你不能在不改源码的情况下让第三方类真正 `implements` 一个新接口，通常要写 adapter。Rust 也有类似边界，而且规则更明确：**实现 trait 时，trait 或类型至少有一个必须定义在当前 crate 里**。

```rust
// 可以：当前 crate 定义的类型，实现标准库 trait
struct UserId(u64);

impl std::fmt::Display for UserId {
    fn fmt(&self, f: &mut std::fmt::Formatter<'_>) -> std::fmt::Result {
        write!(f, "{}", self.0)
    }
}

// 不可以：给 Vec<String> 实现 Display
// trait Display 来自 std，Vec 也来自 std，两个都不是你定义的
// impl std::fmt::Display for Vec<String> { ... }
```

这条规则叫 orphan rule，目的是避免不同库给同一个"外部类型 + 外部 trait"写出冲突实现。真需要给外部类型补行为，常见做法是包一层新类型：

```rust
struct UserNames(Vec<String>);

impl std::fmt::Display for UserNames {
    fn fmt(&self, f: &mut std::fmt::Formatter<'_>) -> std::fmt::Result {
        write!(f, "{}", self.0.join(", "))
    }
}
```

### Trait 作为参数

```rust
// 方式一：impl Trait 语法（简洁）
fn notify(item: &impl Summary) {
    println!("Breaking: {}", item.summarize());
}

// 方式二：Trait Bound 语法（更灵活）
fn notify<T: Summary>(item: &T) {
    println!("Breaking: {}", item.summarize());
}

// 多个 trait 约束
fn notify(item: &(impl Summary + Display)) {
    // item 必须同时实现 Summary 和 Display
}

// where 子句（约束复杂时更清晰）
fn some_function<T, U>(t: &T, u: &U) -> String
where
    T: Display + Clone,
    U: Clone + Debug,
{
    // ...
}
```

```java
// Java 的等价做法
void notify(Summary item) {
    System.out.println("Breaking: " + item.summarize());
}

// 多个约束
<T extends Summary & Display> void notify(T item) {
    // ...
}
```

### Trait Object（dyn Trait）——动态分发

```rust
// 静态分发（编译期确定类型，零成本）
fn notify(item: &impl Summary) { ... }

// 动态分发（运行时确定类型，有虚函数表开销）
fn notify(item: &dyn Summary) { ... }

// 可以放在集合里（不同类型但实现同一个 trait）
let items: Vec<Box<dyn Summary>> = vec![
    Box::new(Article { ... }),
    Box::new(Tweet { ... }),
];
```

```java
// Java 天然支持多态（动态分发）
List<Summary> items = List.of(
    new Article(...),
    new Tweet(...)
);
// Java 不需要特殊语法，因为所有对象引用都是"动态分发"的
```

**Java 程序员注意**：Rust 默认用**静态分发**（`impl Trait` 或泛型），性能最好但每个类型生成独立代码。需要动态分发时用 `dyn Trait`，类似 Java 的接口引用。`Box<dyn Trait>` 类似 Java 的 `InterfaceType` 引用。

### `impl Trait` vs `dyn Trait` 怎么选

Java 程序员很容易把 trait 直接理解成 interface，然后默认想写成 `dyn Trait`。但 Rust 的默认选择通常是 `impl Trait` 或泛型，只有确实需要运行时多态时才用 `dyn Trait`。

| 场景 | 推荐写法 | 原因 | Java 类比 |
|------|----------|------|-----------|
| 函数参数只要求实现某个 trait | `fn notify(item: &impl Summary)` | 写法短，静态分发，零运行时开销 | 泛型方法参数 |
| 参数和返回值要保持同一个具体类型 | `fn pick<T: Summary>(a: T, b: T) -> T` | `T` 能表达“同一种类型”约束 | `<T extends Summary>` |
| trait bound 很复杂 | `where T: Summary + Display + Clone` | 可读性更好，适合多个泛型参数 | 泛型约束列表 |
| 函数返回某个实现 trait 的具体类型，但不想暴露类型名 | `fn create() -> impl Summary` | 隐藏具体类型，仍然静态分发 | 返回接口但实现类型固定 |
| 集合里要放不同具体类型 | `Vec<Box<dyn Summary>>` | 编译期不知道统一具体类型，只能运行时分发 | `List<Summary>` |
| 运行时根据配置切换实现 | `Box<dyn Summary>` 或 `Arc<dyn Summary>` | 具体实现到运行时才确定 | Spring 注入不同 Bean |
| 需要减少泛型导致的代码膨胀 | `&dyn Summary` | 牺牲一点调用开销，换更少单态化代码 | 接口动态调用 |
| trait 里有泛型方法或返回 `Self` | 通常不能直接做 `dyn Trait` | 需要满足 object safety | Java interface 默认可动态分发，Rust 更严格 |

简单规则：

1. **能用泛型或 `impl Trait` 时，先用它们**。
2. **需要把不同类型放进同一个集合，才考虑 `dyn Trait`**。
3. **需要运行时替换实现，才考虑 `Box<dyn Trait>` 或 `Arc<dyn Trait>`**。
4. **如果编译器说 trait is not object safe，说明这个 trait 不能直接当 `dyn Trait` 用**。

```rust
// 返回 impl Trait：调用者知道它实现 Summary，但不知道具体类型
fn create_article() -> impl Summary {
    Article {
        title: "Rust".to_string(),
        author: "Alice".to_string(),
        content: "Ownership matters".to_string(),
    }
}

// 返回 dyn Trait：运行时可以选择不同实现
fn create_summary(kind: &str) -> Box<dyn Summary> {
    match kind {
        "tweet" => Box::new(Tweet {
            username: "alice".to_string(),
            content: "hello".to_string(),
        }),
        _ => Box::new(Article {
            title: "Rust".to_string(),
            author: "Alice".to_string(),
            content: "Ownership matters".to_string(),
        }),
    }
}
```

**Java 程序员注意**：`impl Trait` 不是“返回任意实现类”。对于 `fn create() -> impl Summary`，函数体最终必须返回同一个具体类型；如果 `if` 的两个分支返回 `Article` 和 `Tweet`，就要改成 `Box<dyn Summary>` 或定义一个 enum 包起来。

### 常用标准 Trait

| Trait | 作用 | Java 对应 |
|-------|------|-----------|
| `Display` | 用户友好的字符串表示 | `toString()` |
| `Debug` | 调试用的字符串表示 | `toString()`（调试用） |
| `Clone` | 深拷贝 | `clone()` |
| `Copy` | 按位拷贝 | 基本类型赋值 |
| `Default` | 默认值 | 无直接对应 |
| `From` / `Into` | 类型转换 | 构造函数 / 隐式转换 |
| `ToString` | 转字符串（自动为 Display 实现） | `toString()` |
| `Iterator` | 迭代器 | `Iterator<T>` |
| `PartialEq` / `Eq` | 相等比较 | `equals()` |
| `Hash` | 哈希 | `hashCode()` |
| `Ord` / `PartialOrd` | 大小比较 | `Comparable<T>` |
| `Drop` | 析构（离开作用域时调用） | `finalize()`（已废弃） |
| `Fn` / `FnMut` / `FnOnce` | 闭包 trait | 函数式接口 |

### Display 和 Debug 示例

```rust
use std::fmt;

struct Point { x: f64, y: f64 }

// Debug：自动派生
#[derive(Debug)]
struct PointDebug { x: f64, y: f64 }

// Display：手动实现
impl fmt::Display for Point {
    fn fmt(&self, f: &mut fmt::Formatter<'_>) -> fmt::Result {
        write!(f, "({}, {})", self.x, self.y)
    }
}

fn main() {
    let p = Point { x: 1.0, y: 2.0 };
    println!("{p}");          // 使用 Display：(1, 2)
    println!("{p:?}");        // 使用 Debug（需要 derive Debug）

    let pd = PointDebug { x: 1.0, y: 2.0 };
    println!("{pd:?}");       // PointDebug { x: 1.0, y: 2.0 }
}
```

## 九、Java 程序员注意事项总结

### Struct vs Class

- Rust 的 struct 只是数据容器，方法在 `impl` 块里定义。
- 没有继承！Rust 用 trait 组合代替继承。
- 没有构造函数语法，`new` 只是普通函数。
- 字段默认私有，没有 getter/setter 约定。

### Enum vs Enum

- Rust 的 enum 是代数数据类型，每个变体可以携带数据。
- Java 的 enum 是固定实例集合，不能携带不同类型的数据。
- Rust 的 enum 配合 match 是处理多种情况的最佳工具。

### Trait vs Interface

- Trait 不能有字段（状态），只能有方法。
- Rust 没有继承，用 trait 组合（composition）代替。
- Trait 支持默认实现，和 Java 8 的 default method 类似。
- Trait 可以作为类型约束（泛型 bound）或类型擦除（dyn trait）。

### 泛型

- Rust 泛型是单态化（零成本），Java 是类型擦除。
- Rust 泛型没有通配符（`? extends T`），用 trait bound 代替。
- Rust 的 `impl Trait` 语法比 Java 的泛型更简洁。

## 小结

这一篇的重点不是记语法，而是换一种建模习惯：

- **Struct** 建模数据，**impl** 定义行为，数据和行为分离。
- **Enum** 是代数数据类型，配合 **match** 穷尽处理所有情况。
- **Option** 消灭了 null，**Result** 消灭了异常。
- **泛型** 是零成本的单态化，不是类型擦除。
- **Trait** 比 interface 更灵活，支持组合而非继承。

这些类型系统特性共同构成了 Rust 的核心理念：**让编译器在编译期捕获尽可能多的错误**。下一篇我们进入集合、字符串和函数式编程。
