# 写给 Java 程序员的 Rust 入门（一）：环境搭建与语言基础

> 这是系列第一篇。假设你已经写过 Java，熟悉 JVM、Maven、泛型、Lambda、并发这些概念。这里不从"什么是变量"讲起，而是直接把 Rust 放到 Java 经验旁边看：哪些地方像，哪些地方完全不是一回事。

## 一、工具链：从 JDK + Maven 到 rustup + Cargo

Java 开发者装环境，先装 JDK（带 javac、java、jar 等工具），再用 Maven 或 Gradle 管理构建和依赖，可能还会用 SDKMAN 或 jenv 切换 JDK 版本。

Rust 这边的对应关系：

| Java 生态 | Rust 生态 | 说明 |
|-----------|-----------|------|
| SDKMAN / jenv | `rustup` | 版本管理，下载、切换 Rust 工具链 |
| javac | `rustc` | 编译器 |
| Maven / Gradle | `cargo` | 构建 + 包管理（二合一） |
| google-java-format | `rustfmt` | 代码格式化 |
| SonarLint / SpotBugs | `clippy` | 静态分析、lint 检查 |
| IntelliJ IDEA 插件 / JDT | `rust-analyzer` | IDE 代码补全、跳转、诊断 |
| JAR 包 | `crate` | 第三方依赖包 |

这一整套工具打包在一起叫 **toolchain**，统一通过 `rustup` 管理。

### 安装与基本命令

```bash
# 安装 rustup（顺带把 stable 工具链和 cargo 都装好）
curl --proto '=https' --tlsv1.2 https://sh.rustup.rs -sSf | sh

# 查看版本，相当于 java -version
rustc --version

# 升级工具链，相当于更新 JDK
rustup update

# 查看当前工具链信息
rustup show

# 安装指定版本
rustup install 1.80.0
rustup default 1.80.0

# 项目级别锁定版本（类似 .sdkmanrc）
# 在项目根目录创建 rust-toolchain.toml：
# [toolchain]
# channel = "1.80.0"
# components = ["rustfmt", "clippy"]
```

Rust 分 stable、beta、nightly 三个通道，大致对应 Java 的 LTS、EA（Early Access）和每日构建。正常项目用 stable 就够了。

### 编辑器与 rust-analyzer

Rust 的编译器报错很有用，但日常写代码不能只靠终端。建议把 `rust-analyzer` 配好，它相当于 Java 开发里的语言服务：补全、跳转定义、重命名、类型提示、内联报错都靠它。

常见选择：

- VS Code：安装 `rust-analyzer` 插件。
- IntelliJ IDEA / CLion：安装 Rust 插件。
- Neovim / Helix / Zed：走 LSP，后端也是 `rust-analyzer`。

**Java 程序员注意**：Rust 的类型推断和宏展开很多，IDE 偶尔会比编译器慢半拍。最终以 `cargo check` 为准，IDE 红线只是辅助判断。

### Cargo：Rust 的 Maven

```bash
# 创建新项目，相当于 mvn archetype:generate
cargo new hello_rust         # 二进制项目
cargo new hello_lib --lib    # 库项目

# 构建和运行
cargo build                  # 相当于 mvn compile
cargo build --release        # 相当于 mvn package -P release
cargo run                    # 相当于 mvn exec:java
cargo check                  # 只检查编译，不生成产物，速度快很多
cargo clean                  # 相当于 mvn clean
```

**Java 程序员注意**：`cargo check` 是日常开发中用得最多的命令。Rust 编译比 Java 慢很多（因为要做单态化、借用检查等），日常写代码时用 `cargo check` 快速验证类型和借用规则，真正要运行时才 `cargo build`。

### 项目结构对比

```
hello_rust/                  Java Maven 项目:
├── Cargo.toml               ├── pom.xml
├── src/                     ├── src/
│   └── main.rs              │   └── main/java/com/example/App.java
├── Cargo.lock               ├── src/test/
└── target/                  └── target/
```

`Cargo.toml` 就是 Rust 版的 `pom.xml`：

```toml
[package]
name = "hello_rust"
version = "0.1.0"
edition = "2021"          # Rust 语言版本（类似 Java 的 source/target 版本）

[dependencies]
serde = { version = "1.0", features = ["derive"] }   # 加依赖
```

**Java 程序员注意**：Rust 不允许"白嫖"上游的传递依赖。即使你的依赖 A 内部用了库 C，你想用 C 的 API 也必须在自己的 `Cargo.toml` 里显式声明。这样做的好处是上游换掉 C 不会影响你的代码。另外 Cargo 的版本号是语义化范围（`"1.0"` 表示 `>=1.0.0, <2.0.0`），所以有 `Cargo.lock` 文件来锁定具体版本，类似 npm 的 `package-lock.json`。

### Hello World

```rust
fn main() {
    println!("Hello, world!");
}
```

三个和 Java 不同的地方：

1. 入口函数写 `fn main()`，不是 `public static void main(String[] args)`。
2. `println!` 后面有个感叹号 `!`，说明这不是普通函数调用，而是一个**宏**。Rust 的宏系统后面会专门讲。
3. 编译出来的是原生二进制文件，不像 Java 编译成 `.class` 字节码还需要 JVM。Rust 编译完直接 `./target/debug/hello_rust` 就能跑。

## 二、变量绑定与可变性

Java 里变量默认可变，想不可变得加 `final`：

```java
// Java
int x = 5;
x = 6;              // OK

final int y = 5;
y = 6;              // 编译错误
```

Rust 反过来了——变量**默认不可变**，想可变要加 `mut`：

```rust
// Rust
let x = 5;
x = 6;              // 编译错误！

let mut y = 5;
y = 6;              // OK，因为加了 mut
```

为什么 Rust 要反过来？因为它希望你默认写出"少修改"的代码。变量能不改就不改，引用能只读就只读。这个习惯和后面的并发安全模型是紧密关联的。

### 类型推断

Rust 的类型推断比 Java 的 `var` 更激进：

```java
// Java 10+
var name = "hello";     // 推断为 String
var list = new ArrayList<String>();  // 推断为 ArrayList<String>
```

```rust
// Rust
let name = "hello";          // 推断为 &str
let mut list = Vec::new();   // 推断为 Vec<_>，具体类型后面用到才能确定
let x: i32 = 42;             // 也可以显式标注类型
```

大部分时候你不需要写类型，编译器能推出来。推不出来的时候它会报错提醒你加。

### Shadowing（变量遮蔽）

Rust 有一个 Java 没有的特性叫 **shadowing**——同名变量可以重复声明，新变量会遮蔽旧的：

```rust
let x = 5;
let x = x + 1;        // 合法！这是一个新变量，只是名字一样
let x = "hello";      // 甚至可以改变类型！
```

这在处理数据转换链的时候特别好用。Java 里我们经常被迫取新名字：

```java
// Java：不得不取新名字
String text = "123";
int value = Integer.parseInt(text);
int result = value + 1;
```

```rust
// Rust：一直用同一个名字
let text = "123";
let text = text.parse::<i32>().unwrap();  // 类型变了，但名字不变
let text = text + 1;
```

`parse::<i32>()` 里的 `::<i32>` 俗称 turbofish。它是在告诉编译器“我要把字符串解析成 `i32`”。如果上下文已经能推断类型，也可以写成：

```rust
let value: i32 = "123".parse().unwrap();
```

### 常量与静态变量

```rust
// 编译期常量，类似 Java 的 static final
const MAX_SIZE: u32 = 100_000;    // 必须标注类型

// 全局静态变量
static APP_NAME: &str = "MyApp";

// 可变静态变量（需要 unsafe 才能读写，不推荐用）
static mut COUNTER: i32 = 0;
```

**Java 程序员注意**：`const` 和 `static` 的区别是 `const` 可能被编译器内联到每个使用点（类似 Java 的编译期常量折叠），而 `static` 是一个真实的内存地址。`static mut` 在 Rust 2024 edition 已经被强烈不推荐使用，需要共享可变全局状态时用 `Mutex`、`RwLock`、`OnceLock` 等类型。

## 三、基本数据类型

### 整数类型

Rust 的整数类型比 Java 丰富得多，区分了有符号（`i`）和无符号（`u`）：

| Rust 类型 | 字节数 | Java 对应 | 说明 |
|-----------|--------|-----------|------|
| `i8` / `u8` | 1 | `byte`（只有有符号） | Rust 多了无符号版本 |
| `i16` / `u16` | 2 | `short`（只有有符号） | Rust 多了无符号版本 |
| `i32` / `u32` | 4 | `int`（只有有符号） | **i32 是 Rust 默认整数类型** |
| `i64` / `u64` | 8 | `long`（只有有符号） | Rust 多了无符号版本 |
| `i128` / `u128` | 16 | 无 | Java 没有 128 位整数 |
| `isize` / `usize` | 平台相关 | 无直接对应 | 64 位系统上是 8 字节 |

`isize` 和 `usize` 比较特殊，它们的位宽跟平台一致。`usize` 常用作集合的索引和长度（类似 Java 里用 `int` 做数组下标），`isize` 用得比较少。

`len()` 返回的就是 `usize`，所以新手常写出这种错误：

```rust
let items = vec![1, 2, 3];
let i: i32 = 1;
// println!("{}", items[i]); // 编译错误：索引必须是 usize

let i = i as usize;
println!("{}", items[i]);
```

`as usize` 不是万能药。如果这个数字可能是负数，先检查范围再转换，否则 `-1i32 as usize` 会变成一个巨大的正数。

```rust
let a: i32 = 42;
let b: u32 = 42;
let c = 123_456_789;      // 下划线分隔，提高可读性，默认 i32
let d = 0xff;              // 十六进制
let e = 0o77;              // 八进制
let f = 0b1111_0000;       // 二进制
```

**Java 程序员注意**：Rust 没有 Java 那种自动类型提升。`i32` 和 `i64` 不能直接运算，必须显式转换：

```rust
let a: i32 = 42;
let b: i64 = 100;
// let c = a + b;    // 编译错误！类型不匹配
let c = a as i64 + b;  // 用 as 做显式转换
```

### 整数溢出

Java 的 `int` / `long` 溢出会直接按补码回绕：

```java
int x = Integer.MAX_VALUE;
System.out.println(x + 1);   // -2147483648
```

Rust 更明确一点：debug 构建里整数溢出会 panic，release 构建默认按补码回绕。所以不要把溢出行为当作业务逻辑，真要表达就写清楚：

```rust
let x = i32::MAX;

let checked = x.checked_add(1);      // None，表示溢出
let wrapping = x.wrapping_add(1);    // -2147483648，明确要求回绕
let saturated = x.saturating_add(1); // i32::MAX，饱和到最大值
```

财务、库存、计数器这类代码里，优先用 `checked_*` 或业务类型把范围约束说清楚。

### 浮点类型

```rust
let x = 3.14;       // 默认 f64
let y: f32 = 2.71;  // 显式指定 f32
```

和 Java 的 `float` / `double` 对应，只不过 Rust 默认用 `f64`（精度更高），Java 默认用 `double` 其实也是 f64。

### 布尔类型

```rust
let t = true;
let f: bool = false;
```

和 Java 基本一样。但注意 Rust 的 `bool` 不能和整数互转，Java 里 `if (1)` 不合法，Rust 里 `if 1` 同样不合法。

### 字符类型

这是和 Java 差异较大的地方：

```rust
let c = 'A';            // 单引号，不是双引号
let emoji = '🦀';       // 合法！
let chinese = '中';      // 也合法！
```

| 对比项 | Java `char` | Rust `char` |
|--------|-------------|-------------|
| 编码 | UTF-16（2 字节） | UTF-8 标量值（4 字节） |
| 范围 | BMP（基本多文种平面） | 全部 Unicode |
| 中文支持 | 部分中文需要 surrogate pair | 直接支持 |
| 字面量引号 | 单引号 `'A'` | 单引号 `'A'` |

Rust 的 `char` 是 4 字节的 Unicode 标量值，能直接表示任何 Unicode 字符，包括 emoji。Java 的 `char` 是 2 字节的 UTF-16 编码单元，遇到 BMP 之外的字符（比如 emoji）需要用两个 `char`（surrogate pair）来表示。

### 复合类型：元组和数组

**元组（Tuple）**——可以放不同类型的值：

```rust
let tup: (i32, f64, bool) = (42, 3.14, true);
let (x, y, z) = tup;         // 解构
println!("{}", tup.0);        // 通过索引访问，从 0 开始
```

Java 没有原生的元组类型。一般用 `record`（Java 14+）或者自定义类来模拟：

```java
// Java 的等价做法
record Point(int x, double y, boolean z) {}
var p = new Point(42, 3.14, true);
```

Rust 的元组是值类型，存在栈上（如果元素都是值类型的话），比 Java 创建一个对象轻量得多。

**数组（Array）**——固定长度、同类型：

```rust
let arr = [1, 2, 3, 4, 5];
let first = arr[0];          // 访问元素
let slice = &arr[1..3];      // 切片，得到 &[2, 3]
```

Rust 数组越界访问会直接 **panic**（类似 Java 抛 `ArrayIndexOutOfBoundsException`，但机制不同——Rust 用的是 panic 机制而不是异常）。

**Java 程序员注意**：Rust 的数组是定长的，不能动态扩容。需要动态数组用 `Vec<T>`，类似 Java 的 `ArrayList`。这个后面集合篇会详细讲。

### 类型转换

Java 有自动类型提升和强制类型转换：

```java
int a = 42;
long b = a;           // 自动提升
double c = a;         // 自动提升
int d = (int) 3.14;   // 强制转换
```

Rust **不允许隐式类型转换**，一切都要显式来：

```rust
let a: i32 = 42;
// let b: i64 = a;          // 编译错误！
let b: i64 = a as i64;      // 用 as 关键字显式转换

// 更推荐的方式：用 From / Into trait（后面 trait 篇会讲）
let a: i32 = 42;
let b: i64 = i64::from(a);  // 等价于 a as i64，但更安全
```

`as` 转换是底层的位模式转换（类似 Java 的强制转换），可能会丢数据。`From` / `Into` 是安全的转换 trait，只能用于不会丢数据的转换。

## 四、函数

### 基本语法

```java
// Java
public static int add(int a, int b) {
    return a + b;
}
```

```rust
// Rust
fn add(a: i32, b: i32) -> i32 {
    a + b      // 没有 return，没有分号
}
```

区别很明显：

1. 用 `fn` 关键字而不是访问修饰符 + 返回类型。
2. 参数必须标注类型（Java 可以省略，因为方法签名里有）。
3. 返回类型用 `->` 标注，放在参数列表后面。
4. **函数体最后一个表达式就是返回值**，不需要 `return` 关键字，但也不能有分号。加了分号就变成语句，返回值变成 `()`（类似 void）。

```rust
// 这两种写法等价：
fn add_v1(a: i32, b: i32) -> i32 {
    a + b          // 表达式，作为返回值
}

fn add_v2(a: i32, b: i32) -> i32 {
    return a + b;  // 用 return 也行，但不推荐
}
```

### 函数是一等公民

在 Java 里，方法不是"东西"，你不能把方法赋值给变量。Java 8 引入了方法引用和 Lambda，但本质上它们需要依托于函数式接口。

Rust 的函数是一等公民，可以像值一样传递：

```rust
fn add_one(x: i32) -> i32 {
    x + 1
}

fn apply(fn_ptr: fn(i32) -> i32, value: i32) -> i32 {
    fn_ptr(value)
}

fn main() {
    let result = apply(add_one, 5);   // 把函数作为参数传递
    println!("{result}");              // 输出 6
}
```

```java
// Java 的等价做法
import java.util.function.IntUnaryOperator;

class Main {
    static int addOne(int x) { return x + 1; }

    static int apply(IntUnaryOperator fnPtr, int value) {
        return fnPtr.applyAsInt(value);
    }

    public static void main(String[] args) {
        int result = apply(Main::addOne, 5);   // 方法引用
    }
}
```

Rust 的函数指针类型是 `fn`（小写），和定义函数的 `fn` 关键字同名但含义不同。Java 需要定义一个函数式接口（如 `IntUnaryOperator`），Rust 直接用 `fn` 类型。

### 发散函数（Diverging Function）

Rust 有一个 Java 没有的概念——发散函数，返回类型是 `!`（读作 "never"）：

```rust
fn die(message: &str) -> ! {
    panic!("{}", message);   // panic 永远不会返回
}
```

`!` 表示这个函数永远不会正常返回。这在类型系统层面是有意义的——它可以被用在任何需要返回值的地方，因为"永远不会返回值"和"返回任何类型"不矛盾。

Java 里类似的情况（比如 `System.exit()` 或无限循环的方法）没有类型系统层面的支持，编译器不会做特殊处理。

### 函数重载

**Java 程序员注意**：Rust **不支持函数重载**。你不能定义两个同名但参数不同的函数：

```rust
// 编译错误！Rust 不支持函数重载
fn print(value: i32) { println!("{value}"); }
fn print(value: &str) { println!("{value}"); }
```

Rust 用 **trait 方法** 来实现类似的效果（后面 trait 篇会详细讲）。标准库里你看到的 `println!` 能接受不同类型，是因为它是宏，不是函数重载。

## 五、控制流

### if 表达式

Rust 的 `if` 是**表达式**（有返回值），Java 的 `if` 是**语句**：

```java
// Java：if 是语句，不能用在赋值右边
int value;
if (condition) {
    value = 5;
} else {
    value = 6;
}

// 或者用三元运算符
int value = condition ? 5 : 6;
```

```rust
// Rust：if 是表达式，可以直接赋值
let value = if condition { 5 } else { 6 };
```

注意 Rust 的 `if` 条件**不需要括号**，但**大括号不能省**。而且条件必须是 `bool` 类型，不能像 C/C++ 那样用整数：

```rust
// Rust
if x > 0 {
    println!("positive");
} else if x == 0 {
    println!("zero");
} else {
    println!("negative");
}

// if x { ... }   // 编译错误！x 不是 bool 类型
```

### 循环

Rust 有三种循环方式：

```rust
// 1. loop —— 无限循环，类似 Java 的 while(true)
loop {
    println!("again!");
    break;   // 跳出循环
}

// loop 可以有返回值
let mut counter = 0;
let result = loop {
    counter += 1;
    if counter == 10 {
        break counter * 2;   // break 可以带返回值！
    }
};
// result == 20
```

```rust
// 2. while —— 和 Java 基本一样
while condition {
    // ...
}
```

```rust
// 3. for —— 最好用的循环，类似 Java 的 for-each
let arr = [10, 20, 30, 40, 50];
for element in arr {
    println!("value: {element}");
}

// 用 range 实现类似传统 for 循环的效果
for i in 0..5 {           // 0, 1, 2, 3, 4（不含 5）
    println!("{i}");
}

for i in 0..=5 {          // 0, 1, 2, 3, 4, 5（包含 5）
    println!("{i}");
}
```

```java
// Java 的等价写法
for (int i = 0; i < 5; i++) {     // 对应 Rust 的 for i in 0..5
    System.out.println(i);
}

for (int element : arr) {          // 对应 Rust 的 for element in arr
    System.out.println(element);
}
```

**Java 程序员注意**：Rust 没有传统的 `for (init; condition; update)` 语法，全部用 `for ... in ...` 加 range 来替代。初学可能不习惯，用久了会发现这种写法更清晰，也更不容易出 off-by-one 错误。

### match 简介

`match` 是 Rust 里最重要的控制流工具之一，表面上有点像 Java 的 `switch`，但它做的是模式匹配。这里先给个印象，后面有专门的章节详细讲：

```rust
let number = 13;

match number {
    1 => println!("one"),
    2..=12 => println!("2 to 12"),
    13 | 14 => println!("thirteen or fourteen"),
    _ => println!("something else"),
}
```

和 Java `switch` 的关键区别：`match` 是**穷尽的**（exhaustive），必须处理所有可能的情况，否则编译不过。这个特性在配合枚举使用时特别强大。

## 六、格式化输出

Java 里用 `System.out.println` 和 `String.format`，Rust 用宏：

```rust
// 打印到标准输出
println!("Hello, {}!", "world");           // {} 是占位符
println!("{name} is {age} years old", name = "Alice", age = 30);

// 格式化数字
println!("{:?}", vec![1, 2, 3]);           // Debug 格式
println!("{:#?}", vec![1, 2, 3]);          // 带缩进的 Debug 格式
println!("{:b}", 42);                      // 二进制：101010
println!("{:x}", 255);                     // 十六进制：ff
println!("{:X}", 255);                     // 大写十六进制：FF
println!("{:.2}", 3.14159);               // 保留两位小数：3.14
println!("{:>10}", "right");              // 右对齐，宽度 10
println!("{:<10}", "left");               // 左对齐，宽度 10

// 格式化到字符串
let s = format!("Hello, {}!", "world");    // 类似 Java 的 String.format
```

```java
// Java 的等价写法
System.out.println("Hello, " + "world" + "!");
System.out.printf("Hello, %s!%n", "world");
String s = String.format("Hello, %s!", "world");
```

**Java 程序员注意**：`println!` 和 `format!` 都是宏（注意感叹号 `!`），它们在编译期做类型检查，比 Java 的 `printf` 更安全——类型不匹配会在编译期报错，而不是运行时抛 `IllegalFormatConversionException`。

## 七、Java 程序员常见坑点总结

### 1. 忘了 mut

```rust
let s = String::from("hello");
s.push_str(", world");   // 错误！s 不可变
// 正确写法：let mut s = String::from("hello");
```

Java 里对象默认可修改，Rust 里变量默认不可修改。这是最大的思维转换之一。

### 2. 字符串不是你想的那样

```rust
// Rust 的字符串有两种形态，后面会详细讲
let s1 = "hello";                    // &str，字符串切片（类似 Java 的字符串字面量）
let s2 = String::from("hello");      // String，拥有所有权的字符串（类似 Java 的 String 对象）
```

### 3. 没有隐式类型转换

```rust
let x: i32 = 42;
let y: f64 = x as f64;   // 必须显式转换
// 不能 let y: f64 = x;
```

### 4. 数组越界是 panic，不是异常

```rust
let arr = [1, 2, 3];
// let x = arr[10];   // 直接 panic，程序崩溃
// 安全做法：
if let Some(val) = arr.get(10) {
    println!("{val}");
} else {
    println!("index out of bounds");
}
```

### 5. if 条件必须是 bool

```rust
let x = 1;
// if x { ... }        // 错误！
if x != 0 { ... }     // 正确
```

### 6. 分号会改变返回值

```rust
fn foo() -> i32 {
    42       // 返回 42
}

fn bar() -> i32 {
    42;      // 返回 ()，编译错误！
}
```

## 小结

第一篇先把能马上用起来的基础铺好：

- **工具链**：rustup 管版本，cargo 管构建和依赖，对应 Java 的 JDK + Maven。
- **变量默认不可变**：和 Java 相反，需要 `mut` 才能修改。
- **类型更丰富**：整数区分有符号/无符号，char 是 4 字节 Unicode。
- **没有隐式类型转换**：一切显式来。
- **函数是表达式导向的**：最后一行不带分号就是返回值。
- **if 是表达式**：有返回值，条件必须是 bool。
- **for 循环用迭代器**：没有传统 C 风格 for 循环。

这些概念过一遍之后，下一篇就可以进入 **所有权与生命周期**。那一章会更别扭，但也是 Rust 和 Java 真正分道扬镳的地方。
