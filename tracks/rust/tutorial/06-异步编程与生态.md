# 写给 Java 程序员的 Rust 入门（六）：异步编程与生态

> 本文是系列第六篇。异步编程是现代 Rust 的核心能力，Rust 的生态也已经有大量成熟的 crate 可以替代 Java 生态的常用库。这一篇覆盖 async/await、常用 crate，以及一个完整的实战示例。

## 一、异步编程基础

### 为什么需要异步？

Java 程序员熟悉多线程模型：每个请求一个线程，线程阻塞等待 IO。这在请求量大时会导致线程数爆炸。

Java 21 引入了虚拟线程（Project Loom）。Rust 1.0 发布时还没有今天这套 async/await；`async`/`.await` 是 Rust 1.39 才稳定的。现在的模型是：标准库定义 `Future`，具体怎么调度交给 tokio、async-std 这类运行时。

```rust
// async fn 会生成一个实现 Future 的状态机
// 不被 .await 或运行时 poll，它就不会真正执行
async fn fetch_data() -> String {
    // 异步操作
    "data".to_string()
}
```

```java
// Java 21+ 虚拟线程
Thread.startVirtualThread(() -> {
    // 异步操作
});
```

### Future trait

Rust 的异步核心是 `Future` trait：

```rust
// Future 的定义（简化版）
trait Future {
    type Output;
    fn poll(self: Pin<&mut Self>, cx: &mut Context<'_>) -> Poll<Self::Output>;
}

enum Poll<T> {
    Ready(T),    // 完成了
    Pending,     // 还没完成，稍后再试
}
```

```java
// Java 的 CompletableFuture
CompletableFuture<String> future = CompletableFuture.supplyAsync(() -> "data");
future.thenApply(s -> s.toUpperCase());
```

**关键区别**：
- Java 的 `CompletableFuture` 是运行时对象，创建就有开销
- Rust 的 `Future` 是编译期状态机，不 poll 就不执行（惰性求值）
- Rust 需要运行时（runtime）来驱动 Future，Java 有 JVM 内置的线程池

### async/await 语法

```rust
// async 函数返回 Future
async fn fetch_user(id: u64) -> User {
    // 模拟异步操作
    User { id, name: "Alice".to_string() }
}

// await 等待 Future 完成
async fn main() {
    let user = fetch_user(1).await;
    println!("User: {}", user.name);
}
```

```java
// Java 等价（使用 CompletableFuture）
CompletableFuture<User> fetchUser(long id) {
    return CompletableFuture.supplyAsync(() -> new User(id, "Alice"));
}

void main() throws Exception {
    User user = fetchUser(1).get();  // 阻塞等待
    System.out.println("User: " + user.name);
}
```

**关键区别**：
- Rust 的 `.await` 不阻塞线程，只是暂停当前 Future
- Java 的 `.get()` 阻塞当前线程
- Rust 需要 `async` 运行时（如 tokio），Java 有 JVM 内置支持

### 异步运行时：tokio

Rust 标准库只提供 `Future` trait，实际的异步执行需要运行时。最流行的是 `tokio`：

```toml
# Cargo.toml
[dependencies]
tokio = { version = "1", features = ["full"] }
```

`features = ["full"]` 学习和 demo 很省事，但真实项目里会多编进不少能力。内部服务通常可以先这么写，库代码或体积敏感的二进制建议按需开 `rt-multi-thread`、`macros`、`time`、`net` 等 feature。

```rust
use tokio;

#[tokio::main]
async fn main() {
    // 异步入口
    let result = some_async_task().await;
    println!("Result: {:?}", result);
}

async fn some_async_task() -> String {
    tokio::time::sleep(std::time::Duration::from_secs(1)).await;
    "done".to_string()
}
```

```java
// Java 等价
public class Main {
    public static void main(String[] args) throws Exception {
        CompletableFuture<String> future = someAsyncTask();
        String result = future.get();
        System.out.println("Result: " + result);
    }

    static CompletableFuture<String> someAsyncTask() {
        return CompletableFuture.supplyAsync(() -> {
            Thread.sleep(1000);
            return "done";
        });
    }
}
```

### 并发执行

```rust
use tokio;

async fn fetch_user() -> String {
    tokio::time::sleep(std::time::Duration::from_millis(100)).await;
    "user data".to_string()
}

async fn fetch_orders() -> Vec<String> {
    tokio::time::sleep(std::time::Duration::from_millis(150)).await;
    vec!["order1".to_string(), "order2".to_string()]
}

// 串行执行（慢）
async fn serial() -> (String, Vec<String>) {
    let user = fetch_user().await;
    let orders = fetch_orders().await;
    (user, orders)
}

// 并发执行（快）
async fn concurrent() -> (String, Vec<String>) {
    let (user, orders) = tokio::join!(fetch_user(), fetch_orders());
    (user, orders)
}
```

```java
// Java 等价
CompletableFuture<String> userFuture = fetchUser();
CompletableFuture<List<String>> ordersFuture = fetchOrders();

// 等待两个都完成
CompletableFuture.allOf(userFuture, ordersFuture).join();
String user = userFuture.get();
List<String> orders = ordersFuture.get();
```

**tokio 常用并发工具**：

| tokio | Java 等价 | 说明 |
|-------|-----------|------|
| `tokio::join!` | `CompletableFuture.allOf` | 等待多个 Future |
| `tokio::try_join!` | 无直接对应 | 等待多个，任一失败则返回 |
| `tokio::select!` | 无直接对应 | 等待多个，返回第一个完成的 |
| `tokio::spawn` | `ExecutorService.submit` | 创建新任务 |
| `tokio::time::sleep` | `Thread.sleep` | 异步等待 |

### `tokio::select!`：等待最先完成的任务

`join!` 是“全部都要完成”，`select!` 是“谁先完成就先处理谁”。它常用于超时、取消、同时监听多个 channel。

```rust
use tokio::time::{sleep, Duration};

async fn fetch_from_cache() -> Option<String> {
    sleep(Duration::from_millis(50)).await;
    Some("cache-data".to_string())
}

async fn fetch_from_database() -> String {
    sleep(Duration::from_millis(200)).await;
    "db-data".to_string()
}

#[tokio::main]
async fn main() {
    tokio::select! {
        cached = fetch_from_cache() => {
            println!("cache wins: {:?}", cached);
        }
        data = fetch_from_database() => {
            println!("database wins: {}", data);
        }
        _ = sleep(Duration::from_millis(100)) => {
            println!("timeout");
        }
    }
}
```

**Java 程序员注意**：`select!` 类似“多个 `CompletableFuture` 谁先完成就处理谁”，但它还能直接和 channel、sleep、取消信号组合。没有被选中的分支会被取消，也就是对应的 future 会被 drop。

### 异步中的所有权

异步代码中的所有权规则和同步一样，但有一些特殊情况：

```rust
use std::sync::Arc;
use tokio::sync::Mutex;

// 跨 .await 共享可变状态
async fn process() {
    let data = Arc::new(Mutex::new(vec![]));
    
    let data1 = Arc::clone(&data);
    let data2 = Arc::clone(&data);
    
    let t1 = tokio::spawn(async move {
        let mut d = data1.lock().await;
        d.push(1);
    });
    
    let t2 = tokio::spawn(async move {
        let mut d = data2.lock().await;
        d.push(2);
    });
    
    t1.await.unwrap();
    t2.await.unwrap();
    
    println!("{:?}", data.lock().await);  // [1, 2] 或 [2, 1]
}
```

```java
// Java 等价
List<Integer> data = new ArrayList<>();
// 需要 synchronized 或 ConcurrentLinkedQueue
```

### `tokio::spawn` 的 `'static` 要求

`tokio::spawn` 创建的任务可能在当前函数返回后继续运行，所以任务里捕获的数据必须满足 `'static`：任务不能借用当前栈帧里的临时引用。

下面代码无法编译：

```rust
use tokio::task;

async fn run() {
    let name = String::from("Alice");

    // 编译错误：async block may outlive the current function
    // task::spawn(async {
    //     println!("{name}");
    // });
}
```

正确做法是用 `async move` 把所有权移动进任务：

```rust
use tokio::task;

async fn run() {
    let name = String::from("Alice");

    let handle = task::spawn(async move {
        println!("{name}");
    });

    handle.await.unwrap();
}
```

如果多个任务共享数据，用 `Arc`：

```rust
use std::sync::Arc;
use tokio::task;

async fn run() {
    let config = Arc::new(String::from("production"));

    let config_for_task = Arc::clone(&config);
    let handle = task::spawn(async move {
        println!("config = {config_for_task}");
    });

    handle.await.unwrap();
}
```

**Java 程序员注意**：这和 Java lambda 捕获局部变量不一样。Java 捕获引用，由 GC 保证对象还活着；Rust 没有 GC，所以跨任务边界要么移动所有权，要么用 `Arc` 表达共享所有权。

`tokio::spawn` 还有一个常见报错：`future cannot be sent between threads safely`。多线程 tokio 运行时可能把任务从一个 worker 线程挪到另一个 worker 线程，所以这个 Future 必须是 `Send`。真正的判断点不是“函数里有没有非 Send 类型”，而是：**有没有非 Send 的值跨 `.await` 还活着**。

```rust
use std::rc::Rc;

async fn bad() {
    let value = Rc::new(1);
    tokio::time::sleep(std::time::Duration::from_millis(1)).await;
    println!("{value}");
}
```

`Rc` 不是 `Send`，而且它跨过了 `.await`。改法通常是用 `Arc`，或者把非 `Send` 值的作用域缩短到 `.await` 之前。

### 不要在 async 里长时间持有 `std::sync::Mutex`

同步代码常用 `std::sync::Mutex`。异步代码里要特别小心：如果在持有 `std::sync::MutexGuard` 时 `.await`，可能阻塞运行时线程，甚至让 future 变成不能 `Send`，导致 `tokio::spawn` 编译失败。

反例：

```rust
use std::sync::{Arc, Mutex};

async fn save_to_database(value: usize) {
    // 模拟异步 IO
}

async fn bad(data: Arc<Mutex<Vec<usize>>>) {
    let mut guard = data.lock().unwrap();
    guard.push(1);

    // 不要跨 .await 持有 std::sync::MutexGuard
    save_to_database(guard.len()).await;
}
```

更好的做法是缩短锁作用域，在 `.await` 前释放锁：

```rust
use std::sync::{Arc, Mutex};

async fn save_to_database(value: usize) {
    // 模拟异步 IO
}

async fn good(data: Arc<Mutex<Vec<usize>>>) {
    let len = {
        let mut guard = data.lock().unwrap();
        guard.push(1);
        guard.len()
    };

    save_to_database(len).await;
}
```

如果确实需要异步等待锁，用 `tokio::sync::Mutex`：

```rust
use std::sync::Arc;
use tokio::sync::Mutex;

async fn update(data: Arc<Mutex<Vec<usize>>>) {
    let mut guard = data.lock().await;
    guard.push(1);
}
```

但即使用 `tokio::sync::Mutex`，也不要把锁持有时间拖得很长。锁里只做内存状态修改，网络 IO、数据库 IO、慢计算尽量放到锁外。

**Java 程序员注意**：这和“不要在 `synchronized` 块里做 RPC/数据库调用”是同一个原则。区别是 Rust async 运行时的工作线程更少，阻塞一个工作线程的代价可能更明显。

### 阻塞任务放进 spawn_blocking

async 代码里不要直接做长时间阻塞或重 CPU 计算，比如压缩大文件、同步读写磁盘、大量 JSON/图片处理。它们会占住 tokio worker，让其他请求也跟着慢。

```rust
let result = tokio::task::spawn_blocking(|| {
    // 同步阻塞或 CPU 密集任务
    expensive_calculation()
})
.await
.unwrap();
```

从 Java 虚拟线程转过来时，这一点尤其容易误判。Rust async 不是“每个任务一个便宜线程”，它更像少量 worker 轮流 poll 很多 Future。阻塞 worker 就是在堵车道。

### Send 和 Sync trait

Rust 用 `Send` 和 `Sync` trait 在编译期保证线程安全：

- `Send`：类型可以跨线程转移所有权
- `Sync`：类型可以跨线程共享引用（`&T` 可以发送到其他线程）

```rust
// 大多数类型都是 Send + Sync
// 例外：Rc<T>、RefCell<T>（运行时借用检查，不能跨线程）
// Cell<T>、UnsafeCell<T> 也不是 Sync

// 跨线程发送
fn send_to_thread<T: Send>(data: T) {
    std::thread::spawn(move || {
        println!("{:?}", data);
    });
}

// 跨线程共享
fn share_across_threads<T: Sync>(data: &T) {
    // 可以在多个线程中使用 &data
}
```

```java
// Java 没有编译期线程安全检查
// 需要程序员自己保证
```

**Java 程序员注意**：Rust 的 `Send`/`Sync` 是编译期保证，Java 的线程安全靠程序员自觉（或 `@ThreadSafe` 注解，但不强制）。

### 序列化：serde

`serde` 是 Rust 的序列化框架，类似 Jackson/Gson：

```toml
[dependencies]
serde = { version = "1.0", features = ["derive"] }
serde_json = "1.0"
```

```rust
use serde::{Serialize, Deserialize};

#[derive(Serialize, Deserialize, Debug)]
struct User {
    id: u64,
    name: String,
    #[serde(skip_serializing_if = "Option::is_none")]
    email: Option<String>,
}

fn main() {
    // 序列化
    let user = User {
        id: 1,
        name: "Alice".to_string(),
        email: Some("alice@example.com".to_string()),
    };
    let json = serde_json::to_string(&user).unwrap();
    println!("{}", json);
    // {"id":1,"name":"Alice","email":"alice@example.com"}

    // 反序列化
    let parsed: User = serde_json::from_str(&json).unwrap();
    println!("{:?}", parsed);
}
```


### HTTP 客户端：reqwest

`reqwest` 是 Rust 最常用的 HTTP 客户端，类似 Java 的 OkHttp/Apache HttpClient：

```toml
[dependencies]
reqwest = { version = "0.12", features = ["json"] }
tokio = { version = "1", features = ["full"] }
serde_json = "1.0"
```

```rust
use reqwest;
use serde_json::Value;

#[tokio::main]
async fn main() -> Result<(), reqwest::Error> {
    // GET 请求
    let resp = reqwest::get("https://api.example.com/users")
        .await?
        .json::<Vec<Value>>()
        .await?;
    
    for user in resp {
        println!("{:?}", user);
    }

    // POST 请求
    let client = reqwest::Client::new();
    let body = serde_json::json!({
        "name": "Alice",
        "age": 30
    });
    
    let resp = client.post("https://api.example.com/users")
        .json(&body)
        .send()
        .await?
        .json::<Value>()
        .await?;
    
    println!("{:?}", resp);
    Ok(())
}
```

### 异步运行时：tokio

前面已经介绍了 tokio 的基础用法。补充一些高级特性：

```rust
use tokio;
use tokio::sync::{mpsc, oneshot, RwLock};
use std::sync::Arc;

// Channel（类似 Java 的 BlockingQueue）
#[tokio::main]
async fn main() {
    let (tx, mut rx) = mpsc::channel(32);  // 有界 channel
    
    tokio::spawn(async move {
        tx.send("hello").await.unwrap();
    });
    
    let msg = rx.recv().await.unwrap();
    println!("Received: {}", msg);
}

// 一次性 channel
let (tx, rx) = oneshot::channel();
tokio::spawn(async move {
    tx.send("done").unwrap();
});
let result = rx.await.unwrap();

// RwLock（读写锁）
let data = Arc::new(RwLock::new(0));
let data_clone = Arc::clone(&data);

// 读锁（多个可以同时持有）
let read_guard = data.read().await;
println!("Value: {}", *read_guard);
drop(read_guard);

// 写锁（独占）
let mut write_guard = data.write().await;
*write_guard = 42;
```

### 错误处理：anyhow + thiserror

前面已经介绍过，这里补充完整示例：

```toml
[dependencies]

```

```rust
// 库代码：定义具体错误类型
use thiserror::Error;

#[derive(Error, Debug)]
enum MyLibError {
    #[error("Database error: {0}")]
    Database(#[from] sqlx::Error),
    
    #[error("Not found: {0}")]
    NotFound(String),
    
    #[error("Invalid input: {0}")]
    InvalidInput(String),
}

// 应用代码：用 anyhow 简化处理
use anyhow::{Context, Result};

async fn get_user(id: u64) -> Result<User> {
    let user = db::query_user(id)
        .await
        .context("Failed to query user from database")?;
    
    if user.is_none() {
        anyhow::bail!("User {} not found", id);
    }
    
    Ok(user.unwrap())
}

#[tokio::main]
async fn main() -> Result<()> {
    match get_user(1).await {
        Ok(user) => println!("Found: {:?}", user),
        Err(e) => {
            eprintln!("Error: {:?}", e);
            // 可以打印完整错误链
            for cause in e.chain() {
                eprintln!("Caused by: {}", cause);
            }
        }
    }
    Ok(())
}
```

### 数据库：sqlx

```toml
[dependencies]
sqlx = { version = "0.8", features = ["runtime-tokio-rustls", "postgres", "mysql", "sqlite"] }
tokio = { version = "1", features = ["full"] }
```

```rust
use sqlx::{PgPool, FromRow};

#[derive(FromRow, Debug)]
struct User {
    id: i64,
    name: String,
    email: String,
}

#[tokio::main]
async fn main() -> Result<(), sqlx::Error> {
    // 连接数据库
    let pool = PgPool::connect("postgres://user:pass@localhost/db").await?;
    
    // 查询
    let users: Vec<User> = sqlx::query_as("SELECT * FROM users WHERE active = $1")
        .bind(true)
        .fetch_all(&pool)
        .await?;
    
    for user in users {
        println!("{:?}", user);
    }
    
    // 插入

        .fetch_one(&pool)
        .await?;
    
    println!("Inserted user with id: {}", id.0);
    
    Ok(())
}
```

## 三、实战示例：REST API

让我们用 Rust 构建一个简单的 REST API，对比 Java 的 Spring Boot。

### Cargo.toml

```toml
[package]
name = "rust-api"
version = "0.1.0"
edition = "2021"

[dependencies]
axum = "0.8"
tokio = { version = "1", features = ["full"] }
serde = { version = "1.0", features = ["derive"] }
serde_json = "1.0"
tower-http = { version = "0.5", features = ["cors", "trace"] }
tracing = "0.1"
tracing-subscriber = "0.3"
```

### 代码

```rust
use axum::{
    extract::{Path, State},
    http::StatusCode,
    response::Json,
    routing::{get, post},
    Router,
};
use serde::{Deserialize, Serialize};
use std::sync::Arc;
use tokio::sync::RwLock;
use tower_http::{cors::CorsLayer, trace::TraceLayer};

// 数据模型
#[derive(Serialize, Deserialize, Clone, Debug)]
struct User {
    id: u64,
    name: String,
    email: String,
}

// 应用状态（类似 Spring 的 @Autowired Bean）
struct AppState {
    users: RwLock<Vec<User>>,
}

// 路由处理器
async fn list_users(State(state): State<Arc<AppState>>) -> Json<Vec<User>> {
    let users = state.users.read().await;
    Json(users.clone())
}

async fn get_user(
    Path(id): Path<u64>,
    State(state): State<Arc<AppState>>,
) -> Result<Json<User>, StatusCode> {
    let users = state.users.read().await;
    users
        .iter()
        .find(|u| u.id == id)
        .cloned()
        .map(Json)
        .ok_or(StatusCode::NOT_FOUND)
}

#[derive(Deserialize)]
struct CreateUser {
    name: String,
    email: String,
}

async fn create_user(
    State(state): State<Arc<AppState>>,
    Json(input): Json<CreateUser>,
) -> (StatusCode, Json<User>) {
    let mut users = state.users.write().await;
    let id = users.len() as u64 + 1;
    let user = User {
        id,
        name: input.name,
        email: input.email,
    };
    users.push(user.clone());
    (StatusCode::CREATED, Json(user))
}

#[tokio::main]
async fn main() {
    // 初始化日志
    tracing_subscriber::fmt::init();

    // 初始化状态
    let state = Arc::new(AppState {
        users: RwLock::new(vec![]),
    });

    // 构建路由
    let app = Router::new()
        .route("/users", get(list_users).post(create_user))
        .route("/users/{id}", get(get_user))
        .layer(CorsLayer::permissive())
        .layer(TraceLayer::new_for_http())
        .with_state(state);

    // 启动服务器
    let listener = tokio::net::TcpListener::bind("0.0.0.0:3000")
        .await
        .unwrap();
    
    tracing::info!("Server running on port 3000");
    axum::serve(listener, app).await.unwrap();
}
```

axum 0.8 的路径参数写成 `/{id}`。如果你看旧教程里的 `/:id`，那是 0.7 时代的写法，直接搬到新版本会踩坑。

## 五、Java 程序员注意事项总结

### 异步编程

- Rust 的 `async/await` 编译成状态机，调度由运行时驱动；Java 的虚拟线程是 JVM 运行时调度。
- Rust 需要运行时（tokio），Java 有 JVM 内置支持。
- `Send` 和 `Sync` trait 在编译期保证线程安全，Java 靠程序员自觉。
- 异步中的所有权规则不变，但需要 `Arc<Mutex<T>>` 共享可变状态。

### 生态

- Rust 生态已经足够成熟，可以构建生产级应用。
- `serde` 是最常用的 crate，几乎每个项目都用。
- `tokio` 是异步事实标准，类似 Java 的 Spring。
- `axum` 正在成为 Web 框架的首选，类似 Spring Boot。
- `sqlx` 提供编译期 SQL 检查，比 JPA/MyBatis 更安全。

### 开发体验

- Rust 编译慢，但 `cargo check` 可以快速验证。
- Rust 的错误信息非常友好，编译器是最好的老师。
- Rust 的文档质量很高，`cargo doc --open` 生成本地文档。
- Rust 社区友好，crates.io 生态丰富。

## 小结

这一篇覆盖了 Rust 的异步编程和生态：

- **async/await**：编译期生成状态机，需要运行时驱动。
- **tokio**：最流行的异步运行时，提供并发、channel、定时器等。
- **serde**：序列化框架，类似 Jackson。
- **reqwest**：HTTP 客户端，类似 OkHttp。
- **axum**：Web 框架，类似 Spring Boot。
- **sqlx**：数据库访问，编译期 SQL 检查。
- **thiserror/anyhow**：错误处理，库用 thiserror，应用用 anyhow。

至此，我们已经完成了 Rust 语言核心和生态入门。从环境搭建到异步编程，从基础语法到工程化特性，覆盖了 Java 程序员学习 Rust 需要掌握的核心概念。

如果你已经读到这里，可以继续阅读测试、并发、项目迁移和性能边界几篇，把异步知识放进真实工程场景。Rust 的学习曲线确实陡峭，但一旦掌握，你会发现它带来的安全性和性能提升是值得的。
