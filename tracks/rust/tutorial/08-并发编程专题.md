# 写给 Java 程序员的 Rust 入门（八）：并发编程专题

> 本文是系列第八篇。Java 程序员熟悉 `Thread`、`ExecutorService`、`synchronized`、`volatile`、`BlockingQueue` 和 `CompletableFuture`。Rust 也能写多线程程序，但它最大的不同是：很多线程安全问题会在编译期被发现。本篇专门讲同步并发，异步编程可以回看第六篇。

## 一、并发和异步先分清

Java 里经常把“并发”“异步”“多线程”混着说。Rust 里建议先分清：

| 概念 | Rust 常用工具 | Java 对照 |
|------|---------------|-----------|
| OS 线程并发 | `std::thread` | `Thread` |
| 共享状态同步 | `Mutex`、`RwLock`、`Arc` | `synchronized`、`ReentrantLock` |
| 消息传递 | `mpsc` channel | `BlockingQueue` |
| 异步 IO | `async/await`、`tokio` | `CompletableFuture`、虚拟线程、Netty |
| 数据并行 | `rayon` | parallelStream、ForkJoinPool |

这篇主要讲 OS 线程、锁、channel、`Send`/`Sync`。Tokio 里的异步任务不是 OS 线程，虽然它们可能跑在线程池上。

先把边界说清楚：Rust 的类型系统能消灭 data race，但不会自动消灭死锁、饥饿、业务竞态和锁顺序问题。Java 里会死锁的设计，换成 Rust 也照样会死锁，只是“同时无保护读写同一块内存”这类问题更难写出来。

## 二、创建线程

Rust 标准库创建线程：

```rust
use std::thread;

fn main() {
    let handle = thread::spawn(|| {
        println!("hello from child thread");
    });

    println!("hello from main thread");

    handle.join().unwrap();
}
```

对应 Java：

```java
Thread thread = new Thread(() -> {
    System.out.println("hello from child thread");
});
thread.start();
thread.join();
```

`join()` 返回 `Result<T, Box<dyn Any + Send>>`，因为子线程可能 panic：

```rust
use std::thread;

fn main() {
    let handle = thread::spawn(|| {
        panic!("boom");
    });

    let result = handle.join();
    assert!(result.is_err());
}
```

**Java 程序员注意**：Rust 线程 panic 不会自动把整个进程干掉，除非主线程也 panic 或你显式处理成退出。`join().unwrap()` 的含义是：如果子线程 panic，主线程也跟着 panic。

## 三、move 闭包：把所有权交给线程

下面代码无法编译：

```rust
use std::thread;

fn main() {
    let data = vec![1, 2, 3];

    thread::spawn(|| {
        println!("{data:?}");
    });
}
```

原因是新线程可能比 `main` 里的 `data` 活得更久。正确写法是 `move`：

```rust
use std::thread;

fn main() {
    let data = vec![1, 2, 3];

    let handle = thread::spawn(move || {
        println!("{data:?}");
    });

    handle.join().unwrap();
}
```

`move` 把 `data` 的所有权转移进线程。

**Java 程序员注意**：Java lambda 捕获的是 effectively final 变量引用；Rust 的 `move` 捕获的是所有权。线程边界是所有权边界，这一点非常重要。

## 四、线程返回值

线程闭包可以返回值：

```rust
use std::thread;

fn main() {
    let handle = thread::spawn(|| {
        let sum: i32 = (1..=100).sum();
        sum
    });

    let sum = handle.join().unwrap();
    assert_eq!(sum, 5050);
}
```

类似 Java 的 `Future<T>`：

```java
Future<Integer> future = executor.submit(() -> IntStream.rangeClosed(1, 100).sum());
Integer sum = future.get();
```

Rust 标准库没有内置线程池。如果需要线程池或数据并行，常用 `rayon`。

## 五、共享不可变数据：Arc

如果多个线程都要读取同一份数据，需要 `Arc<T>`：

```rust
use std::sync::Arc;
use std::thread;

fn main() {
    let data = Arc::new(vec![1, 2, 3]);
    let mut handles = vec![];

    for _ in 0..3 {
        let data = Arc::clone(&data);
        let handle = thread::spawn(move || {
            println!("len = {}", data.len());
        });
        handles.push(handle);
    }

    for handle in handles {
        handle.join().unwrap();
    }
}
```

`Arc` 是 atomic reference counting，类似线程安全引用计数。

| 类型 | 线程安全 | 使用场景 |
|------|----------|----------|
| `Rc<T>` | 否 | 单线程共享所有权 |
| `Arc<T>` | 是 | 多线程共享所有权 |

**Java 程序员注意**：Java 对象引用天然可以被多个线程复制，但对象本身未必线程安全。Rust 要求你显式用 `Arc` 表达“这个值会被多个线程共享”。

## 六、共享可变数据：Arc<Mutex<T>>

多个线程修改同一个计数器：

```rust
use std::sync::{Arc, Mutex};
use std::thread;

fn main() {
    let counter = Arc::new(Mutex::new(0));
    let mut handles = vec![];

    for _ in 0..10 {
        let counter = Arc::clone(&counter);
        let handle = thread::spawn(move || {
            let mut value = counter.lock().unwrap();
            *value += 1;
        });
        handles.push(handle);
    }

    for handle in handles {
        handle.join().unwrap();
    }

    assert_eq!(*counter.lock().unwrap(), 10);
}
```

对应 Java：

```java
class Counter {
    private int value;

    synchronized void increment() {
        value++;
    }
}
```

`lock()` 返回 `Result<MutexGuard<T>, PoisonError<_>>`。如果某个线程持锁时 panic，锁会被标记为 poisoned。

```rust
let mut value = counter.lock().unwrap();
```

这里 `unwrap()` 表示：如果锁被污染，直接 panic。生产代码可以显式处理：

```rust
let mut value = match counter.lock() {
    Ok(guard) => guard,
    Err(poisoned) => poisoned.into_inner(),
};

*value += 1;
```

**Java 程序员注意**：`MutexGuard` 离开作用域自动释放锁，不需要 `finally { lock.unlock(); }`。这是 RAII 风格。

如果只是计数器，不一定要上 `Mutex`。Rust 有原子类型，对应 Java 的 `AtomicInteger` / `AtomicLong`：

```rust
use std::sync::{
    atomic::{AtomicUsize, Ordering},
    Arc,
};
use std::thread;

let counter = Arc::new(AtomicUsize::new(0));
let mut handles = vec![];

for _ in 0..10 {
    let counter = Arc::clone(&counter);
    handles.push(thread::spawn(move || {
        counter.fetch_add(1, Ordering::Relaxed);
    }));
}

for handle in handles {
    handle.join().unwrap();
}

println!("{}", counter.load(Ordering::Relaxed));
```

计数、标志位这类简单共享状态，原子类型通常比 `Arc<Mutex<usize>>` 更贴近问题本身。

还有一个 Java 程序员很容易踩的坑：`std::sync::Mutex` **不可重入**。Java 的 `synchronized` 和 `ReentrantLock` 允许同一个线程重复拿同一把锁；Rust 标准库的 `Mutex` 不允许。下面代码会把自己锁死：

```rust
let data = Mutex::new(0);
let _a = data.lock().unwrap();
let _b = data.lock().unwrap(); // 同一线程第二次加锁，会阻塞
```

如果程序卡住但 CPU 不高，先查是不是 guard 活得比你以为的更久。最直接的办法是用小作用域提前释放锁。

## 七、缩短锁作用域

不要持锁做耗时操作：

```rust
use std::sync::{Arc, Mutex};

fn snapshot(data: Arc<Mutex<Vec<String>>>) -> Vec<String> {
    let items = {
        let guard = data.lock().unwrap();
        guard.clone()
    };

    // 锁已经释放，后续慢操作不会阻塞其他线程
    items.into_iter().map(|item| item.to_uppercase()).collect()
}
```

反例：

```rust
fn slow_work(data: Arc<Mutex<Vec<String>>>) {
    let guard = data.lock().unwrap();

    // 持锁做慢操作，会阻塞所有等待这个锁的线程
    for item in guard.iter() {
        println!("{item}");
    }
}
```

**Java 程序员注意**：这和不要在 `synchronized` 块里做 IO、RPC、复杂计算是同一个原则。

## 八、读多写少：RwLock

读多写少可以用 `RwLock`：

```rust
use std::sync::{Arc, RwLock};
use std::thread;

fn main() {
    let config = Arc::new(RwLock::new(String::from("v1")));

    let reader_config = Arc::clone(&config);
    let reader = thread::spawn(move || {
        let value = reader_config.read().unwrap();
        println!("config = {value}");
    });

    let writer_config = Arc::clone(&config);
    let writer = thread::spawn(move || {
        let mut value = writer_config.write().unwrap();
        *value = String::from("v2");
    });

    reader.join().unwrap();
    writer.join().unwrap();
}
```

`RwLock` 允许多个读者，或者一个写者。

对应 Java：

```java
ReadWriteLock lock = new ReentrantReadWriteLock();
```

### 全局惰性初始化：OnceLock / LazyLock

Java 里常用 `static final`、静态内部类 holder 或 Spring 单例管理全局对象。Rust 标准库里可以用 `OnceLock` / `LazyLock` 做线程安全的一次性初始化：

```rust
use std::sync::OnceLock;

static CONFIG: OnceLock<String> = OnceLock::new();

fn config() -> &'static str {
    CONFIG.get_or_init(|| {
        std::env::var("APP_ENV").unwrap_or_else(|_| "dev".to_string())
    })
}
```

它适合配置、正则、只读 lookup table 这类初始化一次、之后只读的数据。不要把可变业务状态塞进全局单例；那通常会把测试和并发问题变复杂。

## 九、消息传递：mpsc channel

Rust 标准库提供多生产者、单消费者 channel：

```rust
use std::sync::mpsc;
use std::thread;

fn main() {
    let (tx, rx) = mpsc::channel();

    thread::spawn(move || {
        tx.send("hello".to_string()).unwrap();
    });

    let message = rx.recv().unwrap();
    assert_eq!(message, "hello");
}
```

多生产者：

```rust
use std::sync::mpsc;
use std::thread;

fn main() {
    let (tx, rx) = mpsc::channel();

    for i in 0..3 {
        let tx = tx.clone();
        thread::spawn(move || {
            tx.send(i).unwrap();
        });
    }

    drop(tx);

    let mut values: Vec<i32> = rx.iter().collect();
    values.sort();
    assert_eq!(values, vec![0, 1, 2]);
}
```

`drop(tx)` 很关键。否则接收端会一直等，因为它认为还有发送者可能发送消息。

对应 Java：

```java
BlockingQueue<Integer> queue = new LinkedBlockingQueue<>();
queue.put(1);
Integer value = queue.take();
```

**Java 程序员注意**：channel 发送的是值，通常会发生所有权转移。发送后，发送线程不能再使用这个值，除非发送的是 clone 或 `Arc<T>`。

## 十、有界队列：sync_channel

无界 channel 可能堆积大量消息。有界 channel 可以施加背压：

```rust
use std::sync::mpsc;
use std::thread;
use std::time::Duration;

fn main() {
    let (tx, rx) = mpsc::sync_channel(2);

    let producer = thread::spawn(move || {
        for i in 0..5 {
            tx.send(i).unwrap();
            println!("sent {i}");
        }
    });

    let consumer = thread::spawn(move || {
        for value in rx {
            println!("received {value}");
            thread::sleep(Duration::from_millis(100));
        }
    });

    producer.join().unwrap();
    consumer.join().unwrap();
}
```

当缓冲区满了，`send` 会阻塞。

## 十一、Send 和 Sync

Rust 的线程安全核心是两个 marker trait：

- `Send`：值可以被移动到另一个线程。
- `Sync`：`&T` 可以被多个线程共享。换句话说，如果 `T: Sync`，那么 `&T: Send`。

大多数类型自动实现 `Send` 和 `Sync`：

```rust
fn requires_send<T: Send>(value: T) {
    std::thread::spawn(move || {
        drop(value);
    });
}
```

不能跨线程的典型类型：

| 类型 | 为什么 |
|------|--------|
| `Rc<T>` | 引用计数不是原子的 |
| `RefCell<T>` | 运行时借用计数不是线程安全的 |
| `Cell<T>` | 内部可变性没有同步 |

示例：`Rc<T>` 不能进线程：

```rust
use std::rc::Rc;
use std::thread;

fn main() {
    let data = Rc::new(String::from("hello"));

    // 编译错误：Rc<String> cannot be sent between threads safely
    // thread::spawn(move || {
    //     println!("{data}");
    // });
}
```

改用 `Arc<T>`：

```rust
use std::sync::Arc;
use std::thread;

fn main() {
    let data = Arc::new(String::from("hello"));

    let handle = thread::spawn(move || {
        println!("{data}");
    });

    handle.join().unwrap();
}
```

**Java 程序员注意**：Java 里 `ArrayList` 能传进线程，但不代表安全。Rust 里很多“不安全共享”的情况根本编译不过。

## 十二、scoped threads

普通 `thread::spawn` 要求闭包里的引用通常满足 `'static`，因为线程可能活得很久。`thread::scope` 可以创建作用域线程，让线程借用当前栈上的数据：

```rust
use std::thread;

fn main() {
    let numbers = vec![1, 2, 3, 4];

    thread::scope(|scope| {
        scope.spawn(|| {
            println!("numbers = {numbers:?}");
        });
    });

    println!("main can still use numbers: {numbers:?}");
}
```

作用域结束前，所有子线程都会 join，所以借用是安全的。

这有点像 Java 的结构化并发思想：子任务的生命周期被限制在父作用域内。

## 十三、数据并行：rayon

如果只是想把集合计算并行化，推荐 `rayon`：

```toml
[dependencies]
rayon = "1.10"
```

```rust
use rayon::prelude::*;

fn main() {
    let sum: i32 = (1..=1_000_000)
        .into_par_iter()
        .map(|n| n * 2)
        .sum();

    println!("{sum}");
}
```

对应 Java：

```java
int sum = IntStream.rangeClosed(1, 1_000_000)
    .parallel()
    .map(n -> n * 2)
    .sum();
```

**Java 程序员注意**：`rayon` 适合 CPU 密集型数据并行，不适合异步 IO。HTTP、数据库、网络服务还是优先 tokio。

## 十四、什么时候用什么

| 场景 | 推荐 |
|------|------|
| 多线程读共享配置 | `Arc<T>` 或 `Arc<RwLock<T>>` |
| 多线程修改共享状态 | `Arc<Mutex<T>>` |
| 生产者消费者 | channel |
| CPU 密集集合计算 | `rayon` |
| 高并发网络 IO | `tokio` async |
| 子线程需要借用父栈数据 | `thread::scope` |
| 单线程共享可变结构 | `Rc<RefCell<T>>` |

## 十五、常见坑

### 1. 忘记 move

```rust
let name = String::from("Alice");

// thread::spawn(|| println!("{name}")); // 可能借用不够久
thread::spawn(move || println!("{name}"));
```

### 2. 用 Rc 跨线程

```rust
// Rc<T> 用于单线程
// Arc<T> 用于多线程
```

### 3. 持锁太久

```rust
let result = {
    let mut guard = data.lock().unwrap();
    guard.push(1);
    guard.len()
};

println!("len = {result}");
```

### 4. 在 async 代码里误用阻塞锁

异步代码中优先用 `tokio::sync::Mutex`，并避免跨 `.await` 长时间持锁。同步线程代码用 `std::sync::Mutex`。

### 5. 忘记关闭 channel

如果接收端用 `for value in rx`，要确保所有 `tx` 都被 drop，否则循环不会结束。

## 十六、Java 程序员注意事项总结

### 线程模型

- `thread::spawn` 类似 `new Thread(...).start()`。
- `JoinHandle` 类似 `Future`，但更基础。
- Rust 标准库没有内置 `ExecutorService`，线程池常用第三方库或 `rayon`。

### 共享状态

- 多线程共享所有权用 `Arc<T>`。
- 多线程共享可变状态用 `Arc<Mutex<T>>`。
- 读多写少用 `Arc<RwLock<T>>`。
- 锁通过 guard 自动释放。

### 消息传递

- channel 类似 `BlockingQueue`，但发送通常转移所有权。
- 有界 channel 可以提供背压。
- 关闭发送端才能让接收端自然结束。

### 类型系统

- `Send` 和 `Sync` 是编译期线程安全边界。
- `Rc`、`RefCell` 不能跨线程。
- 很多 Java 运行时才会暴露的数据竞争，Rust 编译期就会拒绝。

## 小结

这一篇讲的是同步并发：

- **thread::spawn**：创建 OS 线程。
- **move closure**：把所有权移动进线程。
- **Arc**：多线程共享所有权。
- **Mutex/RwLock**：共享可变状态。
- **channel**：通过消息传递组织并发。
- **Send/Sync**：编译期线程安全约束。
- **thread::scope**：结构化地借用父作用域数据。
- **rayon**：CPU 密集型数据并行。
