# 写给 Java 程序员的 Rust 入门（五）：工程化特性

> 这是系列第五篇。前几篇讲的是语法和类型，这一篇开始看工程代码里真正会遇到的东西：什么时候上堆，怎么共享数据，模块怎么拆，宏和错误处理该用到什么程度。

## 一、智能指针

Java 里所有对象引用都是"智能"的——GC 帮你管理内存，引用计数、释放这些事你不用管。Rust 没有 GC，但它提供了一组**智能指针**来模拟 Java 程序员习以为常的一些模式：共享所有权、内部可变性等。

### Box\<T\>——堆上分配

`Box<T>` 是最简单的智能指针，把数据放到堆上：

```rust
// 数据默认在栈上
let x = 5;            // 栈上

// 用 Box 放到堆上
let boxed = Box::new(5);   // 堆上
println!("{boxed}");        // 5
```

```java
// Java 里所有对象都在堆上
Integer x = 5;              // 堆上（自动装箱）
```

**Java 程序员注意**：Java 里不用想"放栈上还是堆上"，因为对象都在堆上。Rust 默认在栈上，只有用 `Box` 才上堆。

`Box<T>` 的使用场景：

```rust
// 1. 递归类型（编译期不知道大小的类型）
enum List {
    Cons(i32, Box<List>),   // 用 Box 让编译器知道大小
    Nil,
}

// 没有 Box 的话：
// enum List { Cons(i32, List), Nil }
// 编译错误！List 的大小是无限的（List 里又有 List）

// 使用
let list = List::Cons(1, Box::new(List::Cons(2, Box::new(List::Nil))));
```

```java
// Java 里递归类型不需要特殊处理，因为引用本身就是固定大小的
class ListNode {
    int val;
    ListNode next;    // 引用，固定大小（8 字节）
}
```

```rust
// 2. 大数组避免栈溢出
let big_array = Box::new([0u8; 1_000_000]);   // 1MB，放堆上安全

// 3. trait object（后面会讲）
let animal: Box<dyn Animal> = Box::new(Dog);
```

`Box<T>` 在离开作用域时自动释放堆上的内存（调用 `Drop` trait），和 C++ 的 `unique_ptr` 类似。

### Rc\<T\>——引用计数（单线程）

`Rc<T>`（Reference Counted）允许多个所有者共享同一份数据：

```rust
use std::rc::Rc;

let a = Rc::new(String::from("hello"));
println!("count: {}", Rc::strong_count(&a));   // 1

let b = Rc::clone(&a);    // 引用计数 +1，不是深拷贝！
println!("count: {}", Rc::strong_count(&a));   // 2

let c = Rc::clone(&a);    // 引用计数再 +1
println!("count: {}", Rc::strong_count(&a));   // 3

drop(c);   // 引用计数 -1
println!("count: {}", Rc::strong_count(&a));   // 2

drop(b);   // 引用计数 -1
println!("count: {}", Rc::strong_count(&a));   // 1

drop(a);   // 引用计数归零，堆内存释放
```

```java
// Java 里不需要这个，GC 自动管理
String a = new String("hello");
String b = a;    // 多个引用指向同一对象，GC 自动回收
String c = a;
b = null;
c = null;
// GC 发现没人引用了，自动回收
```

**Java 程序员注意**：`Rc::clone()` 不是深拷贝，只是增加引用计数（类似 Java 里多一个引用指向同一对象）。`Rc<T>` 只能用于**单线程**场景。多线程用 `Arc<T>`。

### Arc\<T\>——原子引用计数（多线程）

`Arc<T>` 是 `Rc<T>` 的线程安全版本：

```rust
use std::sync::Arc;
use std::thread;

let data = Arc::new(vec![1, 2, 3]);

let handles: Vec<_> = (0..3)
    .map(|i| {
        let data = Arc::clone(&data);   // 引用计数 +1
        thread::spawn(move || {
            println!("Thread {i}: {:?}", data);
        })
    })
    .collect();

for handle in handles {
    handle.join().unwrap();
}
```

```java
// Java 里多线程共享对象不需要特殊处理
List<Integer> data = List.of(1, 2, 3);
for (int i = 0; i < 3; i++) {
    new Thread(() -> {
        System.out.println(data);   // 直接捕获引用
    }).start();
}
```

| 类型 | 线程安全 | 引用计数 | 类比 Java |
|------|----------|----------|-----------|
| `Rc<T>` | 否 | 非原子 | GC 管理的共享引用 |
| `Arc<T>` | 是 | 原子 | GC 管理的共享引用（线程安全） |

### RefCell\<T\>——内部可变性

Rust 的借用规则：要么多个只读引用，要么一个可变引用，不能同时有两者。但有时候我们需要在"只读"的外表下偷偷修改数据——这就是**内部可变性**模式。

```rust
use std::cell::RefCell;

// RefCell 允许在不可变引用下修改数据
let data = RefCell::new(vec![1, 2, 3]);

// 借用（不可变）
let borrowed = data.borrow();
println!("{:?}", borrowed);   // [1, 2, 3]
drop(borrowed);   // 释放借用

// 可变借用（虽然 data 本身不是 mut 的）
let mut borrowed_mut = data.borrow_mut();
borrowed_mut.push(4);
drop(borrowed_mut);

println!("{:?}", data.borrow());   // [1, 2, 3, 4]
```

```java
// Java 里，引用天然就可以修改对象内容
List<Integer> data = new ArrayList<>(List.of(1, 2, 3));
data.add(4);   // 不需要任何特殊语法
```

**关键区别**：Rust 的 `RefCell` 在**运行时**检查借用规则（违反则 panic），而普通引用在**编译期**检查。

```rust
// 运行时借用检查——违反规则会 panic
let data = RefCell::new(5);

let borrowed1 = data.borrow();       // 不可变借用
let borrowed2 = data.borrow();       // 另一个不可变借用，OK
// let mut borrowed3 = data.borrow_mut();   // panic！已经有不可变借用了
```

### Rc + RefCell 组合

`Rc<RefCell<T>>` 是单线程下的"多所有权 + 内部可变性"：

```rust
use std::rc::Rc;
use std::cell::RefCell;

let shared_data = Rc::new(RefCell::new(vec![1, 2, 3]));

let a = Rc::clone(&shared_data);
let b = Rc::clone(&shared_data);

// 通过任何一个引用都可以修改数据
a.borrow_mut().push(4);
b.borrow_mut().push(5);

println!("{:?}", shared_data.borrow());   // [1, 2, 3, 4, 5]
```

```java
// Java 里这就是普通的多引用指向同一可变对象
List<Integer> shared = new ArrayList<>(List.of(1, 2, 3));
List<Integer> a = shared;
List<Integer> b = shared;
a.add(4);
b.add(5);
System.out.println(shared);   // [1, 2, 3, 4, 5]
```

### Weak\<T\>——打断 Rc 循环引用

`Rc` 不是 GC，它只会在强引用计数归零时释放。如果两个对象互相持有 `Rc`，计数永远不会归零，内存就泄漏了。Java 的 GC 能处理循环引用，Rust 的引用计数不行。

常见规则是：**子节点强持有父节点需要谨慎，父子双向关系里通常“子强、父弱”或“父强、子弱”只保留一个方向的强引用**。

```rust
use std::cell::RefCell;
use std::rc::{Rc, Weak};

struct Node {
    name: String,
    parent: RefCell<Weak<Node>>,
    children: RefCell<Vec<Rc<Node>>>,
}

let parent = Rc::new(Node {
    name: "parent".into(),
    parent: RefCell::new(Weak::new()),
    children: RefCell::new(vec![]),
});

let child = Rc::new(Node {
    name: "child".into(),
    parent: RefCell::new(Rc::downgrade(&parent)),
    children: RefCell::new(vec![]),
});

parent.children.borrow_mut().push(Rc::clone(&child));

if let Some(parent) = child.parent.borrow().upgrade() {
    println!("{}", parent.name);
}
```

`Weak::upgrade()` 返回 `Option<Rc<T>>`，因为被弱引用指向的对象可能已经释放了。

多线程版本是 `Arc<Mutex<T>>` 或 `Arc<RwLock<T>>`：

```rust
use std::sync::{Arc, Mutex};
use std::thread;

let counter = Arc::new(Mutex::new(0));
let mut handles = vec![];

for _ in 0..10 {
    let counter = Arc::clone(&counter);
    let handle = thread::spawn(move || {
        let mut num = counter.lock().unwrap();   // 获取锁
        *num += 1;
    });   // 锁在 num 离开作用域时自动释放
    handles.push(handle);
}

for handle in handles {
    handle.join().unwrap();
}

println!("Count: {}", *counter.lock().unwrap());   // 10
```

`lock().unwrap()` 里的 `unwrap()` 不是在解业务值，而是在处理**锁中毒**：如果某个线程持有锁时 panic，Rust 会把这个 `Mutex` 标记为 poisoned，提醒你里面的数据可能只改了一半。demo 里直接 `unwrap()` 可以，业务代码里要么记录错误并退出，要么用 `poisoned.into_inner()` 明确接管这个可能不一致的值。

```java
// Java 等价
AtomicInteger counter = new AtomicInteger(0);
for (int i = 0; i < 10; i++) {
    new Thread(() -> counter.incrementAndGet()).start();
}
// 或者用 synchronized
```

### Cell\<T\>——Copy 类型的内部可变性

`Cell<T>` 是 `RefCell<T>` 的简化版，只适用于实现了 `Copy` 的类型（如 `i32`、`bool`）：

```rust
use std::cell::Cell;

let counter = Cell::new(0);
counter.set(counter.get() + 1);   // 不需要 borrow/borrow_mut
println!("{}", counter.get());     // 1
```

### Deref 和自动解引用

你前面已经见过 `&String` 可以传给 `&str`、`&Vec<T>` 可以传给 `&[T]`。这背后是 `Deref` trait 和编译器的 deref coercion：

```rust
fn print_name(name: &str) {
    println!("{name}");
}

let name = String::from("Alice");
print_name(&name);        // &String 自动转成 &str

fn sum(items: &[i32]) -> i32 {
    items.iter().sum()
}

let nums = vec![1, 2, 3];
println!("{}", sum(&nums)); // &Vec<i32> 自动转成 &[i32]
```

这也是为什么函数参数优先写 `&str`、`&[T]`：调用者传 `String`、`Vec<T>` 或切片都方便。

### 智能指针总结

| 类型 | 所有权 | 可变性 | 线程安全 | Java 类比 |
|------|--------|--------|----------|-----------|
| `Box<T>` | 单一 | 可变（需 mut） | 取决于 T | 普通对象引用 |
| `Rc<T>` | 共享 | 不可变 | 否 | GC 共享引用 |
| `Weak<T>` | 不拥有 | 不可变 | 否 | 弱引用 |
| `Arc<T>` | 共享 | 不可变 | 是 | GC 共享引用（线程安全） |
| `RefCell<T>` | 单一 | 内部可变（运行时检查） | 否 | 无直接对应 |
| `Cell<T>` | 单一 | 内部可变（Copy 类型） | 否 | 无直接对应 |
| `Rc<RefCell<T>>` | 共享 | 内部可变 | 否 | GC 共享可变引用 |
| `Arc<Mutex<T>>` | 共享 | 内部可变（加锁） | 是 | synchronized 共享对象 |

## 二、模块化系统

Java 用 `package` 组织代码，用 `import` 引入其他包的类。Rust 的模块系统更复杂，但核心思想类似。

### crate 和 module

```
Java:
  JAR 包 → package → class

Rust:
  crate → module → struct/enum/fn/...
```

- **crate**：一个编译单元，对应 Java 的 JAR 包。`cargo new` 创建的就是一个 crate。
- **module**：crate 内部的代码组织单位，对应 Java 的 `package`。

### 定义模块

```rust
// 单文件内定义模块
mod network {
    pub struct Connection {
        pub host: String,
        pub port: u16,
    }

    impl Connection {
        pub fn new(host: String, port: u16) -> Self {
            Connection { host, port }
        }

        pub fn connect(&self) {
            println!("Connecting to {}:{}", self.host, self.port);
        }
    }

    // 私有函数（模块外不可见）
    fn validate_host(host: &str) -> bool {
        !host.is_empty()
    }
}

fn main() {
    let conn = network::Connection::new(String::from("localhost"), 8080);
    conn.connect();
}
```

```java
// Java 等价
package network;

public class Connection {
    private String host;
    private int port;

    public Connection(String host, int port) { ... }
    public void connect() { ... }

    // Java 没有模块级别的私有方法，只有类级别的 private
    private static boolean validateHost(String host) { ... }
}
```

### 多文件模块

```
src/
├── main.rs          // crate 根
├── network/
│   ├── mod.rs       // network 模块的根
│   └── http.rs      // network::http 子模块
└── utils.rs         // utils 模块
```

```rust
// src/main.rs
mod network;     // 声明 network 模块（编译器会找 network/mod.rs）
mod utils;       // 声明 utils 模块（编译器会找 utils.rs 或 utils/mod.rs）

fn main() {
    network::http::get("https://example.com");
    utils::log("started");
}
```

```rust
// src/network/mod.rs
pub mod http;    // 声明子模块

pub struct Connection { ... }
```

```rust
// src/network/http.rs
pub fn get(url: &str) {
    // ...
}
```

```java
// Java 等价
// src/main/java/com/example/network/http/HttpClient.java
package com.example.network.http;

public class HttpClient {
    public static void get(String url) { ... }
}
```

**Java 程序员注意**：Rust 2018 edition 之后，可以用 `network.rs` 代替 `network/mod.rs`：

```
src/
├── main.rs
├── network.rs        // 代替 network/mod.rs
└── network/
    └── http.rs
```

还有一个和 Java 很不一样的点：**新建了 `.rs` 文件不等于参与编译**。你必须在父模块里写 `mod xxx;`，编译器才会把它纳入模块树。Java 里把类丢进 package 目录，构建工具通常就能扫到；Rust 刻意要求显式声明，避免目录里临时文件被悄悄编进去。

### 可见性规则

| Rust | Java | 说明 |
|------|------|------|
| `pub` | `public` | 公开 |
| 默认（不写） | `private` | 私有（模块内可见） |
| `pub(crate)` | 无直接对应 | 整个 crate 内可见 |
| `pub(super)` | 无直接对应 | 父模块可见 |
| `pub(in path)` | 无直接对应 | 指定路径可见 |
| 无 | `protected` | Rust 没有 protected |
| 无 | 包级访问（default） | Rust 默认是模块级私有 |

```rust
mod outer {
    pub struct User {
        pub name: String,      // 公开字段
        age: u32,              // 私有字段（模块外不可见）
    }

    impl User {
        // 公开的构造函数
        pub fn new(name: String, age: u32) -> User {
            User { name, age }
        }

        // 公开的 getter
        pub fn age(&self) -> u32 {
            self.age
        }

        // 私有方法
        fn validate(&self) -> bool {
            self.age > 0
        }
    }
}
```

```java
// Java 等价
public class User {
    public String name;    // 公开
    private int age;       // 私有

    public User(String name, int age) { ... }
    public int getAge() { return age; }
    private boolean validate() { ... }
}
```

**Java 程序员注意**：Rust 的 struct 字段默认是私有的！即使 struct 是 `pub` 的，字段也需要单独标 `pub`。Java 里字段也默认私有，但大家用 Lombok 的 `@Data` 自动生成 getter/setter。Rust 没有这种约定，需要手动写或者用 derive 宏。

### use 和路径

```rust
// 导入
use std::collections::HashMap;
use std::io::{self, Read, Write};    // 导入多个
use std::fmt::{self as fmt};         // 重命名

// 在函数/模块内使用
fn main() {
    let mut map = HashMap::new();
    map.insert("key", "value");
}
```

```java
// Java
import java.util.HashMap;
import java.util.Map;
```

**关键区别**：Rust 的 `use` 只是创建别名，不会"加载"类（Rust 是静态编译的）。Java 的 `import` 也是类似——只是告诉编译器在哪里找类。

```rust
// 通配导入
use std::collections::*;

// 相对路径
mod outer {
    pub fn foo() {}

    mod inner {
        use super::foo;    // 导入父模块的 foo
        use crate::outer::foo;   // 从 crate 根开始的绝对路径
    }
}

// 重新导出
pub use inner::SomeType;   // 把内部类型暴露到当前模块的公开 API
```


```rust
// 使用外部 crate
use serde::{Serialize, Deserialize};

#[derive(Serialize, Deserialize)]
struct Config {
    host: String,

```

```xml
<!-- Java Maven 等价 -->
<dependency>
    <groupId>com.fasterxml.jackson.core</groupId>
    <artifactId>jackson-databind</artifactId>
    <version>2.15.0</version>
</dependency>
```

### Cargo.lock：可重复构建

`Cargo.toml` 描述依赖范围，`Cargo.lock` 锁定实际解析出来的版本：

```toml
# Cargo.toml
[dependencies]
serde = "1.0"   # 表示 >=1.0.0, <2.0.0
```

`Cargo.lock` 里会记录精确版本，例如：

```toml
[[package]]
name = "serde"
version = "1.0.203"
source = "registry+https://github.com/rust-lang/crates.io-index"
checksum = "..."
```

对应 Java：

| Java | Rust |
|------|------|
| `pom.xml` / `build.gradle` | `Cargo.toml` |
| Maven dependency resolution | Cargo resolver |
| Maven dependency lock 插件 / Gradle lockfile | `Cargo.lock` |
| `mvn dependency:tree` | `cargo tree` |

提交规则：

- **二进制应用**：提交 `Cargo.lock`，保证部署和 CI 使用同一套依赖版本。
- **库 crate**：通常也可以提交 `Cargo.lock`，但发布到 crates.io 时下游不会使用你的 lockfile。
- **workspace**：根目录通常只有一个 `Cargo.lock`。

常用命令：

```bash
# 查看依赖树
cargo tree

# 更新所有允许范围内的依赖版本
cargo update

# 只更新某个依赖
cargo update -p serde
```

**Java 程序员注意**：`Cargo.toml` 里的 `"1.0"` 不是锁死到 `1.0.0`，而是语义化版本范围。真正锁死的是 `Cargo.lock`。

### Feature Flags：可选能力

Rust crate 经常用 feature flags 控制可选功能，类似 Maven profile、optional dependency 和 starter 的组合，但它发生在编译期。

```toml
[dependencies]
serde = { version = "1.0", features = ["derive"] }
tokio = { version = "1", features = ["rt-multi-thread", "macros", "time"] }
reqwest = { version = "0.12", default-features = false, features = ["json", "rustls-tls"] }
```

含义：

- `features = ["derive"]`：启用 serde 的 derive 宏。
- `default-features = false`：关闭 crate 默认功能。
- `features = ["rustls-tls"]`：选择 rustls，而不是默认 TLS 实现。

自己定义 feature：

```toml
[features]
default = ["postgres"]
postgres = ["sqlx/postgres"]
mysql = ["sqlx/mysql"]
metrics = ["dep:metrics"]

[dependencies]
sqlx = { version = "0.8", default-features = false, features = ["runtime-tokio"] }
metrics = { version = "0.24", optional = true }
```

代码里按 feature 条件编译：

```rust
#[cfg(feature = "metrics")]
pub fn record_request() {
    metrics::counter!("request_total").increment(1);
}

#[cfg(not(feature = "metrics"))]
pub fn record_request() {
    // metrics feature 关闭时什么都不做
}
```

构建时启用：

```bash
cargo build --features metrics
cargo test --no-default-features
cargo test --all-features
```

**Java 程序员注意**：feature flags 会改变编译出来的代码，不是运行时配置。不要用 feature 表达“生产/测试环境不同配置”，那应该交给环境变量或配置文件。

### Workspace：Rust 的多模块项目

Java Maven 多模块项目：

```text
platform/
├── pom.xml
├── common/
├── user-service/
└── order-service/
```

Rust 对应用 workspace：

```text
platform/
├── Cargo.toml
├── Cargo.lock
└── crates/
    ├── common/
    ├── user-api/
    └── order-api/
```

根 `Cargo.toml`：

```toml
[workspace]
members = [
    "crates/common",
    "crates/user-api",
    "crates/order-api",
]
resolver = "2"

[workspace.dependencies]
serde = { version = "1.0", features = ["derive"] }
tokio = { version = "1", features = ["rt-multi-thread", "macros"] }
thiserror = "1.0"
```

子 crate 使用 workspace 依赖：

```toml
[package]
name = "user-api"
version = "0.1.0"
edition = "2021"

[dependencies]
serde = { workspace = true }
tokio = { workspace = true }
thiserror = { workspace = true }
common = { path = "../common" }
```

常用命令：

```bash
# 检查整个 workspace
cargo check --workspace

# 测试整个 workspace
cargo test --workspace

# 只运行某个 crate
cargo test -p user-api

# 构建全部 release 包
cargo build --workspace --release
```

**Java 程序员注意**：workspace 共享一个 `Cargo.lock` 和一个 `target/` 目录，依赖版本更容易统一。小项目先用 module 就够了，等多个 crate 真的需要独立编译或复用时再上 workspace。

### 版本管理：Rust 版本和 crate 版本

Rust 项目有两类版本要管：

1. **Rust 工具链版本**：用 `rust-toolchain.toml` 固定。
2. **依赖 crate 版本**：用 `Cargo.toml` 声明范围，用 `Cargo.lock` 锁定结果。

项目级工具链：

```toml
# rust-toolchain.toml
[toolchain]
channel = "1.80.0"
components = ["rustfmt", "clippy"]
profile = "default"
```

crate 自身版本：

```toml
[package]
name = "user-api"
version = "0.1.0"
edition = "2021"
rust-version = "1.80"
```

`rust-version` 表示 MSRV（Minimum Supported Rust Version，最低支持 Rust 版本）。如果你写的是库，建议认真维护它；如果是内部应用，可以简单跟随团队统一工具链。

依赖版本写法：

| 写法 | 含义 |
|------|------|
| `"1.2.3"` | 兼容版本，通常是 `>=1.2.3, <2.0.0` |
| `"~1.2.3"` | patch 级更新，`>=1.2.3, <1.3.0` |
| `"=1.2.3"` | 精确锁定，不推荐常用 |
| `">=1.2, <1.5"` | 手写范围 |
| `{ path = "../common" }` | 本地路径依赖 |
| `{ git = "https://...", rev = "..." }` | Git 依赖 |

**Java 程序员注意**：应用项目通常靠 `Cargo.lock` 保证可重复构建，不需要把所有依赖都写成 `=1.2.3`。过度精确锁版本会让安全升级和兼容升级更痛苦。

## 三、宏（Macros）

Rust 的宏系统负责很多编译期代码生成。Java 有注解处理器（Annotation Processor）和 Lombok，Rust 有宏；能力更大，但调试成本也更高。

### 声明式宏（macro_rules!）

声明式宏基于模式匹配，类似 `match` 但作用于代码：

```rust
// 标准库的 vec! 宏就是一个声明式宏
let v = vec![1, 2, 3];

// 自定义宏
macro_rules! say_hello {
    () => {
        println!("Hello!");
    };
    ($name:expr) => {
        println!("Hello, {}!", $name);
    };
    ($($names:expr),+) => {
        $(println!("Hello, {}!", $names);)+
    };
}

fn main() {
    say_hello!();                    // Hello!
    say_hello!("Alice");             // Hello, Alice!
    say_hello!("Alice", "Bob");      // Hello, Alice! Hello, Bob!
}
```

### 宏的片段分类符

```rust
macro_rules! create_function {
    ($name:ident, $body:block) => {
        fn $name() $body
    };
}

create_function!(greet, {
    println!("Hello!");
});

// 常用分类符：
// ident  → 标识符（变量名、函数名）
// expr   → 表达式
// ty     → 类型
// pat    → 模式
// stmt   → 语句
// block  → 代码块
// tt     → 任意单个 token tree（最灵活）
// item   → 项（函数、struct 等）
```

### 重复模式

```rust
// 类似 HashMap 的初始化宏
macro_rules! map {
    ($($key:expr => $value:expr),* $(,)?) => {
        {
            let mut m = std::collections::HashMap::new();
            $(m.insert($key, $value);)*
            m
        }
    };
}

fn main() {
    let m = map! {
        "Alice" => 25,
        "Bob" => 30,
        "Charlie" => 35,
    };
    println!("{:?}", m);
}
```

```rust
// 类似 assert_eq! 的宏
macro_rules! assert_equal {
    ($left:expr, $right:expr) => {
        let left = $left;
        let right = $right;
        if left != right {
            panic!(
                "assertion failed: {} != {} (at {}:{})",
                left, right, file!(), line!()
            );
        }
    };
}
```

宏里要特别小心“重复求值”。如果直接在 `if $left != $right` 和 `panic!` 里各用一次 `$left`，调用者传 `next_id()` 这种有副作用的表达式时会执行两遍。先 `let` 绑定一次，行为才接近普通函数参数。

### 过程宏（Procedural Macros）

过程宏接收 TokenStream 作为输入，生成新的 TokenStream。你可以先把它理解成"更底层的编译期代码生成"，等真的需要写宏时再深入。

过程宏有三种类型：

#### 1. derive 宏

自动为 struct/enum 实现 trait：

```rust
// 使用 derive 宏（标准库自带的）
#[derive(Debug, Clone, PartialEq)]
struct User {
    name: String,
    age: u32,
}

// 第三方 derive 宏
use serde::{Serialize, Deserialize};

#[derive(Serialize, Deserialize)]
struct Config {
    host: String,
    port: u16,
}
```

```java
// Java 等价：Lombok
@Data
@Builder
class User {
    String name;
    int age;
}

// Jackson 注解
@JsonTypeName("config")
class Config {
    @JsonProperty("host") String host;
    @JsonProperty("port") int port;
}
```

#### 2. 属性宏（Attribute-like macros）

可以作用于任意项，类似 Java 的注解处理器但更强大：

```rust
// 自定义属性宏的使用示例
#[my_attribute(route = "/api/users")]
async fn get_users() -> Json<Vec<User>> {
    // ...
}
```

```java
// Java 等价
@GetMapping("/api/users")
public List<User> getUsers() {
    // ...
}
```

常见的属性宏：
- `#[tokio::main]`：异步入口
- `#[actix_web::get("/")]`：Web 路由
- `#[test]`：测试标记

#### 3. 函数宏（Function-like macros）

像函数一样调用，但操作语法树：

```rust
// 标准库的函数宏
let v = vec![1, 2, 3];
println!("Hello!");
format!("{} + {} = {}", 1, 2, 3);

// 自定义函数宏（需要在单独的 crate 里定义）
// sql!("SELECT * FROM users WHERE id = ?", user_id)
```

### 宏 vs Java 注解处理器

| 对比项 | Rust 宏 | Java 注解处理器 |
|--------|---------|----------------|
| 执行时机 | 编译期 | 编译期 |
| 输入 | TokenStream / 语法树 | 注解 + 元素（Element） |
| 输出 | 修改/生成代码 | 生成新文件 |
| 能力 | 可以修改原始代码 | 只能生成新代码，不能修改原始代码 |
| 类型安全 | 编译期检查 | 编译期检查 |
| 调试 | 困难（`cargo expand` 查看展开） | 相对容易 |
| 生态 | serde, clap, thiserror, tokio | Lombok, MapStruct, Spring |

**Java 程序员注意**：Rust 宏可以**修改原始代码**（比如给 struct 添加字段、方法），而 Java 注解处理器只能**生成新文件**（Lombok 是通过修改编译器内部实现来"修改"原始代码的，属于 hack）。

### cargo expand——查看宏展开

```bash
# 安装
cargo install cargo-expand

# 查看宏展开后的代码
cargo expand
cargo expand my_module
```

这个工具类似 Java 的 "Show bytecode"，可以看到宏展开后的完整代码，调试宏时非常有用。

## 四、错误处理实践

Java 用异常（Exception）处理错误，Rust 用 `Result<T, E>` 和 `?` 运算符。这里重点看项目里怎么分层处理错误，而不是只看语法。

### 错误处理哲学

```
Java：异常是控制流的一部分，try/catch 跳转
Rust：错误是值，Result<T, E> 是返回类型，必须显式处理
```

| 对比项 | Java | Rust |
|--------|------|------|
| 可恢复错误 | 受检异常（Checked Exception） | `Result<T, E>` |
| 不可恢复错误 | `Error`（如 OutOfMemoryError） | `panic!` |
| 强制处理 | 受检异常必须 catch 或 throws | Result 必须处理（否则编译器警告） |
| 错误传播 | throw / throws | `?` 运算符 |

### panic!——不可恢复错误

```rust
// 类似 Java 的 Error（如 OutOfMemoryError）
fn main() {
    panic!("something went terribly wrong");
}

// 数组越界
let v = vec![1, 2, 3];
// println!("{:?}", v[10]);   // panic!

// unwrap 失败
let value: Option<i32> = None;
// value.unwrap();   // panic!
```

```java
// Java 等价
throw new RuntimeException("something went terribly wrong");
```

**何时用 panic**：
- 原型代码、测试
- 确定不会出错的场景（如数组索引已验证）
- 不可恢复的错误（如配置加载失败）

### Result 深入

```rust
use std::fs;
use std::io;

// 返回 Result 的函数
fn read_config(path: &str) -> Result<String, io::Error> {
    fs::read_to_string(path)
}

// 处理 Result
match read_config("config.toml") {
    Ok(content) => println!("Config: {content}"),
    Err(e) => eprintln!("Failed to read config: {e}"),
}
```

### ? 运算符

`?` 是错误传播的语法糖：

```rust
// 不用 ?
fn read_and_parse(path: &str) -> Result<i32, io::Error> {
    let content = match fs::read_to_string(path) {
        Ok(c) => c,
        Err(e) => return Err(e),
    };
    match content.trim().parse::<i32>() {
        Ok(n) => Ok(n),
        Err(e) => Err(io::Error::new(io::ErrorKind::InvalidData, e)),
    }
}

// 用 ? 简化
fn read_and_parse(path: &str) -> Result<i32, Box<dyn std::error::Error>> {
    let content = fs::read_to_string(path)?;
    let number = content.trim().parse::<i32>()?;
    Ok(number)
}
```

`?` 的含义：`Ok(v)` → 取出 `v` 继续执行；`Err(e)` → `return Err(e.into())`。

### 自定义错误类型

```rust
use std::fmt;
use std::io;

// 定义错误枚举
enum AppError {
    NotFound(String),
    IoError(io::Error),
    ParseError(std::num::ParseIntError),
}

// 实现 Display
impl fmt::Display for AppError {
    fn fmt(&self, f: &mut fmt::Formatter<'_>) -> fmt::Result {
        match self {
            AppError::NotFound(path) => write!(f, "Not found: {path}"),
            AppError::IoError(e) => write!(f, "IO error: {e}"),
            AppError::ParseError(e) => write!(f, "Parse error: {e}"),
        }
    }
}

// 实现 Debug
impl fmt::Debug for AppError {
    fn fmt(&self, f: &mut fmt::Formatter<'_>) -> fmt::Result {
        write!(f, "{}", self)
    }
}

// 实现 Error trait
impl std::error::Error for AppError {}

// 实现 From 用于自动转换
impl From<io::Error> for AppError {
    fn from(e: io::Error) -> Self {
        AppError::IoError(e)
    }
}

impl From<std::num::ParseIntError> for AppError {
    fn from(e: std::num::ParseIntError) -> Self {
        AppError::ParseError(e)
    }
}

// 使用
fn read_number(path: &str) -> Result<i32, AppError> {
    let content = fs::read_to_string(path)?;   // io::Error 自动转为 AppError
    let number = content.trim().parse::<i32>()?;  // ParseIntError 自动转为 AppError
    Ok(number)
}
```

```java
// Java 等价
class AppException extends Exception {
    // 自定义异常类
}

class NotFoundException extends AppException { ... }
class ParseException extends AppException { ... }
```

### thiserror crate——简化错误定义

```rust
use thiserror::Error;

#[derive(Error, Debug)]
enum AppError {
    #[error("Not found: {0}")]
    NotFound(String),

    #[error("IO error: {0}")]
    IoError(#[from] io::Error),

    #[error("Parse error: {0}")]
    ParseError(#[from] std::num::ParseIntError),

    #[error("Unknown error")]
    Unknown,
}

// #[from] 自动生成 From 实现
// #[error("...")] 自动实现 Display
```

```java
// Java 等价：Lombok 或手动写
@ToString
class AppException extends Exception { ... }
```

### anyhow crate——应用层错误处理

```rust
use anyhow::{Context, Result};

fn read_config(path: &str) -> Result<String> {
    // anyhow::Result<T> 等价于 Result<T, anyhow::Error>
    let content = fs::read_to_string(path)
        .context(format!("Failed to read config file: {path}"))?;
    Ok(content)
}

fn main() -> Result<()> {
    let config = read_config("config.toml")?;
    println!("{config}");
    Ok(())
}
```

```java
// Java 等价
String readConfig(String path) throws Exception {
    try {
        return Files.readString(Path.of(path));
    } catch (IOException e) {
        throw new Exception("Failed to read config file: " + path, e);
    }
}
```

### 错误处理最佳实践

```
库代码（library）：
  → 定义具体的错误类型（用 thiserror）
  → 返回 Result<T, MyError>

应用代码（application）：
  → 用 anyhow 简化错误传播
  → 在顶层统一处理和展示错误
```

```rust
// 库代码
#[derive(thiserror::Error, Debug)]
pub enum DatabaseError {
    #[error("Connection failed: {0}")]
    Connection(String),
    #[error("Query failed: {0}")]
    Query(String),
}

pub fn query(sql: &str) -> Result<Vec<Row>, DatabaseError> { ... }

// 应用代码
use anyhow::{Context, Result};

fn main() -> Result<()> {
    let rows = db::query("SELECT * FROM users")
        .context("Failed to query users")?;   // DatabaseError 被包装成 anyhow::Error
    println!("Got {} rows", rows.len());
    Ok(())
}
```

## 五、Java 程序员注意事项总结

### 智能指针

- `Box<T>` 把数据放堆上，类似 Java 的 `new`，但离开作用域自动释放。
- `Rc<T>` / `Arc<T>` 实现共享所有权，类似 Java 的多引用指向同一对象。
- `RefCell<T>` 实现内部可变性，运行时检查借用规则（违反则 panic）。
- 多线程共享可变数据用 `Arc<Mutex<T>>`，类似 Java 的 `synchronized`。

### 模块化

- `mod` 定义模块，类似 Java 的 `package`。
- `pub` 控制可见性，默认私有（Java 字段也默认私有）。
- `use` 导入路径，类似 Java 的 `import`。
- 外部依赖在 `Cargo.toml` 声明，类似 Maven 的 `pom.xml`。

### 宏

- 声明式宏（`macro_rules!`）基于模式匹配，类似 `match` 但用于代码。
- 过程宏可以生成和改写代码，但调试成本也高；业务代码不要一上来就写宏。
- `#[derive(...)]` 自动实现 trait，类似 Lombok 的 `@Data`。
- `cargo expand` 查看宏展开后的代码。

### 错误处理

- `Result<T, E>` 替代异常，`?` 运算符简化错误传播。
- 库代码用 `thiserror` 定义错误类型，应用代码用 `anyhow` 简化处理。
- 没有受检异常/运行时异常的区分，所有错误都是值。

## 小结

这一篇覆盖了 Rust 工程化的三大支柱：

- **智能指针**：`Box`、`Rc`/`Arc`、`RefCell`/`Cell` 解决了所有权限制下的共享和可变性问题。
- **模块化系统**：`mod`、`pub`、`use` 组织代码，比 Java 的 package 更灵活。
- **宏**：编译期代码生成，能少写样板代码，但要控制使用边界。
- **错误处理**：`Result` + `?` + `thiserror`/`anyhow`，显式、安全、零成本。
