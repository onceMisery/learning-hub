# 如何在文档里内联真实源码

写教程最怕的一件事：贴出来的代码随着项目重构悄悄失效了，读者照着敲却跑不通。

这个站点提供了 `<SourceRef>`，它**在构建期去读仓库里的真实文件**，把指定行区间或符号所在的代码块渲染出来。
源码改了，文档下次构建就跟着改，不存在「文档和代码对不上」的中间态。

<Callout kind="info" title="和直接贴代码有什么区别">
直接贴代码是一次性快照；`<SourceRef>` 是一份指向真实文件的引用。
代价是路径或符号名变动时这里会报错——但这正是我们想要的效果：让失效立刻可见，而不是悄悄腐烂。
</Callout>

## 按符号名引用

行号会漂移，符号名相对稳定。指定 `symbol` 后，构建脚本会从首个匹配行开始，
一直取到下一个顶格的 `}`（最多 60 行）。

```md
<SourceRef file="projects/lumen-kanban/src/renderer/db/db.ts" symbol="export class KanbanDB" />
```

## 超出白名单时会怎样

出于安全考虑，`<SourceRef>` 只能读取 `track.json` 里 `codeRoots` 声明的目录。
下面的例子故意指向白名单外的文件：

```md
<SourceRef file="projects/lumen-kanban/package.json" caption="故意越权" />
```

<SourceRef file="projects/lumen-kanban/package.json" caption="故意越权" />

构建不会中断，页面上会给出明确的黄色提示——这是设计上的取舍：
**单个引用失效不应该拖垮整站构建**，但它必须足够显眼，逼你去修。

## 提示块

`<Callout>` 用来打断阅读节奏，标注「坑」「注意」「验收点」这类信息。
`kind` 支持 `info` / `warn` / `success` / `danger`：

<Callout kind="warn" title="坑">
`<Callout>` 的正文支持 Markdown，标签写法有两种，都行：

- **多行**：开始标签单独占一行，正文随便写多少段，最后用 `</Callout>` 收尾；
- **单行**：`<Callout kind="info" title="…">一句话正文</Callout>` 全挤在一行，适合短提示。

两种写法都要求**开始标签位于行首**（前面只允许有空白）。写在段落中间不会被识别，
构建脚本会把它当普通文本，"原样"输出成 `<Callout kind="…">` 这样的字面量。
</Callout>

<Callout kind="success" title="验收点">
新增一篇文档后，跑一次 `pnpm check`：如果 `track.json` 里没登记它，或者登记了文件却不存在，都会直接报错。
</Callout>

## 多语言语法对照

讲语法点时经常要把"同一件事在别的语言里怎么写"摆在一起。逐个语言顺序贴五段代码，
页面会被撑得很长，读者还得来回滚动才能对上行。

`<LangTabs>` 把多份实现收进一个**可切换标签的代码块**：一次只显示一种语言，
点标签切换，右上角复制的是当前这一种语言的代码。

用法是把若干代码围栏放进 `<LangTabs>` 里，语言由围栏的 info 决定
（`java` / `ts` / `rust` / `go` / `python` 会自动显示成 Java / TypeScript / Rust / Go / Python）：

````md
<LangTabs title="变量声明：五种语言对照">
```java
var count = 10;
```
```ts
const count = 10;
```
```rust
let count = 10;
```
```go
count := 10
```
```python
count = 10
```
</LangTabs>
````

渲染结果：

<LangTabs title="变量声明：五种语言对照">
```java
var count = 10;              // 局部变量类型推断（仍是静态类型，编译期定死）
final var name = "lumen";    // final 绑定不可重新赋值，作用接近 JS 的 const

// 类型必须能在编译期确定，写成 count = "x" 直接编译失败
```
```ts
const count = 10;            // 绑定不可重新赋值（对象内容仍可变）
let name = 'lumen';          // let 才能重新赋值

// 类型同样是编译期的，但只在编译时检查，运行期不存在
```
```rust
let count = 10;              // 默认不可变
let mut name = "lumen";      // 加 mut 才允许重新赋值

// 与 Java 最大差异：可变性是绑定的默认属性，要显式"申请"可变
```
```go
count := 10                  // := 声明并推断类型
var name string = "lumen"    // 显式类型写法

// 变量默认有零值（int 为 0、string 为 ""），不存在"未初始化"状态
```
```python
count = 10                   # 没有声明关键字，赋值即声明
name: str = "lumen"          # 类型标注只给工具看，运行时不做强制

# 变量是名字到对象的绑定，可以随时指向另一种类型
```
</LangTabs>

几条约定：

- **标签顺序 = 代码围栏出现顺序**。建议固定按 Java → TypeScript → Rust → Go → Python 排，
  读者会形成"第一个就是 Java"的预期。
- 每个面板**独立复制**，不会把五种语言一起复制走。
- 键鼠都可用：`Tab` 进入标签组后用左右方向键切换，`Home` / `End` 跳首尾。
- 组件本身没有的字段一律省略，不要为了凑数写 `// 无对应概念`；
  某门语言确实没有对应写法时，改用 `<Callout kind="info">` 在下方说明。

<Callout kind="warn" title="坑：标签顺序与代码顺序不一致">
标签是按代码围栏顺序生成的，不是按语言名排序。手写时如果把 Python 的围栏放到了 Java 前面，
标签栏的顺序就会跟着变，读者对照时容易串行。
</Callout>
