## 四、你在这个项目里做出的关键决策（面试/复盘可讲）

| 决策 | 备选 | 选了什么 | 理由 |
| --- | --- | --- | --- |
| 存储 | localStorage / SQLite / Dexie | Dexie | 容量 + 索引 + 异步；无需原生模块 |
| 刷新机制 | 手写 refresh / liveQuery | liveQuery | 消灭"改完记得刷新"这一类 bug |
| 状态归属 | 全进 store / 分层 | 分层 | 业务数据在库，UI 状态在 store，避免双份真相 |
| 拖拽 | HTML5 DnD / dnd-kit | HTML5 DnD | 零依赖 20 行；需触屏/无障碍时再换 |
| lint | typescript-eslint / oxlint | oxlint | TS 7 无稳定编译器 API，前者不兼容 |
| Electron 构建 | electron-vite / 手写 | 手写 | electron-vite 不支持 Vite 8 |
| IPC 返回 | 异常 / Result | Result | 异常跨进程丢类型；Result 可被穷尽检查 |
| 主题 | Tailwind 默认 dark / 自定义变体 | 自定义变体 | 需要"系统/亮/暗"三态 |
| 动效载体 | motion.li 直接挂拖放 / 内部分层 | 内部分层 | Motion 自带手势回调与原生拖放签名冲突 |

## 五、下一步可以往哪走

按"投入产出比"排序：

1. **撤销/重做**（命令模式）—— 看板类应用的高频需求，练的是状态设计与测试
2. **虚拟滚动**（列内卡片上千时）—— 练性能与 `layout` 动画的取舍
3. **多看板 + 路由** —— 引入 React Router，把选中项放进 URL
4. **接真实后端 + TanStack Query** —— 完整体验"服务端缓存 vs 本地真源"的分层
5. **同步与冲突解决** —— outbox 队列 + `updatedAt` 比较 + 冲突 UI
6. **自动更新** —— `electron-updater` + 更新服务器
7. **E2E + CI** —— Playwright + GitHub Actions 三平台矩阵
