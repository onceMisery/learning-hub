# 02 · 阶段 1：布局与主题令牌

## 学完你能做什么

- 不用查文档就写出常见的一维（Flex）与二维（Grid）布局
- 用**容器查询**做出"组件自己会变形"的响应式，而不是只会媒体查询
- 搭一套**设计令牌**，实现"系统 / 亮 / 暗"三态主题，且组件里不出现任何硬编码颜色
- 把这套体系迁移到 Tailwind 4 的 CSS-first 配置上

**前置**：阶段 0（项目能跑起来）。

---

## 1. 最小可运行示例：把地基跑起来看

配套文件：`examples/layout-demo.html`

```bash
# 直接用浏览器打开（不需要任何服务器）
start examples/layout-demo.html        # Windows
open examples/layout-demo.html         # macOS
```

**预期看到**：

1. 三张卡片横向排开，窗口拖窄后自动换行 —— Flex 的 `flex: 1 1 220px`
2. 侧栏 200px + 主区自适应；窗口 < 640px 时整体塌成单列 —— Grid + 媒体查询
3. 两个"组件"：上面的窄（320px）内容紧挨，下面的宽（≥480px）变成两端对齐 —— **容器查询**
4. 切换系统深色模式，全站配色自动切换 —— CSS 变量 + `prefers-color-scheme`

**验证方式**：在 DevTools 里把 `.narrow` 的宽度从 320px 改成 600px，组件**立刻**变成两端对齐 —— 这就是容器查询：它看的是父容器宽度，不是视口宽度。这是组件化开发的基石，因为同一个组件放在侧栏和主区里应该表现不同。

**为什么令牌要分两层**：`--color-bg`（语义）引用 `--color-*` 原始色板（primitive）。组件永远只用语义层，哪天要换品牌色，只改 `@theme` 里一行。

## 2. 接入 Tailwind 4

```bash
npm i -D tailwindcss@4.3.3 @tailwindcss/vite@4.3.3
```

`vite.config.ts` 里加一行插件：

```ts
import tailwindcss from '@tailwindcss/vite';
export default defineConfig({ plugins: [react(), tailwindcss()] });
```

`src/renderer/styles/index.css` 只需要一行：

```css
@import 'tailwindcss';
```

在入口引入：`src/renderer/main.tsx` 里 `import './styles/index.css';`

**验证**：

```bash
npm run build
```

```
dist/renderer/assets/index-*.css   15.64 kB │ gzip: 4.11 kB
```

15KB 就是"扫到才生成"的结果 —— 没用到的类不会进产物。

> ⚠️ **v3 教程在这里全是错的**：v4 没有 `@tailwind base/components/utilities` 三件套，也没有默认生效的 `tailwind.config.js`。看到教程让你 `npx tailwindcss init`，那是 v3。

## 3. 令牌体系与三态主题（本项目真实代码）

`src/renderer/styles/index.css`：

```css
@import 'tailwindcss';

/* 1) 令牌：写在 @theme 里，Tailwind 自动生成 bg-surface / text-fg / border-line 等工具类 */
@theme {
  --color-brand: oklch(0.62 0.19 255);
  --color-brand-soft: oklch(0.95 0.03 255);
  --color-surface: oklch(0.99 0 0);
  --color-surface-raised: #ffffff;
  --color-surface-sunken: oklch(0.97 0.003 265);
  --color-fg: oklch(0.21 0.02 265);
  --color-fg-muted: oklch(0.52 0.02 265);
  --color-line: oklch(0.9 0.005 265);
  --color-line-strong: oklch(0.8 0.008 265);
  --radius-card: 0.75rem;
}

/* 2) 深色：只覆盖语义令牌的值，工具类不需要改 */
[data-theme='dark'] {
  --color-surface: oklch(0.18 0.015 265);
  --color-surface-raised: oklch(0.23 0.015 265);
  --color-fg: oklch(0.95 0.005 265);
  /* … */
}

/* 3) 把 dark: 变体从"跟随系统"改成"跟随 data-theme 属性" */
@custom-variant dark (&:where([data-theme='dark'], [data-theme='dark'] *));
```

配套 Hook（`src/renderer/hooks/useTheme.ts`）把 store 里的 `theme` 落到 `<html data-theme>`：

```ts
const resolve = (mode: ThemeMode): 'light' | 'dark' => {
  if (mode !== 'system') return mode;
  return window.matchMedia('(prefers-color-scheme: dark)').matches ? 'dark' : 'light';
};
// …effect 里 document.documentElement.dataset.theme = resolve(theme)
```

**为什么第 3 步是必须的**：Tailwind v4 的 `dark:` 默认匹配 `prefers-color-scheme`，只能跟随系统。我们要"系统/亮/暗"三态（应用内可强制切换），就必须用 `@custom-variant` 改写成匹配 `[data-theme='dark']`。

**为什么用 oklch 而不是 hex**：oklch 是感知均匀的色彩空间，同一亮度值下不同色相看起来亮度一致，做主题色阶时不会忽明忽暗。老浏览器会自动降级（Tailwind v4 内置 fallback）。

**验证方式**：

1. `npm run dev`，点工具栏的"暗" → 整站变深
2. DevTools 里看 `<html data-theme="dark">` 属性是否跟着变
3. 切回"系统" → 跟随系统设置

## 4. 什么时候用 Tailwind，什么时候写 CSS

| 场景 | 选择 | 原因 |
| --- | --- | --- |
| 布局、间距、颜色、状态变体 | Tailwind 类名 | 可组合、可扫掉、无需命名 |
| 设计令牌、主题变量 | `@theme` | 需要被 JS 读取 / 运行时切换 |
| 复杂的 keyframes、滚动条、第三方覆盖 | 原生 CSS | 类名表达不了 |
| 重复 10 次以上的一长串类名 | 抽成 React 组件 | 组件化复用优于 `@apply` |

**`@apply` 的适用边界**：只在"无法控制对方 HTML"时用（比如覆盖第三方库的类）。滥用 `@apply` 等于用 Tailwind 写普通 CSS，丢掉了可组合性，产物也不会更小。

## 5. 动态类名的坑（必看）

```tsx
// ❌ 生成不出来：Tailwind 是静态扫描源码的，它看不到拼接结果
<div className={`text-${color}-500`} />

// ✅ 完整类名出现在源码里
const colorMap = { red: 'text-red-500', blue: 'text-blue-500' } as const;
<div className={colorMap[color]} />
```

如果类名来自后端/CMS（源码里根本搜不到），用：

```css
@source inline("text-(red|blue|green)-500");
```

## 6. 本阶段踩坑速查

| 症状 | 原因 | 修复 |
| --- | --- | --- |
| Tailwind 类完全不生效 | 忘了 `@import 'tailwindcss'` 或没引入 CSS 文件 | 检查入口是否 `import './styles/index.css'` |
| `dark:` 不生效 | 默认跟随系统，而系统没开深色 | 加 `@custom-variant` 改成 data 属性匹配 |
| 某个动态类名没生成 | 源码里没有完整字面量 | 用映射表或 `@source inline()` |
| 子组件传 `className` 覆盖不掉默认样式 | Tailwind 冲突类"后写不一定赢" | 用 `tailwind-merge`（本项目 `lib/cn.ts`） |
| Flex 子项文字不换行撑破布局 | flex 项默认 `min-width: auto` | 加 `min-width: 0` |
