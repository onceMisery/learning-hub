# 01 · 阶段 0：环境与工程地基

## 学完你能做什么

- 从**空目录**手写出一个 Vite 8 + React 19 + TypeScript 7 项目（不用脚手架，因为脚手架会替你做决定，而你要知道每个决定是什么）
- 跑通 `dev / typecheck / lint / test / build` 五条命令，并知道每条命令到底检查了什么
- 理解 TypeScript 7 与旧版的三处关键差异，以及"为什么我这报错网上没有"

**前置条件**：会写 JS，装过 Node。不需要任何前端框架经验。

---

## 1. 环境检查

```bash
node -v
npm -v
```

预期：`v22.22.2` / `11.2.0`（或更高）。

> **为什么必须 ≥ 22.12**：Vite 8 以纯 ESM 发布，要求 Node 支持无标记的 `require(esm)`，最低就是 20.19 / 22.12。低于这个版本会在启动时直接报 `SyntaxError: Cannot use import statement outside a module`。

版本不够怎么办：用 `nvm` / `fnm` / `volta` 装一个 22 LTS，不要去改系统 Node。

## 2. 最小可运行示例：先跑一个"Hello Vite"

### 步骤

```bash
mkdir hello-vite && cd hello-vite
npm init -y
npm i -D vite@8.3.0
```

新建 `index.html`：

```html
<!doctype html>
<html lang="zh-CN">
  <head>
    <meta charset="UTF-8" />
    <title>Hello Vite</title>
  </head>
  <body>
    <div id="app">加载中…</div>
    <script type="module" src="/main.js"></script>
  </body>
</html>
```

新建 `main.js`：

```js
document.getElementById('app').textContent = 'Vite 起来了：' + new Date().toLocaleTimeString();
```

跑：

```bash
npx vite
```

**预期输出**：

```
VITE v8.3.0  ready in 320 ms
➜  Local:   http://localhost:5173/
```

**验证方式**：浏览器打开 `http://localhost:5173/`，页面显示"Vite 起来了：…"。改一下 `main.js` 保存，页面**不刷新**就更新了（HMR）。

**为什么先做这个**：Vite 开发态**不打包**，浏览器直接吃原生 ESM，所以冷启动是毫秒级。这与 Java 的"编译→打包→部署"完全不同，先把这个体感建立起来。

## 3. 正式项目：逐个文件手写

回到 `lumen-kanban/`，下面是本项目真实使用的配置，每个都解释了"为什么这么写"。

### 3.1 `package.json`

```json
{
  "name": "lumen-kanban",
  "type": "module",
  "main": "dist/main.cjs",
  "engines": { "node": ">=22.12.0" },
  "scripts": {
    "dev": "vite",
    "typecheck": "tsc --noEmit",
    "lint": "oxlint src --max-warnings=0",
    "test": "vitest run",
    "build": "tsc --noEmit && vite build",
    "build:main": "vite build --config vite.main.config.ts",
    "start": "npm run build:main && electron ."
  }
}
```

要点：

- `"type": "module"` —— 配置文件用 ESM 写；但 Electron 主进程产物是 CJS（见 3.4），两者不冲突，因为产物后缀是 `.cjs`
- `"main": "dist/main.cjs"` —— Electron 的入口，必须指向构建产物，**不能**指向 `src/main/index.ts`
- `build` 脚本先跑 `tsc --noEmit` 再打包 —— **类型检查和打包是两件事**。Vite 只负责转译（去掉类型），不做类型检查；CI 里两条都要跑，否则类型错误会溜进产物

### 3.2 `tsconfig.json`

```json
{
  "compilerOptions": {
    "target": "ESNext",
    "lib": ["ESNext", "DOM", "DOM.Iterable"],
    "module": "ESNext",
    "moduleResolution": "bundler",
    "jsx": "react-jsx",

    "strict": true,
    "noUncheckedIndexedAccess": true,
    "exactOptionalPropertyTypes": true,
    "noUnusedLocals": true,
    "noUnusedParameters": true,

    "verbatimModuleSyntax": true,
    "isolatedModules": true,
    "skipLibCheck": true,
    "noEmit": true,

    "types": ["node", "vitest/globals", "vite/client"],
    "paths": {
      "@/*": ["./src/renderer/*"],
      "@shared/*": ["./src/shared/*"]
    }
  },
  "include": ["src", "tests", "vite.config.ts", "vite.main.config.ts"]
}
```

逐条解释"为什么"：

| 选项 | 为什么 |
| --- | --- |
| `strict: true` | **TS 7 已经是默认值**，写上是为了让意图显式。它包含 `strictNullChecks`，能消灭"undefined 不是函数"这一整类线上事故 |
| `noUncheckedIndexedAccess` | 让 `arr[0]` 的类型变成 `T \| undefined`。看代码里到处出现的 `columns[0]?.id` 和 `result.filePaths[0] === undefined` 都是它的功劳 —— 这是本项目最有价值的一条配置 |
| `exactOptionalPropertyTypes` | 区分"没有这个属性"与"这个属性是 undefined"，避免 `{ a: undefined }` 意外覆盖默认值 |
| `verbatimModuleSyntax` | 强制 `import type` 写清楚，避免类型导入被保留到运行时（打包体积 + 循环依赖） |
| `noEmit` | 产物由 Vite 产出，`tsc` 只当类型检查器用 |
| `types` 里的 `vite/client` | 提供 `*.css` 等资源的类型声明，否则 `import './index.css'` 会报 TS2882 |
| `paths` 里必须写 `./` 开头 | **TS 7 移除了 `baseUrl`**，路径必须相对。写 `src/renderer/*` 会报 TS5090 |

### 3.3 `vite.config.ts`

```ts
import { fileURLToPath, URL } from 'node:url';
import react from '@vitejs/plugin-react';
import tailwindcss from '@tailwindcss/vite';
import { defineConfig } from 'vitest/config';

export default defineConfig({
  plugins: [react(), tailwindcss()],
  base: './',
  resolve: {
    alias: {
      '@': fileURLToPath(new URL('./src/renderer', import.meta.url)),
      '@shared': fileURLToPath(new URL('./src/shared', import.meta.url)),
    },
  },
  build: { outDir: 'dist/renderer', emptyOutDir: true, target: 'esnext', sourcemap: true },
  test: {
    environment: 'jsdom',
    globals: true,
    setupFiles: ['./tests/setup.ts'],
    include: ['tests/**/*.test.{ts,tsx}'],
    pool: 'threads',
  },
});
```

三个关键决定：

1. **`base: './'`** —— Electron 用 `file://` 加载产物，绝对路径 `dist/renderer/index.html`，必须设成 `false` 或 `'./'`。
2. **`defineConfig` 从 `vitest/config` 导入** —— 这样才能写 `test` 字段。从 `vite` 导入会报"对象字面量只能指定已知属性"。
3. **`pool: 'threads'`** —— Vitest 5 默认 `forks` 池，在受限环境（沙箱/CI 容器）里会出现 `Timeout waiting for worker to respond`。改成 threads 后稳定。

### 3.4 `vite.main.config.ts`（主进程 / 预加载）

```ts
import { builtinModules } from 'node:module';
import { defineConfig } from 'vite';

export default defineConfig({
  build: {
    outDir: 'dist',
    emptyOutDir: false,
    target: 'node24',
    lib: {
      name: 'lumen',
      entry: { main: 'src/main/index.ts', preload: 'src/preload/index.ts' },
      formats: ['cjs'] as const,
      fileName: (_format, name) => `${name}.cjs`,
    },
    rollupOptions: {
      external: ['electron', ...builtinModules, ...builtinModules.map((m) => `node:${m}`)],
    },
    minify: false,
  },
});
```

- **为什么输出 CJS 而不是 ESM**：Electron 43 对 ESM 的支持仍有边界（预加载脚本、部分原生模块），CJS 是当下最稳的选择，且 `require('electron')` 天然可用
- **为什么 `emptyOutDir: false`**：它会和渲染进程构建产物一起放在 `dist/` 下，清空会删掉刚构建的 `dist/renderer`
- **为什么要 external**：`electron` 和 `fs/path` 是运行时提供的，打进产物会导致找不到模块或体积爆炸

> **为什么不直接用 electron-vite**：`electron-vite@5` 的 peer 是 `vite ^5||^6||^7`，不支持 Vite 8。手写这 20 行反而更清楚。

## 5. lint 为什么是 oxlint 而不是 ESLint

```bash
npm i -D typescript-eslint@8.70.0
# npm error code ERESOLVE
# peer typescript@">=4.8.4 <6.1.0" from typescript-eslint@8.70.0
# Found: typescript@7.0.2
```

TypeScript 7 用 Go 重写了编译器，**7.0 尚未提供稳定的编程式 API**，因此所有依赖编译器 API 的工具（`typescript-eslint`、`ts-jest`、`ts-morph`、Vue/Svelte 的模板类型检查）都要等 7.1。

**推荐方案**：

| 需求 | 方案 |
| --- | --- |
| 类型正确性 | `tsc --noEmit`（TS 7 原生，快 8~12 倍） |
| 代码规范/可疑写法 | `oxlint`（Rust 实现，不依赖 TS API） |
| 强依赖 typescript-eslint 的类型规则 | 安装 `@typescript/typescript6` 兼容包，用 npm alias 并存：`npm i -D typescript@npm:@typescript/typescript6` |

```bash
npm run lint
# 预期：Found 0 warnings and 0 errors.
```

## 6. 本阶段踩坑速查

| 症状 | 原因 | 修复 |
| --- | --- | --- |
| `error TS5102: Option 'baseUrl' has been removed` | TS 7 移除了 baseUrl | 删掉 `baseUrl`，`paths` 的值改成 `./` 开头 |
| `error TS5090: Non-relative paths are not allowed` | 同上 | 同上 |
| `TS2882: Cannot find module ... for side-effect import of './index.css'` | 缺资源类型声明 | `types` 里加 `vite/client` |
| `npm error ETARGET ... electron@43.7.1` | 版本号不存在 | 用 `npm view <pkg> version` 或 `npm view electron@43 version` 查真实版本再锁 |
| Vitest `Timeout waiting for worker to respond` | forks 池起不来 | 配置 `pool: 'threads'` |
| Vite 启动报 ESM 相关语法错误 | Node 版本过低 | 升到 22.12+ |

完整列表见 [09 · 排错手册](./09-排错手册.md)。
