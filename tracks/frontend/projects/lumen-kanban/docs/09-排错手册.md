# 09 · 排错手册

> 本手册里的每一条错误，都是搭建 `lumen-kanban` 时**真实遇到并解决**的。按症状查即可。

---

## 0. 排查方法论（先按这个顺序走）

1. **读完报错全文** —— 80% 的问题报错信息已经写清楚了原因和文件行号
2. **判断属于哪一层** —— 类型层（`tsc`）/ 构建层（Vite）/ 运行时（浏览器控制台）/ 进程层（Electron stderr）
3. **最小化复现** —— 把问题抽到 20 行代码，抽的过程中通常就找到了原因
4. **查官方 changelog** —— 前端生态版本迭代极快，二手教程经常过期（本手册里有 3 条就是版本变更导致的）
5. **设 30 分钟上限** —— 超时就记进待办继续往前走，很多问题会在后续阶段自然解开

## 1. TypeScript 7 相关（版本变更导致，网上教程几乎没有）

### 1.1 `error TS5102: Option 'baseUrl' has been removed`

```
tsconfig.json(26,5): error TS5102: Option 'baseUrl' has been removed. Please remove it from your configuration.
```

- **原因**：TypeScript 7 移除了 `baseUrl`
- **修复**：删掉 `baseUrl`，把 `paths` 的值改成 `./` 开头

```jsonc
// ❌
{ "baseUrl": ".", "paths": { "@/*": ["src/renderer/*"] } }
// ✅
{ "paths": { "@/*": ["./src/renderer/*"] } }
```

### 1.2 `error TS5090: Non-relative paths are not allowed`

- **原因**：同上，路径别名必须以 `./` 开头
- **修复**：同上

### 1.3 `error TS2882: Cannot find module ... for side-effect import of './styles/index.css'`

- **原因**：缺资源类型声明
- **修复**：`tsconfig.json` 的 `types` 里加 `vite/client`

### 1.4 `error TS5112: tsconfig.json is present but will not be loaded if files are specified on commandline`

- **原因**：TS 7 新行为 —— 命令行指定了具体文件时，不会加载 `tsconfig.json`
- **修复**：加 `--ignoreConfig`

```bash
npx tsc examples/type-demo.ts --ignoreConfig --outDir .tmp-examples --strict
```

### 1.5 `'xxx' is possibly 'undefined'` 满天飞

- **原因**：`strict` + `noUncheckedIndexedAccess` 生效（这是**正确行为**，不是误报）
- **修复**：用 `?.` / `??` / 先行判空处理；**不要**用 `as` 断言绕过
- **为什么值得**：本项目里 `columns[0]?.id`、`result.filePaths[0] === undefined`、`parsed.error.issues[0]?.message` 都是它逼出来的，每一个都对应一个真实的越界风险

## 2. 依赖安装相关

### 2.1 `npm error ETARGET: No matching version found for electron@43.7.1`

- **原因**：版本号不存在（我按错误记忆写了个不存在的补丁号）
- **修复**：先查真实版本再锁

```bash
npm view electron version          # 最新：44.3.0
npm view electron@43 version       # 43 线最新：43.7.0
```

- **预防**：`package.json` 里的版本号不要凭印象写，一律 `npm view` 确认

### 2.2 `ERESOLVE: peer typescript@">=4.8.4 <6.1.0" from typescript-eslint`

- **原因**：TypeScript 7 用 Go 重写了编译器，**7.0 未提供稳定的编程式 API**，`typescript-eslint` 目前只支持到 TS 6.0.x
- **修复**（三选一）：
  1. lint 换 `oxlint`（本项目采用，不依赖 TS API）
  2. 用 npm alias 并存 TS 6：`npm i -D typescript@npm:@typescript/typescript6`
  3. 等 TypeScript 7.1（提供稳定 API）

### 2.3 `electron-vite` 报 peer 冲突

- **原因**：`electron-vite@5` 的 peer 是 `vite ^5 || ^6 || ^7`，不支持 Vite 8
- **修复**：不用它，改用 Vite 8 的 lib 模式多入口（见 `vite.main.config.ts`）

## 3. 测试相关

### 3.1 `[vitest-pool]: Timeout waiting for worker to respond`

```
Error: [vitest-pool]: Failed to start forks worker for test files
Caused by: Error: [vitest-pool-runner]: Timeout waiting for worker to respond
Duration 60.07s
```

- **原因**：Vitest 5 默认用 `forks` 池，在沙箱/受限环境里 worker 进程起不来
- **修复**：配置 `pool: 'threads'`

```ts
test: { pool: 'threads', /* … */ }
```

- **验证**：改完从 60s 超时变成 `Tests 9 passed (9) / Duration 11.72s`

### 3.2 `indexedDB is not defined`

- **原因**：jsdom 不提供 IndexedDB
- **修复**：`tests/setup.ts` 加 `import 'fake-indexeddb/auto'`

## 4. 运行时（浏览器控制台）

| 症状 | 原因 | 修复 |
| --- | --- | --- |
| 页面白屏，控制台无报错 | `#root` 没渲染 / CSS 未加载 | 检查 `main.tsx` 是否 `import './styles/index.css'`；检查 `index.html` 是否有 `<div id="root">` |
| Tailwind 类全不生效 | 没 `@import 'tailwindcss'` | 在样式入口加上 |
| 新增卡片后列表不更新 | 忘了 `useLiveQuery` 的依赖数组，或依赖了每次都变的值 | 依赖写 `[boardId]` 这类稳定值 |
| 输入框被反复抢焦点 | `useEffect` 依赖了 `useLiveQuery` 返回的新数组 | 依赖改成 `columns[0]?.id` 这类原始值 |
| 拖拽没反应 | 没在 `onDragOver` 里 `preventDefault()` | 加上；浏览器默认不允许 drop |
| 拖到卡片上却插入到了末尾 | 事件冒泡，卡的 `onDrop` 和列的 `onDrop` 都触发了 | 在卡片的处理器里 `stopPropagation()` |
| 刷新后主题/数据没了 | 没持久化 | 主题走 Zustand `persist`，数据走 Dexie |
| 搜索结果和显示不一致 | 两处过滤规则不同 | 抽成同一个纯函数（本项目 `lib/search.ts`） |

## 5. Electron 相关

| 症状 | 原因 | 修复 |
| --- | --- | --- |
| 窗口全白 | 资源用绝对路径，`file://` 下找不到 | `vite.config.ts` 设 `base: './'` |
| `Cannot find module dist/main.cjs` | 没构建主进程 | 先 `npm run build:main` |
| `require is not defined in ES module scope` | 主进程产物是 ESM | `formats: ['cjs']` 输出 CJS |
| `window.api` 是 undefined | preload 路径错 / 未开 contextIsolation | 检查 `preload` 路径与 `process.contextIsolated` 分支 |
| **`require('electron')` 返回的是路径字符串，`app` 是 undefined** | 环境里设置了 `ELECTRON_RUN_AS_NODE=1`（某些终端/CI 会注入），electron 被当成纯 Node 运行 | 启动前清除该变量：`Remove-Item Env:ELECTRON_RUN_AS_NODE`（PowerShell）/ `unset ELECTRON_RUN_AS_NODE`（bash）。可用 `typeof require('electron')` 是 `'object'` 还是 `'string'` 快速确认 |
| **`GPU process isn't usable. Goodbye.`（进程直接退出）** | 无显卡/无显示的环境（CI、远程桌面、部分沙箱）里 GPU 进程启动失败 | 在 app ready 前加：`app.disableHardwareAcceleration()` + `app.commandLine.appendSwitch('no-sandbox')` + `appendSwitch('disable-gpu')`。有正常桌面的机器不需要 |
| `ERR_FAILED (-2) loading file:///...index.html` | 多为上一步 GPU 崩溃连带渲染进程被杀 | 同上，先解决 GPU 问题再看重载是否正常 |
| **`capturePage()` 截到的是旧画面（隐藏窗口时）** | 隐藏窗口不持续合成帧，截图拿到的是上一帧 | 让窗口 `show()` 后再截；或截图前等待足够久。**注意这也会误导自动化断言**：DOM 里已经有卡片、截图却还是"加载中" |
| 用 JS 给受控输入赋值不生效（`value` 变了但组件没响应） | React 通过 value tracker 判断值是否变化，直接改 DOM value 会"骗过"它 | 用真实键盘事件（Playwright `keyboard.type` / Electron `sendInputEvent`）；纯 DOM 注入可用原生 setter + `dispatchEvent(new Event('input', {bubbles:true}))`，但对部分受控组件不可靠 |
| 点击 `<label>` 内的复选框状态变了两次 | 合成 `click()` 冒泡到 label 后又转发给 input，切换了两次 | 自动化里点击后读回 `checked` 确认；必要时直接点 label 或用真实鼠标事件 |
| **统计列表数量比预期多** | `AnimatePresence` 退场动画期间元素还在 DOM 里（约 1 秒） | 计数时按 `getComputedStyle(li).opacity > 0.5` 过滤，或等待动画结束 |
| `app.getVersion()` 返回的是 Electron 版本而不是应用版本 | 用 `electron 某脚本.cjs` 方式运行时没有"应用"，取到的是 electron 包的版本 | 用 `electron .`（package.json 的 main）运行；脚本方式可自行 `ipcMain.handle` 返回期望值 |
| IPC 调用无任何反应 | 通道名拼错（主进程与 preload 不一致） | 用 `shared/ipc.ts` 的 `IpcChannel` 常量，别写字面量 |
| IPC 返回报错"数据格式不合法" | zod schema 与传入结构不匹配 | 对照 `snapshotSchema` 检查字段；注意 `done` 必须是 0/1 |
| 窗口一闪而过/白屏闪 | 渲染未完成就 `show()` | `window.once('ready-to-show', () => window.show())` |
| 更新后数据丢失 | 数据写在安装目录 | 用 `app.getPath('userData')` |
| 打包后体积异常大 | 依赖被打进产物 | `rollupOptions.external` 排除 electron 与 Node 内置模块 |
| 启动时报 `ValidateIntegrityOrDie` 崩溃 | 运行中 app.asar 被替换（更新器/MDM） | 升级到 43.1.1+（已修复） |
| 重装依赖后报 `Electron failed to install correctly` | `npm i --no-save 其他包` 会重写依赖树，把 electron 的二进制（`node_modules/electron/dist`）清掉 | 重跑 `node node_modules/electron/install.js`；GitHub 下载失败时设镜像 `$env:ELECTRON_MIRROR="https://npmmirror.com/mirrors/electron/"` |

> **自动化验证脚本**：`npm run capture` 会启动应用并走完上述所有验证点（含截图到 `screenshots/`）。调试时可参考 `scripts/debug-filter.cjs` 的写法——用 `executeJavaScript` 读 DOM 状态、用 `sendInputEvent` 模拟真实键盘。

## 6. Dexie 相关

| 症状 | 原因 | 修复 |
| --- | --- | --- |
| `TransactionInactiveError` | 事务里 `await` 了非 Dexie 的 Promise | 事务内只做 Dexie 操作 |
| 加了字段但查询不到 | 没建索引却用 `where()` | 建索引 + 升版本 |
| 老用户升级后字段 `undefined` | 缺 `upgrade()` | 在 `.upgrade()` 里回填默认值 |
| `done: true` 存进去查不到 | 不能索引 boolean | 用 0/1 |
| 批量写入很慢 | 循环 `put` | 改 `bulkPut` |
| 隐私模式/配额不足时报错 | 浏览器限制 | 捕获 `db.open()` 失败与 `QuotaExceededError` 并给用户提示 |
