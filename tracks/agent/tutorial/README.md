# Agent 系统学习目录

> 问题来源：极客时间专栏《AI Agent 系统设计面试现场》面试脑图（85 道问题、550 个知识节点）——每个阶段用它定义「学什么、验什么」。
> 教材主线：《Agent 设计之美》（28+ 设计模式，按七认知功能 × 执行拓扑的双轴框架组织）——正面讲「该怎么设计」。
> 教材反面：《Agent 生产排雷实战》（20 讲，全是线上真实事故）——反面的工程护栏。
> 体系参照：《深入理解 AI Agent》（10 章 + 109 个开源实验）——补齐本目录原本没有的三层：工具与代码的动作空间、触发时机与模态扩展、模型层边界。凡引用其数字，一律注明是书中实测、论文报告还是未复现的预期。
> 起点假设：有后端工程经验，用过至少一个大模型 API，想系统补齐 Agent 工程能力。

---

## 一、这份目录怎么用

1. **按阶段顺序推进**，每个阶段是一篇独立文档，内部按小节展开，可单独阅读、单独验收。
2. 每个小节配三条线索：**设计模式**（《设计之美》对应讲，学正面方案）→ **生产雷区**（《排雷实战》对应讲，看方案失守的样子）→ **面试追问**（脑图里的真实追问链，用来自测）。
3. 全局组织按《设计之美》的双轴框架：**认知功能轴**（感知 / 记忆 / 推理 / 行动 / 反思 / 协作 / 治理）对应阶段 01~06，**执行拓扑轴**（路由 / 循环 / 层级）的追问散布在各阶段。评审一个 Agent 时先定位「功能 × 拓扑」坐标，再谈问题——「不够稳」要能说到「推理 × 循环没有停止条件」这个粒度。阶段 07 是这套坐标的元层用法；08 把「行动」轴拆成供给侧（接口 / 形态 / 代码），09 把「感知 + 行动」轴扩展到时间与模态——谁在什么时候叫它，以及用什么看、用什么说。
4. 每个阶段结束要能回答该阶段的**阶段终检**（最后一层追问），能讲清「为什么这样做、代价是什么、怎么验证」才算过。
5. **每篇文章的尾部固定四件**：踩坑清单 → 扩展阅读（对照 Codex 源码的实现，配示意图）→ 总结 → 思考题。先自己答思考题，再看总结。扩展阅读有三条硬规矩：**按「一次请求怎么走完」讲调用链**，不按源码文件顺序罗列；文件路径只在关键处出现一次，完整入口收进该节最后一小节；行号与枚举变体要打开仓库核过再写，二手资料的说法一律不采信。
6. **九篇正文均已成型**（01 意图识别 / 02 执行核心 / 03 上下文管理 / 04 检索与 RAG / 05 评估与反馈 / 06 协作与治理 / 07 项目深挖与工程表达 / 08 动作空间 / 09 触发时机与交互），01~07 各配一张或多张 Codex 图解，08 与 09 的扩展阅读改为对照《深入理解 AI Agent》的实验台账（实测 / 论文报告 / 未复现预期三种口径分开标）。本文件是仓库内的目录与验收清单，不作为站点页面发布。

## 四、与实战的关系

每个阶段配套一个可运行的小系统作为产出物：01 意图分诊器、02 带预算控制与护栏的 TAO Runtime、03 上下文编排器、04 最小充分检索链、05 离线评估 + Judge + 监控成本面板、06 双 Agent 协作 + 审批门 demo，07 把前六阶段的产出串成一份能讲的项目，08 给这套系统补上动作空间的供给侧——一组带描述与权限声明的工具、一个可编辑文件的沙盒入口、一条有熔断上限的恢复路径；09 再把它接到真实世界的时间上：一个能消费事件的循环（带安全点与三策略）、一路可打断的输入通道。判定标准和面试追问一致：**能报出指标、能定位错例、能讲清代价**。
